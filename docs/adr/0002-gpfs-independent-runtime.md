# 运行时与 GPFS、EE 解耦

2026-11-06，用户明确本项目必须与 GPFS 解耦。本决定适用于整个历史 WIP 的集成及后续实现，不改变 Library → Pool → Tape 管理模型。

## 决定

`tape-rs` 的生产运行时不依赖 IBM Storage Scale/GPFS、EE 服务、GPFS 挂载、DMAPI 或 HSM stub。FDB 保存权威目录、介质归属、原任务及通知；本地磁盘承载可恢复的请求正文、索引暂存和缓存；设备访问经本项目的 SCSI/LTFS 层执行。

`tape assign`、首次 `tape import`、已分配卷再次导入刷新、状态监控、S3 和 FUSE 必须在该依赖集合内完成。`-P` 是池内逻辑目录，不是 GPFS 或宿主机文件系统的挂载路径。解除磁带归属时验证 FDB 中的活动对象、副本、占用及在途任务，不调用 `mmapplypolicy`、EE reconcile、GPFS policy scan 或恢复 GPFS stub。

保留 EE 写入磁带的格式互通能力：直接解析 LTFS 索引、范围和 `ibm.ltfsee.gpfs.*` 等带内属性，将其映射到本项目的文件、目录和链接。属性名中的 gpfs 是源格式的一部分；读取这些属性不能触发 GPFS/EE RPC、外部命令或挂载。

## 研究与验收

真实 EE 的参考行为调查可以在隔离实验环境中安装 GPFS，因为这是 EE 自身的依赖。该环境仅用于产生或读取互通样本、核对命令行为，不能成为本项目服务启动、任务执行或验收成功的前置条件。

最终集成候选须在不暴露 GPFS 挂载和 EE 服务的项目测试运行环境中验证 CLI/HTTP、导入及刷新、S3/FUSE 读写、任务恢复和通知。EE 测试与项目测试分别记录版本、依赖、介质身份和证据；EE 成功不能代替项目独立运行通过。

## 当前核对及边界

集成时的源码核对未发现 GPFS/EE 命令执行、GPFS SDK 链接或 GPFS 服务调用依赖。涉及 GPFS 的生产源码主要是带内 EE 属性解析，以及明确不实现 GPFS/HSM 行为的边界说明；其余命中包括格式互通样本与测试。

内部 `reconcile` 名称也用于索引归并、物理状态核对和接管恢复，不能仅凭单词将这些必要逻辑当成 GPFS 依赖删除。用户管理接口不提供 EE 的 GPFS `tape reconcile`。本次源码检查不是最终物理独立运行验收；后者仍须在整体集成完成后执行。
