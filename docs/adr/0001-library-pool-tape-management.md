# 多节点、多带库管理采用 Library → Pool → Tape

2026-11-04，用户确认使用 Library → Pool → Tape 作为首版管理模型，多个节点可共同管理多个 Library，各 Library 有自己的参与节点和唯一就绪 active_node，并尽量分散在不同健康节点。去掉 nodegroup 和默认 G0，避免额外分组阻断带库接管或让池归属依赖节点部署；执行权仍通过多数派许可与设备隔离建立。

任务与目录权威保存在 FDB，索引导入必须异步受理；SQLite 仅作本地索引暂存和缓存。首版不迁移旧分组及原型持久格式，备份并清理受影响实验元数据后重建。完整约束、接口和验收条件见 [管理模型规范](../management-model.md)。
