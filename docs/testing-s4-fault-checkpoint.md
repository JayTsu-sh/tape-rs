# 实验室 S4 故障检查点

真实故障验收需要准确区分磁带尚未提交、S4 已完成但 FDB 尚未登记、FDB 已发布三个阶段。仅在日志中看到“开始提交”再停止 FDB，不能证明命中了第二个阶段。

`hardware-fault-tests` 是显式测试构建 feature，依赖 `fdb`，不增加依赖包或管理 API。正常发行构建不启用此 feature。启用后的守护进程只有在设置 `TAPE_RS_TEST_S4_GATE_DIR` 时才读取测试计划；不要将该环境变量加入正式服务配置。

测试目录必须是当前运行用户拥有的绝对路径、权限 `0700`，文件权限 `0600`，最终路径不能是符号链接。检查点以打开的目录句柄访问计划和回执，JSON 文件最大 64 KiB。协调者须独占创建并同步文件，通过同目录临时文件加硬链接原子发布，不能覆盖已有文件或边写边暴露 `release.json`。

`plan.json` 固定本次实验的身份：

```json
{
  "version": 1,
  "nonce": "本次实验的规范小写 UUID",
  "namespace": "原命名空间 UUID",
  "library_serial": "实际目标带库序列号",
  "volume": "原磁带卷 UUID",
  "previous_generation": 201,
  "request_epoch": 1,
  "operations": ["按字典序排列、不重复的全部原上传 operation UUID"]
}
```

有原请求与计划重叠时，整个合批必须与计划完全相同，且库、命名空间、卷及代数一致；拆批或身份不符会在追加正文前拒绝。其他原请求不触发该计划。`armed.json` 在首次追加前独占发布，保存原批次、各上传身份和前代索引摘要；已消费的实验不能重新启动。

只有 `sync_batch` 成功返回、并取得实际已提交索引后，检查点才发布 `hit.json`。此时正文、索引、最终屏障及 VCI 已完成，下一步 FDB 索引登记尚未执行。`hit.json` 保存实际卷、代数、位置、索引摘要，并绑定 `armed.json` 的 SHA-256。等待最多 120 秒；等待期间不发设备命令，不变更执行权、预约或 FDB 检查点。

实验协调者确认实际命中后，按原服务阶段记录注入独立 FDB 集群故障，再发布 `release.json`：

```json
{
  "version": 1,
  "nonce": "与 plan.json 相同的实验 UUID",
  "armed_sha256": "armed.json 原始字节的 SHA-256 小写十六进制",
  "hit_sha256": "hit.json 原始字节的 SHA-256 小写十六进制"
}
```

释放仅结束本地测试等待；后续 FDB 登记继续执行原有权限检查。释放不符、文件错误或等待超时均返回未知结果，保留原请求和实验文件；不能再次提交新身份、重写正文或清除池屏障。协调者必须恢复其已发出的原 FDB 服务操作，核对相同配置、二进制和全部服务终态，再查询并恢复原上传。

这些本地文件用于证明实验时序，不是目录权威、擦除许可或恢复凭据。恢复仍由原 FDB 批次和实际磁带索引决定。验收还须独立核对原上传回执、所有正文摘要、物理 WRITE 次数、代数变化和最终机械占用；检查点命中本身不算通过。软件单元测试不替代真实带库验收。
