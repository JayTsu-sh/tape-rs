# FDB 只读元数据入口

启用 `fdb` 特性构建的 `ltfsd` 提供 `--fdb-metadata-readonly`，作为 Active 带库路由的只读运行时验收入口。它要求 `--fdb-cluster-file`、`--client-listen`、真实 `--changer-serial` 或 `--libraries-config`，以及现阶段启动参数中的节点编号、成员和独立 `--data-dir`。所有配置带库必须已经通过 FDB Active 路由验证。进程只持有数据目录实例锁、连接 FDB 并监听 HTTP；不打开 Raft、SQLite 目录、spool 或设备，不申请 VIP。旧服务遇到 Active 路由仍拒绝启动。不能用此模式代替正式文件服务或启用写入。

每个请求使用配置中的物理带库序列号。路径和目录游标采用无填充 Base64URL，避免路径分隔符与二进制键在 URL 中产生歧义：

| 请求 | 返回 |
| --- | --- |
| `GET /readyz` | 所有带库的 Active 路由均有效时 200，否则 503 |
| `GET /v1/fdb/stat/{serial}?path={base64url}` | 同一 FDB 读版本的文件或目录元数据；文件包含长度、版本、卷、条码及已知摘要 |
| `GET /v1/fdb/children/{serial}?path={base64url}&limit=100&after={cursor}` | 同一 FDB 读版本的目录页；`limit` 为 1–100，`after` 使用上页 `next` |

路径必须是以 `/` 开头的 UTF-8，最多 2048 字节。目录页的 `name_b64` 保留原始名称，`name` 仅在名称可编码为 UTF-8 时提供。页可能没有可见项但仍有 `next`，调用者应迭代到 `next=null`。每页是独立 FDB 事务；跨页期间发生写入时，当前接口不保证快照一致性。进程固定启动时验证的 Active 路由，每次目录读取在同一事务中核对其身份；路由变化时需重新启动。不在配置中的带库和不存在的路径返回 404；无效参数返回 400；路由失效、FDB 不可用或目录证据损坏时返回 503。此入口不提供文件内容、池管理、任务或任何写入操作。

生产切换仍需正式 owner/PR/S4 执行器、介质身份回读、增量 extent、批次归并回收、可信冻结及亿级规模和真实磁带验收。只读入口的成功不能用作切换许可。

## FC 换带器的预留路径

真实 FC 执行器必须同时配置换带器序列号和 `changer_target_port`（FC 目标端口 WWPN）。同一物理换带器可由不同驱动器端口导出，现场已确认这些路径的 PR 注册表独立；各节点的 `/dev/sgN` 顺序也可能不同，不能按首个序列号匹配选择隔离域。示例：

```json
{
  "default_library": "55L3A78011W9LL01",
  "libraries": [{
    "changer_serial": "55L3A78011W9LL01",
    "changer_target_port": "0x5000e1117018605d",
    "drive_serials": ["117018606F"]
  }]
}
```

单库启动对应 `--changer-target-port WWPN`。发现过程通过 Linux FC sysfs 核对实际远端端口，再结合 VPD 序列号选择设备；指定端口不可见、被占用或元数据无法核实时拒绝成为候选，不回退到其它预留域。端口作为设备配置进入多库 manifest 和候选组摘要；离线扩库、替换/移除驱动均禁止顺带改绑端口。当前没有改变既有多库端口绑定的迁移流程，使用新的隔离数据目录验证。非 FC 单路径发现仍可使用；非 FC 重复路径因缺少已验证的统一预留域而拒绝。带库访问标识、池的故障域仍是真实带库序列号。

## 旧目录的显式暂停和冻结

在旧 Raft/SQLite 模式下，以下管理请求必须指定带库作用域：

```text
POST /libraries/{serial}/admin/catalog/current/quiesce
{"confirm":true}

POST /libraries/{serial}/admin/catalog/current/freeze
{"confirm":true,"quiesce_index":暂停请求返回的索引}

POST /libraries/{serial}/admin/catalog/current/export
```

暂停后新写入及 owner 分配停止，现有健康 owner 可完成收尾。计划停机结束该 owner 后，等待 Raft 确认没有 owner，再冻结；失联或已被新实例替代的旧 owner 由多数派撤销，避免暂停状态反复拒绝新分配而永远无法冻结。冻结请求仍由状态机检查精确暂停轮次、owner 和任务状态，不会强制清除健康 owner。冻结完成后允许 FDB 只读 owner 重新接任，旧 SQLite 执行器仍拒绝接管。

节点导出始终由收到请求的本机处理，多库网关不会将这个只读 POST 转发到 Leader。响应返回该节点编号、应用水位、冻结索引和快照 SHA-256；验收须将下载文件与响应头一起交给 `verify_node_export`，使用三个实际节点的导出生成证书。`examples/fdb_empty_cutover.rs` 仅服务隔离空目录演练，要求显式环境门控，拒绝导入含池、磁带、文件或任务的快照，不访问设备，也不提供一般生产迁移功能。清单必须包含冻结前已经实际取得 PR 的旧 owner 轮次，作为 FDB owner epoch 基线；不凭冻结索引推算轮次。重试仅可复用节点、应用水位及摘要完全一致的既有预备证书，拒绝覆盖不同证书或再次激活活动路由。

## Raft/PR owner 只读接任阶段

`--fdb-owner-readonly` 是独立于上述无设备只读入口的阶段性运行模式。它要求 `--fdb-cluster-file`、`--libraries-config` 和 `--client-listen`，并要求配置中的每个真实带库序列号已有有效 FDB Active 路由。此模式沿用原 `ltfsd` 三节点 Raft 数据目录和设备组配置：Raft 确定 owner 后，执行线程用同一多数派许可逐 CDB 守护并取得整个设备组的 PR；在 `Recover` 阶段逐设备回读 PR，核对本节点 Raft 的 `catalog_frozen_index` 等于 FDB 路由的 `frozen_index`，再推进 FDB owner epoch，之后再次核对许可和 PR。任一检查失败会报告该轮接任失败，不开放文件服务。

该模式在同一 HTTP 监听地址上提供 FDB 元数据和下节的磁带内容读取接口。它不打开或重放 `directory.db`，不启动旧文件写入调度；内容读取可触发只读装卸，不格式化或写介质；上传、同步、管理命令和 VIP 仍未开放。进程创建本地 `fdb-owner-spool` 供现有 Raft 协调对象及匿名读取暂存使用。每次内容请求仍须独立核对介质和全部栅栏，不能只依据 `Serving` 摘要发送内容。正式写入模式仍须在每盘介质恢复、FDB 批次提交、池/任务和大目录内存界限验收后另行启用。

取得本轮 FDB owner epoch 后，执行线程读取换带器库存，并对已装载、已归属的条码在同一 FDB 读版本核对活动路由、精确 owner epoch、磁带分配、卷放置和当前已观察索引。未归属或已分配但尚未绑定卷的磁带不会被读带；无法唯一映射配置驱动器或 FDB 身份不一致时本轮接任失败。对已绑定卷，受守护驱动器只读 P0 标签，检查卷 UUID，按 FDB 记录的位置流式读取精确 DP 索引构造，核对完整文件标记、SHA-256 与数据分区 EOD；随后从 IP EOD 反向定位末构造，逐条流式解析 Full 索引，核对边界、身份及代数不领先已观察 DP。同代 Full 还要求 IP 回指当前 DP，并逐节点核对文件、extent、属性、目录及逻辑头部；文件和目录条目顺序可不同，缺失、额外、冲突路径或 UID 均拒绝。比较使用自动回收的临时 SQLite，页面缓存为 8 MiB，不保留整棵目录树。DP 增量头必须流式回溯到 Full 基线，在临时磁盘库重放；每个前驱的位置、代数、类型及 SHA-256 还必须匹配同一 FDB 读版本中的已观察历史或导入基线。IP 落后仍支持；同代 IP Full 必须匹配重放视图和对应回指。读带失败、DP 介质比 FDB 更新、IP 领先/尾部异常或摘要不符时拒绝本轮 Serving。`Serving` 摘要中的卷数只表示这些条件均通过；这是只读内容的介质证明，尚未接入未观察批次恢复或写入。

冻结旧目录后，Raft 仍复制设备 owner 的候选资格、接任、隔离、就绪和放弃控制事件；池、旧目录及介质状态变更继续拒绝。旧 SQLite 执行器在冻结状态拒绝接管设备，避免把旧写入路径重新打开。隔离 FDB + 模拟设备测试覆盖三节点实际 Raft 竞选、原 owner FC 不可用后的再次接任、两轮全部设备 PR 回读和 FDB epoch 单调推进。该测试在单台机器上的三个进程内节点运行；独立三主机接管另已完成下述空目录/真实 FC 验收，真实介质恢复仍须单独验收。

Serving 期间，执行线程每秒复核本轮多数派许可、所有设备 PR，并从同一 FDB 读版本核对活动路由与 owner epoch。任一栅栏失效或 FDB 无法验证时立即报告 Lost，停止该轮服务；不自动重新抢占 PR。此运行期检查不能替代跨主机进程切换和真实介质故障验收。

## 磁带的 HTTP 内容读取

只有 `--fdb-owner-readonly` 开放以下接口，`--fdb-metadata-readonly` 继续只提供元数据：

```text
GET /v1/fdb/files/{serial}?pool={pool_uuid}&path={base64url}
Range: bytes=0-1048575
```

`serial` 使用配置中的真实带库序列号；`pool` 必须是 UUID，`path` 沿用元数据接口的 UTF-8/Base64URL 规则。例如 `/a` 的路径参数为 `L2E`。池在创建时固定绑定一个物理带库序列号；FDB 当前副本、磁带分配和池的带库归属必须一致。池不跨带库，跨库副本/迁移使用另一库的另一池。读取完全不依赖旧 SQLite 池 lane。请求可发到任一配置节点，入口按该库 Raft owner 转发一次，目标节点重新检查状态；目标改变或转发环路返回可重试错误，不要求用户选择实际 owner。当前 CLI 仍禁止在此阶段开启 `--http-vip`，旧 `/files`、FUSE 和文件客户端协议尚未接入 FDB。

完整响应为 200，单段 Range 为 206 并带 `Content-Range`；无法满足的范围为 416，带 `Content-Range: bytes */总长度`。多段或不认识的 Range 沿用原接口规则返回完整内容。重复 Range 返回 400；存在 `If-Range` 时因未提供可核对的 validator 而返回完整内容。HEAD/写入方法返回 405，不启动读带。Range 从完成全部验证的匿名文件切片，每次请求仍读取并验证整个目标文件；不能把小范围请求理解为按范围读带。响应为 `application/octet-stream`，带实际长度、`Accept-Ranges: bytes` 和 `Cache-Control: no-store`。

| 情况 | 状态 |
| --- | --- |
| 未配置带库、路径不存在、文件不在指定池 | 404 |
| 路径为目录 | 409 |
| 路径/池/查询参数无效 | 400 |
| owner 恢复中、目标磁带无法调度、容量或并发不足、栅栏失效、FDB 不可用或执行器读取失败 | 503，无文件内容 |
| 已验证本地文件无法构造响应 | 500 |
| 等待读取或转发超过配置超时 | 504，无文件内容 |

内容只在执行线程完成 PR/许可、FDB route/epoch、标签、DP/IP、文件长度/已知摘要和最终副本复查后发送。没有摘要的外部文件仍只能核对身份、extent 与长度。下载全程持有 HTTP 并发名额；最多 32 个正在排队、读取或下载的内容请求。客户端等待超时后，已经开始的 CDB 不被强行取消，执行任务继续持有名额直到收到回执，避免超时重试不断堆积设备请求。匿名暂存文件最后一个描述符关闭时释放空间。服务在其他节点转发时，两端分别计入自己的并发上限。正文开始后发生连接中断时无法改发 503，调用方必须根据 Content-Length 判断下载是否完整，丢弃不完整结果后重试。

owner 模式的 `/readyz` 同时检查全部配置库的 Active 路由、Raft owner 就绪状态和匹配的 FDB epoch，返回 `mode=fdb-owner-readonly`。本机 owner 还须持有有效的 Serving 许可；远端 owner 通过一次有界的单库 HTTP 探测确认，端口不可达、失权或 owner 已变化均返回 503。内部 `?library={serial}` 探测避免双库 owner 分散时相互探测整个集群，单次转发最多等待 5 秒。执行线程发生 PR/路由/读取失权时同步关闭本轮许可，再上报控制循环。独立元数据模式仍返回 `mode=fdb-metadata-readonly`。就绪观测不能替代每次读带的栅栏核验。此模式支持下节的按需装卸；VIP、写入和实带内容验收仍未完成。

## owner 按需只读装卸

读取优先复用目标磁带所在的合格驱动器；目标位于存储槽时，查询驱动器的密度能力并选择兼容空驱动器。无空驱动器或达到池的 `mountlimit` 时，只能淘汰本轮已确认卷/池身份的最久未使用读带；达到配额时必须淘汰同池读带。已有兼容空驱动器时，可先卸下另一台不同代驱动器中的同池读带以释放配额，再使用该空驱动器。介质类型未知或无兼容驱动器返回可重试错误。小规模设备/介质策略沿用已冻结的 Raft 管理视图，文件及卷/池归属来自 FDB，不读取 SQLite 池 lane。此阶段不能修改冻结策略。

读带使用现有 `read_idle` 超时后卸回原存储槽；原槽不可用时选其他空存储槽。没有空槽时保留挂载并退避。挂载配额按库存中实际占用和 FDB 磁带归属计算，离线或被策略禁止腾退的同池介质也占配额；可淘汰记录仅决定能否卸下。停机也尝试卸下受管读带，策略禁止或没有空槽时保留介质并释放正常持有的 PR。清洗带、未归属介质和无法确认身份的介质不会被自动腾退。不操作 I/E 槽。库存中任一满元素缺少条码、条码/地址重复或配置驱动器无法唯一映射时安全拒绝；这是可能影响整库可用性的保守限制。

MOVE 前后核对库存、Raft 许可、设备 PR 和 FDB route/epoch。装载后核对卷 UUID，再由读取原语核验 DP/IP 和文件内容。卸载前核对卷/池归属及标签 UUID，UNLOAD 后再次检查全部栅栏，才允许 MOVE。设备错误、失权或移动结果无法确认时结束本轮 owner，不做补偿移动。只读卸载不写 IP、文件标记或 MAM，不宣称执行了写入后的清洁检查点；增量卷的既有数据保持原样。

## 单卷读取缓存的介质证明

`VolumeExtentCache::build_verified_latest_from_media` 按 FDB 精确索引身份流式重读当前 DP 构造，仅在 XML 身份、完整文件标记、SHA-256 和数据分区 EOD 均一致后发布节点本地 SQLite 缓存。介质已有更新的 S4 或未索引尾部时不能把旧索引当作当前头。旧文件可能仍指向更早的索引代数；`build_verified_from_media` 可按位置和摘要重建这些历史缓存，但**不证明介质当前头**。正式读取必须先在当前 owner 许可与设备 PR 下确认最新头，并在使用读取计划前复核所有权。两种构建都会移动读头；由显式 owner 只读 HTTP 入口调用，目前仅完成门控的模拟验收，正式生产尚未切换。

`resolve_active_read_for_owner` 在一个 FDB 读版本中核对启动时固定的 Active 路由、精确 owner epoch、文件当前副本和该副本所用的历史或当前索引身份，并以此身份打开本地 extent 缓存。旧 epoch 或路由变化会拒绝产生读取计划；缓存 UID/长度与已发布副本不符也会拒绝。返回的计划仍只是元数据：执行器在读带前必须重新核对 Raft 许可、设备 PR、FDB owner 和介质当前头；独立 metadata-only HTTP 模式仍不提供文件内容。

`daemon::fdb_read::ActiveMediaReader` 是 owner 执行线程使用的读取原语，要求调用方独占驱动器、提供同一轮次及同一 `Permission` 对象的 `GuardedTransport`。它核对 PR、标签、FDB 当前 DP 的 SHA/完整文件标记/EOD、IP 不领先及同代 Full 的逻辑视图一致性，再按已确认 extent 读取单个文件，校验长度与 FDB 中已知的 SHA-256 或 MD5。没有摘要的外部文件只能核对身份、extent 和长度。内容写入立即取消目录链接的 0600 临时文件，最终再次核对许可、PR、路由/epoch、文件副本和 FDB 卷头；全部成功才返回从头可读的文件句柄。任一步失败不会返回内容句柄，临时内容随句柄关闭回收。此读取原语不装卸介质，owner 在调用前负责只读装卸；增量头只有在完整重放及 FDB 前驱身份检查均通过后才能用于内部读取，已接入显式只读 HTTP 模式，尚未部署正式内容服务。

`resolve_active_read_source_for_owner` 可在缓存尚不存在时，从同一 FDB 读版本取得路径、当前副本及精确来源索引；`ActiveReadSource::plan_read` 随后核对本地缓存。`ActiveMediaReader::read_with_cache` 按卷、代数、位置、摘要及 Full/增量标志组合的身份选择缓存文件：缺失时先证明当前介质头，再流式重建所需的历史或当前索引缓存，重新核对 FDB 来源与卷头后执行读取。已有缓存复用；损坏缓存、非普通文件或身份不符时拒绝，不覆盖诊断证据。缓存可删除后重建，不能授予设备所有权或代替当前卷头证明。

正式 owner 执行线程现支持内部 `ReadTo` 和 `Read` 请求，以及 UUID 池作用域的同类请求。池作用域以 FDB 当前副本的 `placement.pool_id` 校验，读取器在缓存重建前和读带前重新检查，最终仍要求副本/放置不变；错池或非法 UUID 返回 Failed 且不终止 owner。读取调度不依赖旧 SQLite 的池 lane。仅匹配已经装入驱动器的条码；未 Serving 或目标介质未装载时返回 Busy，不触发机械操作。读取前后复查整个设备组 PR，读取或栅栏失败则报告 Lost 并结束本轮；缺失路径或无效读取请求不结束 owner。`ReadTo` 返回已验证的匿名文件，避免再复制整文件；内存型 `Read` 最多返回 256 MiB。缓存目录为本地 spool 同级的 `<spool文件名>.fdb-extents`，独立于启动时的 spool 清理，按来源索引隔离且可跨重启复用。已接入上述显式只读 HTTP 内容入口，只读装卸由 owner 调度，写入仍未接入。

当前实现每次读取仍流式核验当前 DP/IP 索引；增量头还会遍历并重放所需的前驱链。缓存命中可以避免重建 SQLite，但不省略这一步介质扫描。比较/重放临时库、受管理的 extent 缓存和下载文件已接入空间准入；亿级规模下的容量和读取吞吐仍未验收，不能据此宣布生产或亿级性能达标。


## 增量头的磁盘重放证明

`IndexReplay` 只保留节点的逐字段 SHA-256、UID、路径及增量字段标志，不保存整棵目录树、完整节点或 XML。临时 SQLite 的页面缓存为 8 MiB，关闭 mmap；逐构造的主键拒绝重复路径，删除先于新增，目录祖先先于子节点，替换目录会清除其旧子树。每代完成后检查 UID 非零、唯一及 highestfileuid 上界。重放与现有内存算法对照测试覆盖删除、重命名、类型/目录替换、符号链接、清空 xattr 及 512 组局部字段更新。内存还取决于单个节点属性/extent、单条 XML 事件与链深，不是对任意恶意输入的固定内存保证。

`verify_dp_ip_head_with_evidence` 对最新增量核对 FDB 精确摘要/代数/类型、完整文件标记和 EOD，沿严格向前回指验证每个前驱的完整构造，默认最多 64 个前驱，再从 Full 正序落盘重放。`verify_active_index_predecessors` 在同一 FDB 事务中核对当前路由、精确 owner epoch、卷归属、当前头和全部前驱身份；未知、早于导入基线、摘要变化或链不完整均拒绝。长时间读带和落盘重放不占用该 FDB 事务；事务只核对至多 65 个小身份记录。只对前驱做 XML 解析检查不足以授权读取。历史维护检查点也使用不可变代数身份记录核对，不要求它对应文件写入批次。

同代 Full 的物理回指分别核对：IP 必须指向当前 DP Full，且没有增量回指；DP Full 可以保留指向上一份增量的历史回指。它们的逻辑头和节点另外比较，不能要求这两个物理回指字段相同。同代 IP Full 与 DP 增量的内部读取要求 IP 回指 Full 基线及当前增量，并与完整重放视图相符；它不授予写入或清洁卸载资格。清洁一致卷仍应以 DP Full 收束。[SNIA LTFS 2.5.1 §5.4、Annex H](https://www.snia.org/sites/default/files/technical-work/ltfs/release/SNIA-LTFS-Format-2-5-1-Standard.pdf#page=98)

编码器同步修复完整变更节点清空 xattr 时漏写空集合的问题：增量中用已有标准 `<extendedattributes/>` 表示清空，既有解析器已支持，无需新增依赖或迁移持久化格式。不会重写历史索引。

本机显式压测：100 万基线节点、100 万局部增量更新、100 万 IP 节点比较通过，临时库 1,019,904,000 bytes；release 测试 49.73 s，独立进程峰值 RSS 27,056 KiB。此结果只针对合成节点的磁盘重放；未证明亿级全链路、复杂 extent 或真实介质吞吐。这是加入空间准入之前的基线，本机压测显式使用 `/work` 临时空间。


## 实带 Full 源的流式发现与取证

`capture_full_recovery` 从真实 DP EOD 反向定位末 Full 构造，读取原文时顺序写入调用方的临时输出，逐节点解析并在临时 SQLite 中检查路径、UID 和节点指纹。Full 历史链逐代检查自指针、代数和结束标记，同代历史副本必须逻辑等价；前一代的磁盘表交换为下一轮基线，不累积目录树。随后沿用现有严格 DP/IP 核验，包括原文摘要、当前 EOD、同代回指和节点/属性一致性。历史深度仍受 `RecoveryBudget.max_chain_len` 限制，截断状态明确返回；不能将预算内核验写成完整历史审计。

返回值只有构造身份、原文长度、EOD、IP 代数及历史核验状态。内存取决于单个节点或 XML 事件、目录深度和固定 SQLite 页面缓存，不随文件总数建立内存目录集合；巨大单节点属性仍可能占用较多内存。临时盘沿用 `IndexScratchBudget` 的预分配、页面上限和空间不足拒绝规则。调用方的原文输出也占用临时盘，必须在函数完整成功后才发布；失败留下的原文只能作为未验证诊断证据。

这是已完成尾部的 Full **只读源证明**，不授予写入、清洁卸载、T1/T2 修复或未知增量头的启动资格。增量头或历史增量前驱显式拒绝；已有 FDB 精确来源的增量重放继续走原来的磁盘重放路径。旧写入恢复和 `LtfsVolume` 的整树接口尚未因此改成流式，不能据此宣称全部恢复流程均已完成亿级改造。

`examples/fdb_physical_read_acceptance.rs` 默认使用这一入口：捕获成功后分别流式建立 `ImportSpool` 和 extent 缓存，逐条核对，再通过 `VolumeExtentCache::read_file_to_writer` 读取参考文件，避免重新挂载整棵索引树。它要求显式环境门控和操作者已经持有的 PR，并对每条读取/定位命令前后回读预留；不连接 FDB、不格式化或写介质。`--legacy-tree` 仅用于对照旧路径。源清单不是三节点冻结或生产迁移证书，缓存读取也不能独自证明 owner 或介质当前性。

## 索引核验临时盘准入

Full 比较与增量重放共用 `IndexScratchBudget` / `ScratchDatabase`。owner 接任和内部读取显式使用每库本地 spool 目录，不再依赖 SQLite 的进程级临时目录选择；底层工具可通过 `RecoveryBudget.index_scratch` 指定已有目录、单次上限及文件系统余量。默认开发预算为单次 128 GiB、余量 1 GiB，不代表亿级目录的实测容量或正式容量承诺；当前 owner 启动参数可覆盖这些值。

临时文件以随机名称、`create_new`、0600 创建。开始索引读带前先检查文件系统可用空间，并以 Linux `fallocate(KEEP_SIZE)` 在同一个数据库 inode 预分配真实磁盘块；以后逐节点按需增长，每段 16 MiB，最后一段受预算限制。SQLite `max_page_count` 只允许增长到已经预留的页数，8 MiB 页面缓存和关闭 mmap 的限制不变。Full 基线复制改成逐行处理，避免大条 `INSERT SELECT` 绕开逐段预留。空间不足、文件系统不支持预分配或超过预算均中止证明，不返回已验证内容。

物理块预分配使同一文件系统上的多个库、多个进程实际竞争空间；`fstatvfs` 的余量检查是采样，不能阻止其他进程随后消耗余量，也不等于对整台主机提供文件系统硬配额。当前索引查询使用现有路径/UID 索引，不引入额外全量排序。主证明数据库使用这一页数预算；下述受管理 extent 缓存和下载文件使用各自上限，并通过真实块预分配竞争同一文件系统空间。其他 SQLite 工作文件和外部写入者不受这些预算约束，不能据此宣称整节点硬配额隔离。

连接关闭后删除自己的临时文件并归还块，失败路径同样处理；不清理其他缓存或数据库。进程被强杀可能留下命名临时库，由该库 spool 的既有启动清理回收，底层工具自行负责指定目录中的遗留文件。默认上限可使超大或复杂索引安全拒绝，但尚未验证亿级文件在该预算内一定能够完成。


启用准入后的本机 release 合成重放复测：100 万基线 + 100 万局部增量 + 100 万 IP 节点，55.84 s，峰值 RSS 26,916 KiB，数据库逻辑大小 1,019,904,000 bytes（不含预留尾段和文件系统元数据）。只是一轮测量，不是亿级或实带性能保证。独占 24 MiB 文件系统另测并发预留：实际空间不足时安全拒绝，两次并发分配也可能同时失败；全部释放后能再次准入。它验证安全和资源回收，不保证竞争时一定有一个请求成功。

## extent 缓存和下载暂存预算

仅 `--fdb-owner-readonly` 可设置以下参数，单位为 MiB。每库分别应用，非法零值和长度溢出由 CLI 拒绝；保留余量允许为零。默认值是开发上限，不是亿级或实带容量保证。

| 参数 | 范围 | 默认值 |
| --- | --- | ---: |
| `--fdb-read-index-mib` | 每库单次索引核验临时库 | 131072 |
| `--fdb-read-cache-mib` | 每库受管理 extent 缓存目录总量 | 131072 |

## 单节点属性 4 MB 限制的评估（2026-10-27）

结论：4,000,000 字节限制是原单事务实现的临时保护，不能作为长期的 LTFS 导入规格；也不能在原实现上直接删除或提高。应分离“可保存的属性总量”和“每次处理的资源预算”，先实现大属性的分批上传与原子发布，再解除这一固定导入门槛。以下为实施前的分析；已实施范围、验收与仍存边界见下一节。

### 当前限制实际约束什么

`managed_catalog/attributes.rs::MAX_ENCODED` 限制一个文件或目录的全部编码属性，包括 NodeMeta、全部 xattr 的键和值、base64 标志及符号链接。它不是单个 xattr 的大小，也不是文件内容、整个索引或整卷的容量。base64 属性当前按编码后的字符串计费，不能直接等同于解码后的字节数。

超过 64,000 字节后，属性拆为多个 64,000 字节分块，但 `write_attribute_chunks` 在调用方的同一个事务内写入全部分块，`publish_in_state` 还要发布文件 head、副本、反向索引和操作记录。分块只解决单 value 大小，不解决单事务负载。导入清单在调用 `NodeAttributes::from_file/from_directory` 时已经执行 4 MB 检查，尚未连接 FDB 就可能拒绝整个源；因此这是把存储提交预算提前耦合到了来源解析中。

核对正在使用的 [FDB 7.3.78 官方限制说明](https://github.com/apple/foundationdb/blob/7.3.78/documentation/sphinx/source/known-limitations.rst)：单 value 最多 100,000 字节，事务 affected data 最多 10,000,000 字节，且官方建议对超过 1 MB 的事务重新设计。事务约五秒的版本窗口也限制跨时段读写。4 MB 并非 FDB 要求的数值。它为其他记录留有大小余量，但不能证明任一调用方总事务大小、时延或并发内存都满足要求。

现场 AA0013L8 的只读源取证在建立清单时已遇到“LTFS 节点属性超过单次提交预算”。这证明当前门槛阻挡实际介质接入；不能据此推断介质损坏或删减其属性。该次失败已正常归槽和释放 PR，未完成非空 FDB 导入验收。

### 为什么不能直接去掉

当前 `NodeAttributes::Complete` 同时持有解码字段和完整编码 Vec，构造、克隆、重试、分页和 `hydrate_node` 还会产生额外分配。单节点限制不能代替总并发字节预算，按条数分页也不能保证页面内存有界；直接放开会放大内存、事务重试和恢复成本。`AttributeManifest` 还使用 `u32` 长度和 `u16` 分块数，现有强制转换依赖有限大小；不能只改常量而忽略格式范围、溢出检查和兼容性。

亿级文件场景不意味着需要更大的单文件属性上限，而是需要小的常用元数据、更少的写放大和按需读取。即使平均每文件仅有 1,000 字节属性，1 亿文件也有约 100 GB 属性原始数据，尚未计算 key、索引、副本和存储开销。单纯提高最大值不能解决这一规模问题。

### 推荐的边界与发布方式

| 层次 | 推荐约束 |
| --- | --- |
| 属性完整性 | 不以固定 4 MB 作为源格式合法性判断；完整保留原属性，拒绝静默截断、丢弃或伪装导入成功 |
| 单 value | 保留 64,000 字节分块作为初始实现，低于 FDB 单 value 硬限制 |
| 单事务 | 按实际 key/value、其他 mutations 和冲突范围预留预算；初始以约 256 KiB 写入为目标，低于 1 MB，依据三节点测试调整，并非 FDB 硬限制 |
| 处理资源 | 限制在途字节数、并发、缓存和暂存磁盘；按字节分页，单个大值也须流式处理，超预算明确失败且可恢复 |
| 常用查询 | UID、时间、只读位、符号链接、版本及定位/校验所需字段独立保存；路径解析、stat 和普通目录列举避免读取全部自定义 xattr |
| 大属性读取 | 按属性或不可变对象分块读取；跨事务保持同一对象身份，验证长度、分块和完整摘要，读取期间防止 GC 删除 |

大属性先写入不可变的独立版本对象，按预算分多次事务提交；分块与进度持久化，允许幂等重试。全部分块验证完成后记录完成状态，最后用小事务检查当前 namespace、来源、owner 和目标版本并发布对象引用。读者只能看到完整旧版本或完整新版本。不可覆盖读者仍可能持有的旧分块；回收必须考虑未发布上传、活跃上传、已发布引用和在途读取，不能仅按上传时间删除。普通小属性继续走短事务，避免为亿级常规节点都增加暂存事务。

本地 SQLite 可承载原文解析和上传暂存，不能成为唯一的大属性权威来源；正式接入后的属性对象和引用需要由 FDB 或已明确设计的共享持久存储保存。当前不为解决这个问题额外引入对象存储。新增写入的产品配额可以独立制定，但不能把 FUSE/HTTP 暴露限制或当前 FDB 事务预算当作旧 LTFS 介质导入的格式限制。

验收至少覆盖 4 MB 边界、真实 AA0013L8 属性完整回放、跨多事务大小、上传和发布前后崩溃、重复上传、owner 切换、缺失/篡改分块、并发读取与 GC，以及同等并发下的 RSS 和实际事务大小。解除当前门槛前应通过这些检查；不能用更换为属性较小的磁带宣称此缺口关闭。

## 大属性分批提交与原子引用（2026-10-27）

已取消 `MAX_ENCODED=4_000_000` 门槛。`attribute_objects` 在 FDB 的 namespace 内保存不可变属性对象，以完整属性摘要标识；属性总量与事务大小分离。每个 value 保持 64,000 字节，一次上传事务最多写四块及进度记录，并设置 `TransactionOption::SizeLimit(512_000)`。完成全部分块后才能由原有 namespace、来源、owner 和文件版本检查所在的小事务发布引用。上传中断只留下私有的可续传前缀，重复提交不会重写已完成对象；未完成对象不能成为 inode 或活动准备记录的可见引用。小属性仍直接内联，避免给常规节点增加上传事务。

上传和读取都不再一次收集整个分块集合。读取按四块一批使用新事务，逐块检查顺序、长度、总量及完整摘要；结构校验流式检查字段、UTF-8、标志和 EOF，跨块多字节字符也必须合法。namespace 校验先在状态写事务外完成对象的流式验证，再确认校验游标及对象完成引用，提交原有小事务；并发校验推进游标时不会使用错页证明。对象在 namespace 存续期间保留，覆盖 inode 不删除旧版本；清理仅限显式废弃、无保留引用的 namespace，不执行按时间回收活动对象。

`NodeAttributes` 内部共享不可变属性，事务重试不深复制整组 xattr。清单导入移动已解析字段，解码接管已有编码缓冲；分页同时限制条数与约 8 MiB 的编码属性总量，单个超预算节点独占一页并仍完整返回。HTTP `stat`、路径中间目录和目录列举不再展开大 xattr；需要完整属性的既有 API 保留完整返回语义。新增 `node_attributes_to` 按原编码流式输出，调用者必须先写私有暂存，只有最终长度/摘要核验成功后才能向外发布结果。

持久化变化：新的 inode 外部引用 tag 为 3，活动准备 marker 为 v2；旧原型格式拒绝解码，不能混跑或直接复用旧原型候选，应重建尚未切换的候选。属性本体编码 v1 和 SQLite 清单 schema 不变。当前引用仍使用 `u32` 长度及 `u16` 块数，因此保留 4,194,240,000 字节的编码可表示边界和溢出检查；它与每事务预算分开，不能将其理解为无限制属性存储。正式旧 Raft/SQLite 服务未切换。
