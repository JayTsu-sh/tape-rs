# 完整库存响应校验

`MediumChanger::read_all_status` 发起一次覆盖地址 map 的 READ ELEMENT STATUS 请求。只有报告、页及描述符完整，元素数量与报告头和 map 一致，每个地址唯一且属于对应类型的 map 区间，才返回完整库存。截断或缺少元素时报错，不返回部分成功、不自动请求第二份库存，也不推断介质不存在或槽位空闲。

解析器保留报告范围外的传输填充规则：这些填充不作为元素数据；完整空页不阻止后续页解析。描述符须容纳12字节固定字段、每个声明卷标的36字节，以及已出现的DVCID头和其声明的正文。未知页类型、非空页的零描述符长度、残缺页头/描述符均拒绝。生产 CDB 的字段、分配长度、超时及 SG_IO 绑定没有改变。

依据 [IBM TS4300 SCSI Reference SC27-4641-00](https://www.ibm.com/support/pages/system/files/inline-files/%24FILE/SC27-4641-00_1.pdf) 印刷页48–49：报告声明可用元素和字节数；缩小 allocation 不会相应缩小可用字节数。设备可以成功返回不完整传输，应用需要据此检查完整性。

纯回归测试先证明旧代码会接受只剩8字节头部的截断回复，以及长度自洽但少一个存储槽的回复；修复后全部拒绝。正常完整回复、报告外填充及空页后继续解析仍通过。

`tests/changer_live_inventory_readonly.rs` 是显式忽略的真实设备探针，必须指定 changer 路径、序列号、主 FC 端口和当前项目 PR 键。探针先核对端口、序列号及预留，每次查询前后再核对预留；只读传输禁止无数据和写命令。测试适配器仅在探针内缩小 READ 请求为头部或一个元素，验证真实设备回复交给同一核心后被拒绝；完整请求应通过。它不会搬带、装卸、初始化或修改 PR。
