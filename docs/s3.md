# 匿名 S3 HTTP 接口

S3 接口由 tape-rs 的 ltfsd 提供。当前生产入口统一使用 FoundationDB 保存池、文件目录、属性和持久任务，文件正文写在磁带上；FDB 本身不是 S3 服务。管理接口与 S3 都使用 HTTP，通过同一个受管理的 VIP 访问；FUSE 与 Rust Client/lib 继续使用原文件接口，直接连接各节点物理地址。

| 使用方 | 地址与接口 |
| --- | --- |
| 管理运维 | `http://<VIP>:7401/admin/...` |
| 外部 S3 客户端 | `http://<VIP>:7402/<bucket>/<key>` |
| FUSE / Client/lib | 各节点物理地址的 `7401` 端口，原 `/libraries/.../pools/.../files` 等接口 |
| S3 内部转发 | 当前带库 owner 的物理节点地址与 `7402` 端口 |

S3 不要求 AK/SK，不校验 Authorization / SigV4；所有请求均以匿名身份处理。连接到 S3 端口即能执行开放的读写及对象删除操作。管理接口的既有行为独立于 S3。

## 启动与 VIP

在所有集群节点的原启动参数上增加以下配置，地址须替换为实际已预留的同子网 VIP：

```bash
--libraries-config /etc/tape-rs/libraries.json \
--fdb-cluster-file /etc/tape-rs-fdb/fdb.cluster \
--fdb-owner-writable \
--fdb-s3 \
--client-listen 0.0.0.0:7401 \
--client-port 7401 \
--http-vip 192.0.2.100 \
--http-vip-interface eth0 \
--s3-listen 0.0.0.0:7402 \
--s3-port 7402
```

使用含真实设备序列号的 `--libraries-config`，单库也使用此配置。S3 要求 fdb 构建特性、FDB owner 模式和显式 `--fdb-s3`；只读 owner 只提供查询和读取。不给 `--s3-listen` 时不开 S3。S3 监听必须是 `0.0.0.0:<s3-port>`，同时接收 VIP 请求和节点间转发；各节点 S3 端口一致，节点之间应允许访问该端口。S3 不单独申请第二个 VIP，地址漂移与许可沿用[现有 HTTP VIP](http-vip.md)。

客户端始终使用 VIP。VIP 入口按 bucket 定位带库与 pool，再单次转发到该库 owner；不向客户端重定向到物理 owner，也不在失败后重放正文。VIP 切换会中断已有 TCP 连接，客户端新请求仍访问同一个地址。

启用 S3 不改变 FUSE / Client/lib 的接口。它们应配置各节点物理地址；多库启动时给这些客户端的节点提示也使用物理地址。管理与内部文件 HTTP 目前共用监听端口，通过访问地址和路径区分用途，并不因此新增内部文件客户端的 VIP 依赖。

下述查询、内容上传/覆盖、删除与 RenameObject 均使用同一个 FDB 权威，磁带操作复用已有 owner、PR 隔离和提交流程。生产启动不再提供旧 SQLite S3 后端回退，见 [FDB S3 对象接口](foundationdb.md#s3-对象接口)。

## bucket 与 pool

一个 bucket 唯一对应 `(真实带库序列号, pool UUID)`。通过管理 HTTP 创建 pool 后自动出现在 ListBuckets；管理接口成功删除 pool 后对应 bucket 消失。没有独立建桶、删桶动作，不分配介质、不装带、不格式化。原删除 pool 的介质归属和任务限制仍生效。

bucket 名为 `pool-` 加 SHA-256 摘要的前 56 个十六进制字符，输入是序列号的 UTF-8 字节长度（8 字节大端序）、序列号字节、pool UUID 字节。名称符合 DNS bucket 命名的基本长度与字符规则；跨库同名/同 UUID 池仍有不同名字，不受 pool 改名、owner 切换影响，也不引入新的持久化映射。

可先通过管理接口取得 pool UUID，再计算对应名称：

```python
import hashlib
library = '真实带库序列号'.encode('utf-8')
pool = 'pool UUID'.encode('utf-8')
print('pool-' + hashlib.sha256(len(library).to_bytes(8, 'big') + library + pool).hexdigest()[:56])
```

ListBuckets 的 `CreationDate` 使用 FDB 池记录中的实际创建时间，以 UTC 毫秒精度返回。

## 支持范围

| 操作 | 行为 |
| --- | --- |
| ListBuckets | 列举所有已知带库的 pool 投影 |
| HeadBucket / GetBucketLocation | 查询存在性；region 固定 `us-east-1` |
| ListObjectsV2 | `prefix`、`delimiter=/`、`max-keys=0..1000`、`continuation-token`、`start-after`、`encoding-type=url`、`fetch-owner` |
| ListObjects V1 | `marker` / `NextMarker`，兼容 s3cmd |
| HeadObject | 仅查已提交元数据，不装带；没有正文 |
| GetObject | 完整对象及单个字节区间 Range；包括开放末尾与后缀区间 |
| PutObject | 定长整文件上传，磁带 S4 提交和 FDB 目录发布完成后返回 `200` |
| DeleteObject | 通过 FDB 原版本条件提交 LTFS 索引删除并发布后返回 `204`；对象不存在也返回 `204` |

GET/HEAD 支持 ETag 与修改时间条件；ETag 条件优先。PUT 支持 `If-None-Match: *` 和单个强 ETag 或 `*` 的 `If-Match`，DELETE 支持 `If-Match`。预检后仍由 FDB 原 inode/版本条件阻止竞态覆盖或误删；条件失败返回412，执行期间版本冲突返回409。写入的时间条件、大小条件及 `If-Range` 明确拒绝，不忽略后执行。无法满足的 Range 返回 `416 InvalidRange`，多区间请求明确拒绝。

不支持 CreateBucket、DeleteBucket、multipart、CopyObject、批量删除、ACL、policy、版本化、标签、加密、通知或自定义存储类别。`STANDARD` 作为兼容字段接受。未支持操作返回 S3 XML 错误，不能静默当作普通 PUT。原生目录与符号链接不作为可下载对象，GET 不跟随链接。

## FoundationDB RenameObject

本项目实现 S3 服务端，因此可在已有 pool bucket 上提供 `RenameObject`。使用原 S3 端口、匿名和 path-style 请求；可写 owner 将它交给现有 FDB rename 执行器，完成后返回200空正文。只读 owner 拒绝改名。

```bash
aws --endpoint-url http://<S3地址>:7402 --no-sign-request s3api rename-object \
    --bucket <bucket> --key new-name.bin --rename-source <bucket>/old-name.bin \
    --destination-if-none-match '*' --client-token <保存并重复使用的唯一token>
```

支持两端 ETag/时间条件与持久 token 幂等。响应丢失或504后必须使用同一 token 和参数重试，不能用新 token 操作可能已被重建的原名字。同一 token 改参数返回400；已完成结果可以在 owner 不在线或当前名字变化后重取。对象正文、用户元数据、摘要和 Last-Modified 保留。

当前限定同 bucket 普通对象、已有父目录；不改名目录或链接。FDB ETag 使用逻辑身份版本，改名后会变化；跨卷改名仍可能装带并提交 LTFS 索引。AWS 将 RenameObject 限定为 S3 Express One Zone 目录桶，本项目将其作为现有 bucket 的扩展，具体条件、状态码与验证边界见 [FDB RenameObject](foundationdb.md#s3-renameobject)。

## key、元数据与提交

普通 key `project/a.bin` 对应指定 pool 中的 `/project/a.bin`，与内部文件接口共享命名空间。第一版限定为现有文件模型能无损表示的路径：不能有前导/重复/尾斜杠、`.`/`..` 分量、控制字符、XML 1.0 不接受的 U+FFFE/U+FFFF 或 `.tapers` 保留根路径；不能同时存在文件 `a` 与其子路径 `a/b`。不能无损表示的 key 返回错误，不进行归一化。百分号只解码一次，`+` 保留为加号，中文及空格可用。内部文件接口留下的非 XML 字符对象名，须用 `encoding-type=url` 列举；默认列举遇到它们返回 `400`，不生成非法 XML 或改名。

上传必须提供 `Content-Length`，流式写入暂存文件，不将整文件放入内存。上传中断或 MD5/SHA-256/CRC32 校验失败时释放准入与暂存，不能排入磁带提交队列。支持 `Content-MD5`、普通 `x-amz-content-sha256` 以及头部 `x-amz-checksum-sha256`、`x-amz-checksum-crc32`（IEEE CRC32，大端四字节 Base64）；SDK 的 `x-amz-sdk-checksum-algorithm` 必须与实际校验头一致。一次上传只接受一种 checksum；不支持 CRC32C、CRC64、aws-chunked、HTTP chunked 或 trailer。multipart 与 aws-chunked 是不同机制，两者在本版均未实现。

S3 PUT 持久化标准 LTFS MD5 及 SHA-256 摘要。ETag 统一为 FDB namespace/inode/逻辑版本构成的 opaque 标识，与 HEAD、GET、条件请求及 RenameObject 一致，不作为 MD5 使用。完整对象的 HEAD/GET 使用 `ChecksumMode=ENABLED` 时，优先返回上传时验证且与当前正文 SHA-256 绑定的 CRC32；没有有效 CRC32 时返回已知 SHA-256。Range 不返回完整对象校验值。经 FUSE 改写正文后，即使旧 S3 属性被保留，也不会返回旧 CRC32。

`Content-Type`、Content-Encoding/Language/Disposition、Cache-Control、Expires 与 `x-amz-meta-*` 随对象元数据持久化，总序列化长度上限 8 KiB。S3 PUT 替换对象元数据；原文件接口保留现有覆盖语义。

上传先校验完整正文，再为新 key 按需创建 FDB 目录；同名普通对象采用原版本条件覆盖。父目录创建也走原有持久节点任务，后续上传失败可能留下空目录，不会发布部分文件正文。S3 原请求的替换属性在任何追加前绑定到原 operation 和指纹并持久保存；接管沿用真实 LTFS 提交与原 FDB 发布证据。内部 `202` 仍只代表暂存，S3 不把它映射为上传成功。覆盖提交前可读旧版本，提交后发布新版本。读取核对版本与暂存文件长度，发现读取期间换版时返回冲突。DELETE 复用 FDB 单节点 Unlink 任务，等待 LTFS 索引删除提交及 FDB 发布，不立即擦除历史字节或回收磁带空间。

HTTP 超时、响应丢失、owner/VIP 切换可能使已提交写入的响应丢失。S3 不承诺 exactly-once；重试可能产生额外磁带写入。结果未定错误包含内部任务号（已知时），应通过对象 HEAD/GET 和内部文件任务接口核对。

对象列举使用 FDB 有界范围扫描，按完整 UTF-8 键字节字典序分页，默认/最多1000条；不全量收集后排序截断。token 绑定 bucket、namespace、prefix、delimiter 与游标，跨节点可继续使用。HEAD/list 只读取已发布元数据投影，不加载大属性或装带；跨页不提供全局快照，百万/亿级性能仍待验收。

写入始终绑定 bucket 对应的 pool。复用现有按池、多驱动调度和 mountlimit；资源不足时返回明确错误或等待现有调度，不回退到其他池。空池可列举，但 PUT 需要管理端先配置可写介质。

## 客户端

AWS CLI 使用 unsigned 请求和 VIP；单次上传优先使用 `s3api put-object`：

```bash
aws --endpoint-url http://192.0.2.100:7402 --no-sign-request s3 ls
aws --endpoint-url http://192.0.2.100:7402 --no-sign-request \
    s3api put-object --bucket <bucket> --key project/a.bin --body ./a.bin
aws --endpoint-url http://192.0.2.100:7402 --no-sign-request \
    s3api get-object --bucket <bucket> --key project/a.bin ./readback.bin
```

SDK 配置自定义 VIP endpoint、path-style、匿名/unsigned 模式、已知 Content-Length；支持 SDK 默认的头部 CRC32，无须关闭该校验。禁用自动 multipart，磁带操作的客户端读取等待应覆盖实际装带与提交时间，不改变底层 SCSI 超时。

s3cmd 2.4.0 自身要求凭据配置并签名，可设置客户端占位值 `anonymous` / `anonymous`；服务端没有对应密钥，也不验证该签名。配置 `host_base=<VIP>:7402`、`host_bucket=<VIP>:7402`、`use_https=False`、`bucket_location=us-east-1`，上传加 `--disable-multipart`。占位配置只用于满足该客户端，不代表身份或权限。

## 验证入口

默认 Rust 测试只使用内存 SimLibrary。定向运行：

```bash
cargo test --lib daemon::s3
cargo test --bin ltfsd s3_cli_tests
cargo test --test ltfsd_cluster s3_ -- --test-threads=1
cargo test --test multilib_cluster
```

外部客户端互操作使用可选 Python 环境，不增加生产 Rust 依赖：

```bash
# 在独立 Python venv 安装 boto3、awscli、s3cmd 后：
TAPE_RS_S3_PYTHON=/path/to/venv/bin/python \
    cargo test --test ltfsd_cluster s3_external_clients -- --ignored --nocapture
```

该测试启动三节点模拟集群，通过非 owner 的本机入口运行真实客户端，不访问设备、不配置真实 VIP。它不能代替 Holo 虚拟介质、真实 VIP 漂移或物理带库验收；部署及现场完成情况以最新交接记录为准。

FUSE与S3共用同一FDB命名空间；最新[FUSE物理验收](../.scratch/ltfs-ha/reports/fuse-fdb-physical-20261104.md)包含独立S3读回及删除后再改名的UID历史判定修复。

三台物理节点 `10.131.7.207–209` 已使用相同版本启用 FDB S3；访问地址为 `http://10.131.7.219:7402`。A 库测试池 `s3-acceptance-20261104` 对应 bucket：

```text
pool-053468f37a1ca04b042cc67471d64d003487c491740abda730d216aa
```

该池使用 `AA0017L8`，保留 `readback.bin`、`empty`、`samples/中文 +%2F.bin` 三个样本。`readback.bin` 为 16,878,000 字节，SHA-256 为 `318c396ba827547fcdc90116dc628205201b1fbf6aa3ab80a6c5990d56f47c10`。

真实带库上已验证上传、覆盖、下载、Range、元数据替换、条件请求、分页、RenameObject 原 token 重试和删除；正常重启全部三个项目服务后，再次下载三个保留对象，长度、摘要、ETag 和元数据一致。FDB 集群在此过程中保持运行。完整范围、原始失败与修复、SCSI 日志及未覆盖项见[物理验收报告](../.scratch/ltfs-ha/reports/s3-fdb-physical-20261104.md)。
