# 续期契约回溯与条件线性化细化

日期：2026-09-16；票据 31。仅审计现有规划中记录的接受项、给出顺序对象和历史映射草案；不实现、不运行模型、不选择容器/时钟或添加实时假设。现有规划是未提交文件，引用标明本次读取的位置；不冒充对历史聊天或旧文件版本的独立考证。

## 结论

**原始 QG/RQ 没有把最终确认可见点 C 固定为逻辑接受点。** 第 30 轮把 P 限定为“尚未接受登记”、进而要求 C<D，是助手后来选择的更强解释；不能将它倒写为用户已明确要求。纠正该解释不等于允许过期后取得新证据续活。

可以推进以下条件细化候选：完整非时间证据已在 P 前就绪，发布后的可信样本证明 P 早于原截止 D 和原证据期限 E；**成功分支的续期逻辑生效点为 P，C 仅公布其可核验结果**。Pending 期间不使用新期限；任何真正终止都不可逆。下面给出覆盖读者和失败分支的顺序规格及映射条件，尚不是完成的形式化证明或可直接宣称安全的 Rust 实现。

## 2. 原始文献只提供证明框架

Herlihy/Wing 定义以合法顺序历史解释并发调用、保持非重叠操作次序；生效可以先于返回。必须依据对象语义解释所有结果，不能给每条不合意轨迹任意挪动时间。下述对象、Pending 映射及条件生效规则是项目推论，不是论文提供的现成算法。[原论文，第 1—2 节][linear]

后采样论证还依赖同一可信时钟及 P→样本的真实顺序。Rust Instant 不保证匀速或统一的系统挂起语义，平台问题可能破坏单调性；本报告不以“单调”代替暂停模型验证。[官方 Instant 文档][instant]

## 3. 最小顺序对象（本地内存语义候选）

对象按精确运行实例/许可身份管理 `Live(D, revision, accepted_ctx)` 或 `Terminal(reason)`；终止为吸收态。物理交付不属于这个对象。读取结果是针对本次检查的许可/拒绝，不是无限期 capability。

- **Renew(ctx,E,expected)**：在它的逻辑生效时刻 τ，必须仍 Live、当前前态及全部实质证据匹配，且 `τ<D`、`τ<E`。成功把 D 改为 `max(D,E)` 并消费 ctx。正常不延长结果可单独消费，不借 max 掩盖过期证据。允许返回明确未生效的失败；不得把“已成功但随后终止”报告成仍有效。
- **Check**：在自身有效检查切点，只有 Live 且当前时间小于 D 才能返回允许；若返回可用截止 d，允许 `d≤D` 的保守值，不承诺 d 是精确最新 D。无法证明时可拒绝本次动作；需终止时通过以下操作落地，不能先虚报终止成功。
- **Expire/Stop**：真实到期、适用已知失效或无法证明时效导致的保守关闭，把精确许可置为 Terminal。适用的安全失效不能被后来健康清除；多个来源和范围仍按原门控规则。已过期的许可不能等未来请求补证据继续 Live。
- **Status/Result**：区分“本次拒绝/待核对”“续期曾成功”“本轮已终止”。若 API 要求精确最新截止，而不是保守可用截止，下面 Pending 读法不能直接实现该 API；需返回待核对或另行实现准确查询。

这里允许保守关闭的依据是原 QG 对无法可信判断时效的处理，不新增无限任意失败自由；完整无冲突正例必须能够完成。抽象对象始终只有一个实际截止，表示层旧 D 的保守使用不另创宽限期。

## 4. 具体候选与精确映射

单刷新者先完成 safe、实际 apply、身份/term/配置/轮次等非时间证据；从精确 Live(r,D) 条件发布唯一 Pending P，携带原 D、E、N=max(D,E) 及不可变证据关联。P 本身不允许读者使用 N。

发布后采样 W；必须证明 P 实際先于 W 且 `W<D`、`W<E`，才能生成绑定 exact-P 的证书。若不满足，终止/失败，不能用模型已知的 P 真值替代程序缺失的证书。证书完整公开后才条件 C：exact-P→Confirmed；任何适用限制、终止或上下文变化均不得被覆盖。具体表示仍待票据 29 的同步/生命周期证明。

**成功历史映射：** C 成功且证书真实的分支，把 Renew 线性化在 P。后采样提供 P 的及时性上界，全部实质证据在 P 前完成，前态由条件替换固定。P 后、C 前没有使用 N 的行为；C 不新增期限、不更改 t0，只公布这次及时接受的事实。C 可晚于旧 D，因为在该成功历史中抽象截止已在 P 改为 N，而不是在 D 失效后再复活。

**失败历史映射：** 不要求失败续期也在线性化到 P。若 P 期间关闭先成功，则续期可在关闭之后线性化为失败、无续期效果；P 只是没有被成功实现的准备步骤。若采样失败或当前前提不匹配，则按对应拒绝/终止事件映射。所有失败分支期间读者从未使用 N，因而不需要把失败的 P 强行解释成已授予后又回滚。

这种成功/失败使用不同生效点是待证明的历史映射，不允许实现读取未来或模型真值。系统始终只能依据当前 P、真实证书、条件更新结果与当前时间决策。

## 5. 所有读者分支及终止优先

| 具体历史 | 顺序对象解释与必须约束 |
| --- | --- |
| P 后、旧 D 前读者使用旧 D | 成功续期历史中是 `d=旧D≤新D` 的保守许可；失败历史中仍是原期限。不能将旧 D 对外声称为精确最新抽象截止。 |
| P 后达到旧 D，读者关闭 exact-P 成功 | 返回 Terminal，C 必须失败；把失败续期排在终止之后，不存在成功续期再复活。 |
| 同上，关闭输给 C | 不能先对外宣告已终止；重读证书、当前期限及当前限制。若当前已过 N，立即按该当前期限拒绝/终止；若未过且全部条件成立，才可允许。 |
| P 后读者仅保守拒绝本次动作，没有宣告终止 | 不把该拒绝倒写为已发生 Terminal；若根据现有策略必须关闭，仍保留关闭义务，不能用“拒绝”代替完成。并发合法确认与关闭需按真实结果解释。 |
| P/W 均及时；无人观察；C 在旧 D 后而 N 前 | 可映射为 P 时及时成功，不靠无人运行 timer 取得宽限。其成立依据是证据与 P 的证书；没有证书，即使无人观察也不能继续。 |
| P/W 及时；C 甚至晚于 N | Confirmed 最多公布历史及时接受，不能标签即 Active。读者按当前 N 拒绝；下一 Renew 的 P/W 也必须早于旧 N，否则失败/终止，不能形成续活链。 |
| 旧 D 后才得到 safe/apply 证据，或 P 在旧 D 后才发生 | 后采样无法证明 P<D；拒绝/终止。与“证据及 P 及时但 C 迟到”严格区分。 |
| 适用已知失败/明确 Terminal 发生在 P 前或期间 | 更新关联必须阻断发布或确认。不能把真正失效重新解释成“只是暂时看不到证书”；若确认先成功而后失效，历史成功仍不表示当前有权。 |
| 完整正常刷新及连续刷新 | 各次 P 按单刷新者次序，以前次实际有效 D 为上界核验；原 ctx 不重用。无故障证据及时公开的分支必须有持续进展。 |

多读者的关键不是“有没有人看过 P”，而是有没有形成实际终止及各次返回的语义。任何读者成功终止均使整条成功续期历史不可用；任何声称已终止的返回必须有对应的真实终止依据。失效事件适用性与版本 CAS 竞争不能被这一证明省略。

## 6. 审计判断与下一步

以上给出**可实施逻辑候选的条件细化草案**：原 QG/RQ 的“及时接受证据、无宽限、过期/终止不可复活”可以保留；需要明确修正的是第 30 轮自加的“P 永远不是接受，只有 C 才能接受”的表示解释。不能一面保留该解释，一面又允许 C>D；也不能只改名称而不采用上述所有读者约束。

建议下一步直接冻结这份顺序对象、操作返回语义和成功/失败映射为验证目标；将原 RT02 从“仅凭 C>D 一律否决”改为区分有无及时 P 证书、实际终止及当前 N。随后审查实现级状态表示与观察轨迹，未获实现授权前不运行模型。首先验证：保守截止不冒充精确查询、关闭与 C 竞争、C>N、已知失败覆盖、单刷新链、时钟失信和无故障正例。

仍未完成：所有历史的形式化细化证明、弱内存/时钟与条件发布的组合、资源回收和进展界限。上述序列推导没有证明真实 CDB 交付，也不能直接套用首次启用或 K→G；它们权限与前提不同。报告不宣称已满足完整 RQ/EG/LG，亦不把未验证假设写成系统能力。
