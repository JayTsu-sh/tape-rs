# 参选失效与 Raft 内核调用重叠：契约细化审计

票据 35。固定 raft-rs v0.7.0，官方提交 `10c6e9db6792b85c81784e44fc278f895d5f0ab0`；只读复用该检出并浏览固定源码。未修改库、运行代码/模型或访问设备。

## 结论与需要明确的选择

原 EG 确实要求参选门控覆盖竞选中变化、不能降级选出设备不合格的控制 Leader；但没有定义“任意故障源刚获知的瞬间，另一个线程的 RawNode 连内部 Leader 赋值也绝不能发生”的原子语义。不能把后者冒充用户原话，也不能反过来把原 EG 自动缩成“仅不开放 G”。

**可实际推进的候选是完整的竞选/领导输出隔离，加合法切点退出；不是回滚 RawNode。** 这需要明确产品定义：与失效重叠的不可中断调用可能产生仅内部、未获对外资格的 Candidate/Leader 转换；此后不得发布可用控制 Leader、受理其新 Leader 业务、续跑其竞选/领导输出或建立 K/G，必须保留必要协议历史并退回。若“暂不产生 Leader”被要求包含 RawNode 内部角色，这条候选就不满足，不能仅靠证明包装层正确自行放行。

推荐下一步明确上述可观察契约，作为受控适配验证方向；若坚持更强的内核角色保证，则单独授权设计库内门控扩展及其同步协议。普通回调中读一次资格也不自动满足“源端获知瞬时”的要求。本报告不选择 fork、不宣布 EG 已完成。

## 原接受项与后续草案的证据边界

以下引用来自主工作树规划，而不是 Raft 文献：

- `issues/18-raft-execution-contract.md:40–46`：合格才进入竞选，门控覆盖自动、显式、转移及竞选中变化，保留健康投票/复制和多数派规则。
- 同文件 `:58–66`：无合格候选时不产生 Leader，不降级仅控制 Leader；当选后的隔离/恢复仍是独立门槛。
- 同文件 `:471–495`：后来接受固定候选及合法切点处理，但明确不默认 fork；S/RawNode 已开始调用的重叠仍是缺口。
- `raft-rs-binding.md:96–108`：S 不跨慢保存，源端获知、原子失效和内核消费分开；没有批准通过延后“获知”定义或只关闭 G 解决 EG。

所以此次需要的是明确内核中间态与“发布合格控制领导资格”的关系；它不是重新选择设备门槛，也不允许全部不合格时维持一个可工作的临时控制 Leader。原 EG 留白能支持讨论细化，但不足以自动证明所有人原先已接受这种可观察定义。

## 固定源码核对

| 入口/变化 | 实际路径与适配影响 |
| --- | --- |
| 自动、显式竞选 | `tick_election` 可内部生成 Hup；RawNode.campaign 也转 Hup。`hup` 检查未应用配置后选择预选、正式或转移竞选，不读取设备资格。 |
| 转移 | `step` 先处理 term；Follower 的 TimeoutNow 可以直接 `hup(true)`，跳过 PreVote。禁选不能直接丢弃高 term 处理。 |
| 预选/正式选举 | `become_pre_candidate` 不增加 term/vote；`become_candidate` 增 term 并自投。`campaign` 投自己的票并生成其他 voter 的请求。 |
| 获胜响应 | `step_candidate → poll`；预选赢票可立即启动正式竞选，正式赢票可立即 `become_leader → bcast_append`。一次调用外部前检无法插入这两个步骤之间。 |
| 当选/退位 | 当选设置 Leader/self leader_id，并追加空条目；公开 `become_follower(current_term, INVALID_ID)` 可合法退回。同 term reset 保留 vote，但重置计时、读请求和跟踪；不是只修改 role，也不撤回已生成日志/消息。 |

上述源码依据：[Raft 固定源码][core]，具体区间 `1040–1310`、`1324–1577`、`2220–2373`。这是调用路径事实，不表示直接公开调用底层 become_candidate/leader 是受支持的项目入口；应用必须封装所有内核变更。

`send` 将消息加入本地 Vec，而非直接网络交付；Ready 暴露 SoftState、HardState、entries、消息等，取 Ready 后必须按 advance 契约完成，不能穿插任意 step/campaign。Leader 状态的 Ready 消息可属提前发送组，因此项目隔离策略必须覆盖两组 Ready 消息与 LightReady，不能只挡 persisted_messages。[RawNode 固定源码][raw]、[Raft send][send]

Raft 的 term、vote 和日志有持久安全要求；资格失效不是擦除已投票或降低任期的理由。Raft 允许消息丢失，不意味着可以随意删除本地协议历史或改变已提交结果。[Raft 原论文 Figure 2、§5][paper]

## 明确观察事件，不移动“获知”

用 F 表示来源实际获知，X 表示竞选失效代次发布，I/O 表示一次内核调用开始/结束，M 表示内部角色变化，A 表示适配层接受合格领导资格，N 表示某消息越过外部交付门。

- 若已有适用 X 在 I 前发布：先处理 B/Bc 失配；旧 PreCandidate/Candidate 退回，禁止新竞选入口，然后才处理其他合法输入。不能故意先交付赢票响应再关 G。
- 若 `I < F ≤ X < M < O`：原版不会在调用中观察 X，M 可发生。S 的互斥、外层 SeqCst 读数或事后日志不能改写该事实。[Rust 原子排序范围][ordering]
- F 到 X 本身仍有发布延迟；如果 F 在 I 前、X 尚未出现，包装层也不能声称已经感知所有来源。须记录和约束该窗口，不把 F 改名为获得 S 后的时刻。
- N 已发生的旧竞选请求不能撤回。其迟到响应按当前真实 term/role 处理；新的健康通知不能使旧 Bc 重新匹配。外部对端可能已经提高任期或投过票，隔离不等于抹去这些影响。

## 不改库的受控适配候选及必要条件

1. **前门与调用所有权。** 唯一 RawNode 推进者；每个合法调用前核对当前资格、竞选代次和未处理失效。自动 tick/显式 campaign/TimeoutNow 使用 25/26 的分类适配，保留正常投票、复制及原 term 特例。稳定失效发布不等待 S/Ready；不通过并发修改 `&mut RawNode` 抢占正在执行的调用。
2. **产物先隔离。** 该调用返回前，内核消息、SoftState 和回调结果不得被独立网络/路由/控制任务直接当作可用领导资格消费；返回后再按原竞选代次核验。库诊断日志可能记录内部 Leader，必须与产品的可用领导状态区分，不能篡改日志声称 M 未发生。业务提案、RQ 发起、转移业务、K/G 建立均不得仅凭 raw role 开放。
3. **失配退出。** 调用若产生未经 A 接受的新 Leader，失配后仍按失败竞选处理，不偷套“已有有效 Leader”的宽松规则。正常 step/tick/campaign 已返回且尚未领取下一 Ready、也无旧 Ready 未完成时，可先通过公开方法按当前 term 退回 Follower，再取得反映最终状态的 Ready；这避开等待新 Ready 保存后才退位，但不取消应保存的 HS/日志。有未完成 Ready 时先隔离所有该轮领导产物，完成必要保存、实际安装/应用和 advance 工作，再到合法切点退回。不要非法跳过 Ready、手工清空未稳定日志或回写旧 term/vote。
4. **输出按身份/原因分类。** 丢弃或取消的是本节点失效竞选的尚未交付 Vote/PreVote 请求，以及未经 A 接受的领导者新 Append/Heartbeat/其他领导服务产物；保留给其他候选者的合法投票响应、Follower 复制/快照响应及必要高 term 处理。Ready/LightReady 的保存、提交、实际 apply 义务独立于是否发送某条消息；已提交旧控制事实仍按确定性状态机处理，不从 apply 触发设备动作。新 Leader 自动空条目按正常日志规则保留或被以后合法冲突覆盖，不自行撤销。
5. **再次放行仍需精确版本。** A 与后续输出队列必须绑定同一竞选/执行实例和失效代次，失配只能关闭，不能换绑旧产物。A 后发生故障转入既有 Leader 故障政策；A 前失败的新 Leader 不允许以后台控制服务形式留下。本节不要求已获资格的 Leader 遇任一局部设备故障都退位或清空正常复制输出，故障范围仍按原 LG/分层健康判断。最终网络交付前的失效竞态仍须界定交付点并验证，不能靠一次返回后检查证明 F 之后没有任何 N。

这是应用适配推论，具有具体实现路径而非已验证保证。公开退回路径存在，但异步取日志回调、Ready 保存中断、必要配置应用的后续 Ready、输出队列代次和对外 A/N 同步须完整验证。不能为了省证明删除所有选举消息、暂停健康协议参与或永久拒绝正例。

## 更强内核角色方案的真实成本

如契约要求 X 先于角色接受切点时内核绝不建立新 Candidate/Leader，库内必须在自动 Hup、预选转正式及正式赢票等完整路径提供受约束的中断/接受机制，且所有相关前态变化都需安全处理。一次 `is_eligible()` 调用与之后 role 写入之间仍可发生 X；需要明确同步/条件接受切点，不能只增加一个 bool hook 宣称完成。若要求以更早 F 为边界，还需覆盖来源发布的 F→X 过程。

本报告不证明所有强语义实现不可能，只确认固定版现有外围 API 没有在这些内部位置提供完整机制。更强方案涉及核心适配接口、取消失败语义、投票/任期/日志一致性及升级维护，必须另获授权；不能利用 failpoint、panic 或 unsafe 别名中断当作生产方案。

## 最小可执行验证目标（未执行）

- EO01：X 已发布后自动/显式/TimeoutNow/赢票输入均不能继续旧竞选；其他节点正常投票/复制仍成功。
- EO02：预选赢票和正式赢票内部各处与 F/X 重叠；记录 M，隔离 A/N；退回后 HS、空条目及 committed/apply 一致，不强行回滚。
- EO03：失效发生于 ready()/保存/advance；两类 Ready 和 LightReady 输出均不漏检，合法完成与故障出口都可前进。
- EO04：旧投票响应、旧未交付请求、异步取日志完成、健康 ABA；不能混淆消息类别、复用 Bc 或抹掉已发事实。
- EO05：全部不合格不发布可用控制 Leader；合法新代次合格且有 quorum 时能选举并经 K/G 工作，不靠永久拒绝过验收。
- EO06：分别观察 F、X、I/M/O、A/N；不借模型真值感知未发布故障，也不把未证明的交付窗口标为通过。
