# 标准库许可状态表示：可实施候选与最小修正

日期：2026-09-16；票据 33。核对 Rust 官方 Mutex、Arc、原子文档及固定 Rust 1.85.0 原子源码说明，结合项目 29/31/32 的状态规则。仅研究报告；未写实现、运行模型、添加依赖或访问设备。

## 结论

**稳定 Arc<RoundCell>＋Mutex 保护不可变描述符＋非指针原子 token，可作为首个表示验证基线。** 它能把大对象安全读取与不可逆停发分开，不需要自研裸指针回收。代价是读者可能因短锁忙而拒绝一次派发，以及 Arc/锁竞争和回收成本；这些不是延迟上界保证。

必须补齐四项：描述替换后 CAS 失败的恢复；K 专属与整轮故障的不同关闭操作；覆盖尚未发布新轮次的稳定实例/范围失效依据；读取失败、终止及历史确认的不同结果。整体尚未证明完整 EG/LG、P/W/C 时间语义或物理交付。

## 1. 官方事实

| 事实 | 项目用途与限制 |
| --- | --- |
| Mutex 通过 guard 排他访问，try_lock 不能立即取得锁时失败而不等待；Poisoned 与 WouldBlock 不同。[Mutex API][mutex] | 大描述可在锁内安全克隆 Arc；忙只表示此次尚不能核验，不表示本轮已终止。 |
| Poisoning 是建议性机制，某些 panic/异常不会触发，不能依赖它维持 unsafe 安全。[Mutex poisoning][poison] | 必须检查描述/token 自身不变量；不能以“没有 poison”断言一次发布完整，也不能随意 clear_poison 继续授权。 |
| Arc 共享分配、clone 增加强引用；最后强引用释放会 drop 内部值。Arc 不自动同步 T 的可变内容。[Arc][arc] | 读者在 mutex 内取得强引用后可安全持有不可变描述；其有效性仍需 token 核验。最后释放与析构是实际成本。 |
| 从裸指针增加 Arc 引用要求对象在操作全过程存活。[Arc 原始引用前提][raw] | 不采用 atomic 指针 load 后再补强引用；RoundCell 通过已持有的安全 Arc 传播。 |
| 标准原子在可用目标上 lock-free，但不保证 wait-free；fetch_or 也可能由 CAS 循环实现。[原子能力][atomic] | 无描述锁、无应用分配的撤销不等于无暂停/无重试或 CPU 时间上界；需检查目标的 64 位原子支持。 |
| CAS 成功才条件替换；失败不发生该替换，weak CAS 可伪失败。[固定官方源码][cas] | token 的每次正式阶段发布与 STOP 竞争；不能在失败后用 store 强制写入想要的新状态。 |

## 2. 最小表示及不变量（项目候选）

- RoundCell 在本轮生命周期内地址和身份稳定；任务与失效源提前通过安全所有权拿到 Arc。新对象的分配、注册、证据构造不放进快速撤销路径。
- 描述锁保存 `Arc<不可变描述>`：许可/实例、阶段、发布修订、范围、截止与证书等。token 是整数，不是指针，含阶段、单调发布修订及不可逆 STOP；具体位分配未定。
- 非 STOP 的已发布 token 必须对应匹配修订/阶段的描述。STOP 可先于原因正文生效，读者见 STOP 直接拒绝，不等待大描述更新。
- 只有单一发布者推进正常阶段/修订；撤销者只按权限设置 STOP 或进行精确到期/阶段关闭。任何发布都不清 STOP，计数不能回绕后复用；编码容量不足时受限，不让加法溢出污染阶段位。
- K→G 使用同一阶段状态协调两类权限；若改成多个 RoundCell，需另证联合交接，不能把两个独立 Active 标志当作等价替换。

## 3. 发布事务与 CAS 失败修正

1. 锁外构造完整新描述、P 或证书 C，捕获 expected token 及适用实例/范围失效前提。
2. 持描述锁后重新核验旧描述/token、expected 和当前前提。移出旧 Arc、换入新 Arc，然后以精确 expected 条件发布新 token；CAS 的成功是本次内存阶段发布点，不是设备交付。
3. **若 CAS 因 STOP 或其他前态变化失败：** 最小候选是在仍持锁时恢复旧描述，保留并尊重当前 token，随后释放锁；不得把旧 token 写回，也不得清 STOP。被替换出的新/旧 Arc 均延后到锁外 drop。另一选择是显式保留不可用状态，但不能把描述/token 不匹配当正常可用并继续发布。
4. 成功后解锁再处理旧对象释放。CAS 后、解锁前暂停时，读者 try_lock 失败而拒绝；撤销仍可设置 token.STOP，发布者恢复后不能报告当前仍有执行权。
5. P/W/C 分别走对应发布步骤；P 成功后才取 W，C 绑定原 P 及真实样本。C 迟到只按 31/32 的历史接受语义解释；不能退回“先 now 再一次 CAS 直接续期”。

锁内只保留已准备数据的移动、校验、引用操作和有限发布步骤，不做 I/O、await、用户回调、日志格式化、证据构造或析构。强 CAS 可简化单次失败分类；是否采用它是后续实现细节，不改变失败必须核验的规则。

## 4. 读者最小路径

先检查 STOP/适用稳定故障门；尝试描述锁，WouldBlock 则此次不派发，不自旋等待锁、不凭忙返回 Terminal。取得锁后克隆描述 Arc、读取 token 并核对完整身份/修订/阶段，释放锁。之后读取当前可信时间，按 31/32 的阶段规则判断，再复核原 token 未变、无 STOP 且共同/范围门控仍允许。

读到旧描述但 token 已变，重新核验或保守拒绝；不能拿旧截止无条件停止新状态。Pending 稳态可用旧截止，首次与交接 Pending 拒绝新副作用；K 准备封闭态不允许旧在途确认改绑或增加固定 Dk。证书 C 不等于当前有效，仍检查当前 N/Eg。

多个独立门控的读取不是天然整体快照；初始内存模型可用明确的统一顺序和单向失效来论证，具体 Ordering 组合仍须验证。复核后发生撤销与真正调用之间的窗口没有消失；本路径不跨 CDB/远端调用持锁，不提前把软件检查当作已交付。

## 5. 撤销、阶段和健康 ABA

| 来源 | 最小操作及范围 |
| --- | --- |
| 对整轮确实适用的非时间故障 | 已持有 RoundCell 的失效源 fetch_or STOP；不取描述锁、不分配原因正文、不等 S/Ready。多源只关闭，不相互清位。 |
| 到期观察 | 依据对应描述和当前时间，对 exact token 条件关闭；失败后重新判定，不能因 oldD 已过就无条件 fetch_or 杀死已合法续期。 |
| 旧 K 专属阶段事件 | 条件核对 K/交接 Pending 的身份与阶段；确认已进入有效 G 后不能整轮 STOP。若 Pending 保守关闭赢 C，G 不得恢复。 |
| K 事件揭示共同现实危险 | 不因最初关联 K 而忽略；按当前真实范围关闭。阶段 CAS 失配不是“该风险已不存在”。 |
| 整实例故障发生时新轮次尚未发布 | 仅关闭当前 RoundCell 不够；需稳定实例级 sticky 闩锁或等价失效代次覆盖准备中的对象，并被新发布与所有读者检查。 |
| 可证明局部的资源故障 | 作用于稳定范围/资源代际门控，不误杀无关资源或健康控制成员；不能拿一个全局 STOP 代替所有作用域。 |

**新轮次竞态的最小安全要求：** 实例故障闩锁即使与新 token 发布竞争，也必须使该新对象不可使用；发布返回不得据 token 成功宣称当前有效。该闩锁在其运行实例生命周期内不能被普通健康消息清除；按已有恢复协议建立新上下文，也不意味着旧任务可以改绑新闩锁。

可恢复范围的多来源健康状态不能只用一个可往返布尔值：恢复一个来源不清除其他限制；新的健康证据需当前修订，旧许可依赖的失效历史不能消失。稳定实例闩锁、范围代次与故障原因集合的完整注册/恢复协议仍须具体定义。本报告不把“增加 latch”三个字当作已解决跨对象原子发布。

K 专属条件关闭 CAS 失败时，只能重读并核对当前阶段/身份后决定重试或不再适用，不能为求快速改成整轮 STOP。它不取描述锁，但可能重试；不能把它与共同故障的单次 fetch_or 接口一起宣称为一次 RMW 完成或有等待上界。失效源事先持有 RoundCell 的前提也需要注册协议，尚未证明所有来源都能覆盖新轮次安装窗口。

## 6. 毒化、异常与成本

Poisoned 视为该许可控制视图不能使用，先执行适用安全关闭，再走核对/新上下文；不直接 into_inner 后继续授予权限。即使没有 poison，描述/token 不匹配也拒绝并处理异常；需要覆盖 panic 在替换前、替换后、CAS 前后、恢复及解锁的切点。不得依赖 poison 兜住不安全指针或破坏所有权的操作。

try_lock 忙时拒绝是明确可用性取舍，持锁线程暂停可令所有相关读者暂时拒绝，但不阻塞独立撤销。低频发布也不证明没有竞争；读者自身短暂持锁、引用计数缓存竞争、最后 drop/分配器及调度都需测量。锁外 drop 只是避开描述锁，不保证析构无延迟。快速失效源应保留预持有引用并先闭门，不把 clone/drop、诊断写入或原因分配设为关闭前提。

## 7. 下一步

建议采用该标准库基线进入表示级规格，不为本轮引入原子指针/ArcSwap：安全引用路径已清楚，暂不足以证明更复杂容器收益必须优先。它不是生产性能最优承诺，若以后更换容器须保留同一门控语义和回收证明。

可留作后续比较的是在 mutex 内仅复制一个固定大小派发快照，把完整证据保留于稳定控制对象，以减少每条命令的引用计数/最后释放路径；但其所有字段、证据关联生命周期和复制成本尚未核对，本轮不选择它替换 Arc 描述基线。

优先验证 PR01 描述替换/CAS/STOP 各交错与失败恢复；PR02 读者忙、毒化和暂停；PR03 旧 K 到期与共同故障；PR04 新对象准备遇实例故障；PR05 多来源失效/健康及代次耗尽；PR06 31/32 的 P/W/C 和正常进展。全部未实现/执行；不称无锁结构、wait-free 撤销、完整时效算法或外部 fencing 已证明。
