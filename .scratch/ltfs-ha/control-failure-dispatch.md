# 控制存储故障与运行许可派发边界

关联：[执行授权](issues/18-raft-execution-contract.md) · [存储恢复](control-storage-recovery.md) · [资格同步](raft-rs-binding.md#资格发布失效代次与同步边界) · [时效刷新](authority-refresh.md) · [接口事件](control-interface-events.md)

状态：依用户自动推进授权采用的故障处理与派发验证基线，未实现/执行。沿用 SG/LG/HK/RQ 的安全范围，不选存储引擎、锁/原子类型、时钟 API 或设备隔离设施，不改变 Raft 核心、成员或逐文件提交协议。本节中的状态与事件是规格概念，不代表已有运行接口。

## 故障按证据及影响分类

以下分类不是 errno 映射表。判定须同时带上操作身份、发生阶段、是否可能已有写入、仍可信的恢复依据以及当前运行许可范围；拿到一个错误码或超时通知不能推断所有内容。

| 可证明的情况 | 当前允许与禁止 | 恢复出口 |
| --- | --- | --- |
| 新业务控制提案尚未受理，准入资源不足 | 可拒绝该新提案，不生成外部动作；已提交条目仍按序应用，必要 Raft 投票/复制不能被业务准入规则永久拒绝 | 资源恢复后可受理新的合法请求；此前是否入队未知时不能宣称确定未受理 |
| 本机新快照构建/保存失败，但尚未发布且旧恢复组合、必要协议写入仍可信可用 | 不发布失败对象、不回收旧依据；可继续正常控制及仍有效的 K/G。不把普通快照优化失败直接等同于历史损坏 | 按当前切点重新准备快照；空间继续不足并影响必要保存时重新分类，不能永久忽略积压 |
| 必要保存仍在途，尚无明确失败或历史失信证据 | 当前 Ready 等待真实结果，不伪造 advance，不并发新内核输入；独立门控照常检查期限及现实失效。原 K/G 仅在所有原条件仍有效时继续，不因等待延长期限 | 真实关联完成后按原周期推进；原许可已经终止则不能被完成通知复活 |
| 必要日志/协议保存明确失败，或应用/安装失败使当前控制视图不能可靠使用 | 停止本实例新的 K/G 副作用，限制候选；停止正常内核输入与新的协议发送/重试，不靠 RAM 状态继续投票。不假报保存/应用完成，也不在未完成 Ready 上强行退位 | 进入下述“停止并核对”路径；仅写失败不自动证明旧持久历史损坏，不直接清空或要求成员替换 |
| 必需持久历史确认丢失、损坏、回滚、身份不匹配或无法建立可信恢复组合 | 按 SG 限制该身份的投票、参选、执行；保留数据及诊断，不初始化空旧 voter | 显式受控恢复/替换；健康多数派按原配置和隔离门槛另行接管 |
| 仅文件缓存、某卷追加资格或局部设备故障，控制历史仍可信 | 按原文件/设备范围降级，不自动停止健康投票复制，不把单卷只读升级为全组撤权 | 按相应视图/卷恢复规则；若新事实表明影响更广，再按真实范围收紧 |

“必要保存”包含当前 Ready/LightReady 必需的日志、协议状态及接收快照的配套发布，不包含可安全放弃的未发布本机快照。所谓“旧组合仍可信”须有依据：若新快照失败揭示的是共享底层存储失效，不能仍归类为无害构建失败。日志压缩、发布或回收结果未知且影响当前存储视图时，也不能套用“还没发布所以无害”。

存储等待时间和故障判定期限留空。一次普通未完成操作不会自动被称为“已经失败”；反过来，已收到必要保存失败不能靠原 RQ 期限尚未到来继续执行。超时只表明该观察主体尚未取得确定结果：若仅为当前等待，保留在途；若管理路径决定放弃当前控制实例，则进入停止并核对，不能跳过未知效果后继续下一写周期。

缺少外部隔离证据与控制持久历史损坏分别处理。某个外部事实暂时不可核验，只收紧依赖它的资格；只有损坏了恢复控制状态必需的正文/引用等，才按控制存储恢复失败处理。安全门控可以在记录新事实之前关闭，记录无法持久化不能被报告成“已保存”。

## 必要故障后的停止并核对

[SQLite 运行基线](control-store-sqlite.md)现提供本节的具体存储候选：同库事务、单入口、进程期本地排他及原事务/对象收束。BUSY、I/O 错误、COMMIT 成功丢通知和 RAM 发布失败分别映射，不能用 close_v2/取消 future 当旧写者已退出；不修改这里必要故障先停的政策。
首版采用保守出口：必要保存或实际应用明确失败后，不在原 RawNode 周期中自动循环重试并继续运行；先终止本实例相关运行许可，封闭新的协议输入及发送，核对持久组合后重建控制运行上下文。接受一次可恢复写失败也可能造成控制恢复和设备新轮次等待的代价。此为设计裁定，不是本轮自动重启服务的授权。

1. **本地先停。** 门控关闭不等待撤权记录、磁盘响应或 S 临界区；该节点不能借“补写终止记录”继续旧副作用。正常协议发送任务及传输重试停止新尝试，已交付/未知消息不声称撤回，其他节点按合法协议处理；诊断取证与控制投票区分。
2. **冻结完成关联。** 保留原存储操作、Ready、实例与预期写入关系。迟到成功可能改变可恢复事实，但只进入核对，不直接恢复原 RawNode、原 K/G 或新实例的完成位置。未知写入不能被新写入覆盖来消除。
3. **先排除旧写者。** 重建前须证明旧存储写入口及已提交底层写任务不会再与新入口并发修改同一控制存储；只丢弃回调、取消 future、换进程名称或设置新实例 ID 不构成该证明。具体存储任务终态和排他所有权机制待适配；无法证明时保持受限，不开第二个写者。
4. **按事实恢复。** 能证明持久历史可信、写入口已安全接续且存储能力恢复时，允许按既定启动屏障自动重建并追赶；不能把一次写失败永久等同于 SG。无法建立可信历史时转 SG 显式流程，不从磁带补出投票或删除原目录。
5. **分开恢复权限。** 新控制上下文使用新的执行实例关联，先恢复合法投票/复制，EG 和新 K/G 另行核验；这不要求擅自更换持久 Raft member ID。旧磁带命令与管理动作仍有自己的外部效果和 fencing 要求；本地存储写者停止不证明设备旧执行者已经被隔离。

RAM 状态机应用失败与持久历史损坏也不同：若历史仍可信，可从完整快照和日志重建；同一条目确定性失败不能跳过、吞掉或反复重启假装取得进展。软件/编码兼容问题保留为阻断原因，修正须另属实施任务。已经按协议提交的条件拒绝不是应用异常，不走该故障出口。

此限制作用于出错实例，不主动命令全组停止或修改多数派。故障实例恰是当前设备执行者时，它停止新命令自然造成服务空档；其他节点仍须取得合法领导权、外部隔离及恢复证据，不能因为收到了故障报告就开始写带。

## 运行许可的本地发布与终止

[标准库表示](permit-representation.md)现将描述读取、token 条件发布、失败恢复及独立整轮 STOP 分开；[稳定故障域代次](permit-fault-scopes.md)覆盖故障发生时尚未发布的新轮次。后续健康不更新旧许可绑定，旧 K 阶段事件不误写共同域；该设计不隐藏源端获知到失效原子操作的延迟，RP/FS 均未实现/执行。

[整体许可发布候选](permit-publication.md)将下列规则细化为版本前态条件转换，并明确保留跨截止暂停、回收和快速撤销缺口；不是完整可放行的实现。[存储完成契约](storage-completion-contract.md)同时细化前节的旧写者封闭/收束及迟到结果语义。

采用**独立身份的许可实例、不可逆终止、单一启用/刷新入口**作为逻辑基线。控制授权记录、运行许可及某条命令的交付尝试不合并成一个 ready 布尔值；它们分别回答历史是否允许、当前是否仍有效、动作是否可能已产生效果。

- 每份 K/G 运行许可绑定原集群、节点/执行实例、轮次、受管配置、权限种类/范围及控制位置；准备启用时还带所用资格修订。各次续期只更新同一未终止许可的期限，不给旧对象重置终止状态。
- 单一控制入口负责启用、刷新及 K→G 交接；候选所需状态与证据必须在发布切点仍匹配，不能按准备时的旧健康视图覆盖更新的限制。低频启用/刷新与独立快速停发必须给出可验证的并发顺序。
- 失效入口只能单向关闭明确受影响的许可并保留原因/修订，不负责重新开门。整实例控制失败同时使其 K/G 的共同前提失效；局部卷故障、K 正常阶段退出及旧 K 超时不能直接终止独立有效的新 G。
- 后来健康不能擦掉中间失效。若关闭发生在许可准备与发布之间，发布必须失败或得到已终止对象；不得出现“旧失效只关了旧指针，新许可随后无条件发布”的空窗。参选失效代次 B 的职责仍是 EG，不用它替代所有 K/G 及资源故障域。
- 热路径只能读取/核验本地许可和资源状态，不逐 CDB 获取控制临界区 S、等待存储或发起多数派确认。不得把可能长期阻塞的 CDB 或远程管理调用放进启用/关闭临界区；具体原子操作、内存可见性、对象生命周期和性能预算仍未选择或验证。

这确定并发实现必须满足的结果，而不是声称单独一个原子布尔值或上述单入口已解决竞态。若实现无法同时证明快速停发、当前前态发布及不跨慢调用的要求，保留缺口，不将失效判据改成“等到取得锁才算获知”。

## 每条动作的派发切点

| 动作所处边界 | 必须处理的条件 | 失效时的结果 |
| --- | --- | --- |
| 请求进入应用或批次队列 | 关联任务、范围及准备依据，入队不授予持续执行权 | 不安排尚未发出的后续动作，不自动改绑新 G |
| 执行者取出单条动作 | 核对实际目标身份/资源代际、K/G 种类及范围、当前许可/期限、恢复阶段 | 不满足则不继续；K 不能当作正常数据/读带许可 |
| 最后一处可控制的派发入口 | 再检查许可当前未终止、期限尚有效、已知风险和设备/卷前提；同一动作独占地进入一次尝试，重复回调不能生成第二次 | 队列内或重试前尚可控制的动作停发；不以检查曾通过为理由续发 |
| 已进入底层调用/外部通道，受理状态不明 | 记录实际交付尝试及适用边界，区分确定未受理、受理和未知 | 未知不等于取消或从未执行；不盲重发、退款或丢弃可能效果 |
| 返回与下一条动作 | 结果归原动作；下一条重新走全部派发门控 | 迟到成功不恢复许可，不补索引结束标记/同步或机械手收尾 |

计时器尚未运行不提供宽限：派发入口和刷新入口都必须读取当前时间检查期限，无法信任时钟连续性时受限。每次管理适配器的后续重试也须检查当时 K；有 K 仍不证明未知外部动作可安全重试。设备命令不因存储/网络重试能力而自动获得重放许可。

**实际边界不能偷换。** 上层入队、软件判定允许、进入系统调用、驱动受理、设备执行是不同事件。首版仍须由具体适配定义可观测的最后派发点；未找到该点前不能把一个软件准备标记称为“命令已发出”。最后检查后线程暂停再交付、系统/服务端已接受但尚未执行的动作，仍须靠外部 fencing 和未决效果收束约束。不能锁住慢调用来伪造撤销即时性，也不能靠提前记为“已发”掩盖违背 LG 的派发。

## 迟到结果不丢事实，也不续权

失效后的结果只更新原操作的已知事实及其可核验结果，不直接改变新实例的许可、卷视图或额度。新流程若需要采用它，必须核对原动作与当前安全判断的关系；原关联过期不意味着危险事实可以丢弃。存储不可写时可以安全观察，但 RAM 中的观察不能报作已可靠复制；恢复仍从持久意图及现实效果核验，不靠丢失的本地诊断证明动作没发生。

已经完整满足归档持久化契约的历史结果，不因 K/G 终止自动撤销；能否通知应用取决于完整原关联和提交证据，而非“旧回调一概丢弃”。单条 WRITE 或结果未知不升级成整批归档成功；本轮不引入回执或跨节点请求去重。

## 故障与进展场景

[故障源接入协议](fault-source-integration.md)把本节故障分类映射到稳定 gate 和来源职责，并以连续 H 防止后到事件被后续健康覆盖。必要安全关联不可恢复与普通诊断日志丢失分开；失效先于记录，不等原因保存才停发。SI 场景补充来源交接、事件空洞与记录预算失败，均未实现/执行。

FD01—FD08 均未实现/执行，关联 SR06、QS、RQ、LG、HK 和 DV06。

| 用例 | 必须命中的交错及安全断言 | 进展正例 |
| --- | --- | --- |
| FD01：等待与明确失败 | 同一 Ready 分别安排慢成功、明确失败、结果未知；不假 advance，失败不能等 RQ 到期才停发 | 原许可未失效的正常等待可继续；可信故障恢复可重新参与控制 |
| FD02：快照优化与必要保存 | 本机未发布快照构建失败和接收快照发布失败分别注入；不混用故障范围，不提前回收 | 旧组合及必要写入仍可靠时正常服务，不因普通优化失败永久停服 |
| FD03：迟到写者与恢复 | 原写任务延迟、回调丢失、恢复请求并存；旧写者未收束不开新写者，迟到成功不复活旧周期 | 写者排他及历史可信后可重建，正常重启不被一概要求换成员 |
| FD04：准备启用后失效再健康 | 在许可准备/发布/终止之间切换资格，失效不能被健康覆盖，旧许可不可复活 | 当前完整前态上准备的新轮次可成功启用 |
| FD05：刷新与到期/关闭 | 到期回调延迟、safe 结果迟到、失败关闭与刷新竞争；先判原期限，刷新不覆盖终止 | 期限内有效确认仍可续期，不强制逐 CDB 同步 |
| FD06：多级队列与最后派发 | 数据/索引/读定位/机械手/管理重试各入口；检查后暂停再交付单列外部隔离假设 | 资格有效时单条动作能推进，多驱动不被控制慢操作全局锁住 |
| FD07：K→G 与局部故障 | 交接前故障、交接后旧 K 定时事件、单卷失败、整实例存储失败分别调度；精确限制范围 | 正常交接及无关卷继续，整实例确实失效则全部相关许可停发 |
| FD08：迟到事实与结果确认 | 原索引 WRITE、最终屏障、旧隔离结果及保存失败交错；不续发、不丢未知、不猜成功 | 完整原提交证据可核验，健康多数派可在其全部条件成立后接管 |

观察须覆盖故障被获知、门控实际关闭、许可准备/发布、每个派发尝试与实际受理证据；源端已知但发布尚未完成的窗口不能从测量中删除。没有全部入口的观察不能证明“无新命令”，永远拒绝也不算进展通过。

## 仍需落定
