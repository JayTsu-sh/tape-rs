# 卷提交后的本地状态发布协议

关联：[D03 原裁定](issues/04-durability.md#已裁定发布准备与同批一致转换) · [提交状态机](commit-state-machine.md) · [容量账本](capacity-reservations.md) · [性能契约](performance-acceptance.md)

状态：依自动接受授权采用的本地转换设计；不是现有实现或测试结果。仅收敛 S2 准备到 S5/S6 的状态一致性，不定义文件操作语义、设备持久化证明、会话续期时钟或 HA 许可算法。磁带仍为已提交状态权威，不新增本地持久事务、回执或节点间文件状态共识。

## 每卷一个状态更新次序

同一运行实例内，每卷准入、变更登记、额度/引用转换、取消关闭、校准发布及提交发布，通过同一逻辑顺序更新该卷运行状态。后台工作只产生携带原关联的结果，不能直接修改其中部分字段。这是每卷状态串行化要求，不是指定线程、actor 库或全库锁；不同驱动器仍可并行。

慢设备调用、索引编码、缓存持久化、网络通知和大型构建不得占住状态更新边界。HA 快速停发具有独立路径，不能等待这个顺序器排队或完成提交；一个本地状态事件也不是逐 CDB 的执行许可。最终设备派发继续核验 18 的独立门控。

状态发布采用受生命周期保护的不可变根：读者得到某个完整版本，不能分别取得提交代、目录与能力标志后自行拼接。根包含或关联已提交视图、未提交变更、当前账本/引用和本地服务状态。只读者不由此取得长期设备权限，也不在本节决定未提交内容的用户可见性。

## 冻结对象与当前对象分开

每个本地批次使用不可复用身份：运行实例、卷 UUID、恢复上下文、本地批次号及精确基线。磁带 generation 不是唯一的回调去重键。该关联仅用于本次运行，重启或接管不从它恢复旧上传。

S2 保留不可变提交描述，包含：

- 已核验的快照及必要依赖、待发布已提交视图、确切文件版本/变更范围；不能只存“清除此文件 dirty”。
- 当前等待者要求的覆盖依据；请求后来新增的需求不被旧描述顺带满足。
- 本批设备操作、额度与快照引用的身份，以及已有计账切点；存转换依据，不存将来整份账本的替换镜像。
- 编码、发布和结果关联的资源预算；所有 S4 判断所需证据独立于可重建缓存更新。

首版每卷最多一个已进入索引写入、等待 S4/S5 收束的批次。索引写入期间可按既有策略有界接收下一批，但不启动另一份冲突索引，也不让后批发布越过前批。批次失败后不是直接丢掉记录再重试；是否可继续设备写入仍由异常尾部恢复决定。

变更与引用有稳定身份，部分文件按实际冻结范围记录覆盖。不能用一个全局数字水位清除包含空洞、跨对象依赖或未完成文件的变化；只有证明某子范围连续且全部覆盖时才可压缩表示。完整文件 size 触发计量继续按既定就绪/未提交规则，不因一次前缀 fsync 就将整文件减掉。

## 发布的条件转换

| 步骤 | 转换及拒绝条件 |
| --- | --- |
| CP1：准备 | 在 S2 构造本批已提交视图候选、覆盖描述及发布资源预算；失败不开始本批索引，不重写此前已执行数据 |
| CP2：记录独立持久化结果 | 只有完整 S4 证据才能将精确批次记为持久化已证实；缓存成功、普通写成功、单个回调均不能替代 S4 |
| CP3：读取当前状态 | 核对卷、运行/恢复上下文、基线与批次状态；旧实例结果不能转换新实例状态。后续变更、取消或较新校准不是丢弃它们的理由 |
| CP4：按身份计算差量 | 已提交视图取本批冻结候选；从当前未提交集合仅移除已覆盖部分；按当前引用及基线对齐额度，保留当前取消/关闭状态、后续变化和保护预算 |
| CP5：一致发布 | 构建完备新根后在卷状态顺序中替换当前根；转换前态若变化，回到 CP3 重新计算本地差量，不能重发磁带命令或把旧镜像强行写回 |
| CP6：通知与回收 | 发布后通知精确覆盖者；网络失败只改变通知结果。延后回收已无引用的旧根和准备对象；重复事件不重复转换或释放 |

CP2 表示历史持久化事实，不要求已失效 G 重新生效才能保留这份事实。当前许可失效时仍关闭新设备派发；有完整关联的历史成功可按既有政策通知，不能据此开放服务或新任务。执行/恢复上下文已经替换则不能更新新上下文的卷根，旧结果仅进入隔离的事实处理路径。

CP4 不覆盖整个当前状态。例如校准已将某笔消耗纳入新基线，提交事件只按该消耗身份解除相应快照引用，不再从新基线扣一次；提交本身也不退还物理占用。取消已禁止会话继续写入，发布只补充该旧请求的事实和安全释放，不恢复接收资格。

time 触发从发布后仍未覆盖的变更中保留最早登记时刻，不改成发布完成时间。size 触发只更新被确切覆盖的完整文件计量；IP 维护、Full 检查点债务与会话期限各自保留，不由成功通知统一清零。

## 有界资源与失败出口

优先结构共享和本批差量，不要求每批复制全目录。S2 为本批可预见发布工作预留本地预算，后续接收和状态增量也必须分别有界；不能在旧准备预算上无限挂接新任务。具体结构、批次上限和数值仍由实现/测量确定，不能据“预留过”证明任何分配都不会失败。

若 CP3—CP5 不能形成可信新根，不部分应用后继续服务：保持旧已提交视图对象完整，但将受影响卷的正常视图服务及新修改置为不可用，按磁带证据重建。旧根不因尚完整就可以冒充最新视图。须有预备的失效标记路径，至少不依赖此次失败的分配；具体同步机制仍待验证。

S4 证据与覆盖关联仍可信时，即使 CP5 失败也可按原政策返回该请求的持久化成功及服务降级；证据丢失则结果未定。进程状态可能损坏时按更大故障域处理，不要求一个不可信进程继续回复。没有完成原子根替换的异常不得被捕获后当正常成功继续执行。

旧根、快照、暂存和额度的回收各有不同条件。读者仍引用旧根时不能释放它；旧根引用解除也不意味着磁带空间释放。回收不得把析构/慢清理放入设备快速撤销路径。过载处理采用有界接收和拒绝/背压，不承诺零成本或无限队列下进展。

## 验证目标

下列 PC01—PC06 是设计用例，均未实现/执行；与 PV/C/K 既有场景交叉核对，不取代它们。

| 场景 | 必须成立 |
| --- | --- |
| PC01：冻结 X 后接收同文件 Y | 仅 X 发布及确认；Y 的范围、最早时间、引用及未提交状态保留 |
| PC02：冻结后取消并发生新校准 | 取消不回滚；使用当前基线及引用计算，不双扣、不多退，也不把当前账本还原到 S2 |
| PC03：重复/乱序提交结果与通知失败 | 同批只转换一次；未来批次不能越过未收束前批；通知重试不重写磁带 |
| PC04：S4 成立、根构造失败 | 不暴露半发布视图；旧目录不冒充最新；独立覆盖证据完整时仍可通知持久化事实 |
| PC05：许可失效、换卷/换实例与迟到结果 | 停发不等待卷顺序器；旧结果不改新根、不复活权限，可信历史事实不被抹掉 |
| PC06：读者持旧根及高压正常提交 | 无悬空/混代读取；有界接收及延后回收；资源足够、无故障分支能够完成发布而非永久拒绝 |

本设计给出 D03 的本地更新次序与差量转换方向。根表示/生命周期、预备失效路径和成本上界仍需具体实现验证；会话有效活动的时间切点、容量物理模型、D01/D02 与 18 的许可/外部效果协议不由本节解决。04 保持 claimed，文件契约与模块划分依赖不提前解除。
