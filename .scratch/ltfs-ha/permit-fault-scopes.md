# 稳定故障域代次与跨轮许可绑定

关联：[状态表示](permit-representation.md) · [资格 Q/V/B](raft-rs-binding.md#资格发布失效代次与同步边界) · [失效与派发](control-failure-dispatch.md) · [执行授权](issues/18-raft-execution-contract.md)

状态：依自动接受授权推进的项目协议候选，不是 Rust 标准库功能或已运行验证。专门解决故障只关闭当前 RoundCell、却漏掉准备中新轮次的问题；不替代 Raft 参选代次 B、外部隔离或完整风险事实。

## 固定故障入口不跟着活动指针移动

在运行上下文建立时，先为实际需要的故障域建立稳定 ScopeGate，相关故障源持有其安全引用，然后才能在该故障域下准备任何运行许可。故障源不需先找到“当前活动 RoundCell”，也不遍历所有旧/新许可后才算失效。

ScopeGate 包含单调的原子 `failure_epoch` 和受保护的资格审查记录 `Reviewed(epoch, qualification, context, evidence)`。初始资格为未知；没有完整合格审查就不能授权。原子 epoch 只表达依赖中断，详细原因、未决效果和控制历史仍在各自对象中保存。

同一运行上下文内不更换 gate 身份，不把 epoch 归零。旧任务、旧健康回调和旧许可始终绑定旧 gate/epoch；新执行上下文的建立仍须遵守 TG/SG 的恢复与旧效果核验，不以分配新 gate 绕过真实故障。

## 按权限的实际前提划分故障域

| 故障域 | 依赖它的权限 | 边界 |
| --- | --- | --- |
| 执行实例共同前提 | 该实例全部 K/G | 领导上下文、必要控制状态等共同条件失效；不自动更改其他健康 Raft 成员 |
| 受管组协调前提 | 依赖该条件的 K，及尚须有效 K 的交接前态 | 不把纯 K 旧阶段计时事件传播成 G 的共同故障 |
| 受管组设备执行前提 | G、首次/交接中的 G 候选 | 隔离及旧效果安全等；仅 G 不满足时不停止仍合法的 K 协调 |
| 卷/资源能力 | 对应卷的读或写操作 | 可证明局部的限制不误伤无关卷；范围不明按既有规则扩大核验 |

具体 gate 清单必须来自该许可/动作的全部必要前提，不能由调用者自选较少的 gate。配置、资源身份或依赖集合改变时，旧集合先失效/受限，再核验新集合；不能仅修改一个动态列表，让旧描述漏查新增限制。新故障源未接入、来源退出但责任未交接或范围覆盖未知时，该域不标合格。

绑定分层：RoundCell 描述关联 K/G 本身必需的实例/组级 gate；一次文件或设备任务另外持有对应卷/资源能力代际的绑定，派发核验两层。不能把所有卷的 gate 合入一个共同 G 的失效集合，否则单卷失效会错误撤销整组许可。局部恢复可在仍有效 G 下建立经核验的新资源能力/视图代际；旧资源绑定不修改，旧未知动作不因此自动重放。

K→G 的成功前态必须包含有效 K 所依赖的域；已经合法进入 G 后不再依赖纯 K 阶段条件，但仍依赖所有 G 共同安全条件。旧 K 结果若揭示 G 的真实危险，应更新相应共同/G gate，不因最初事件关联 K 而忽略。

## 失效先前进代次，健康不能擦除

已识别为适用的故障首先对相应 gate 原子推进 failure_epoch；推进生效后，所有绑定旧 epoch 的许可都失去后续核验依据，不等描述锁、S、Ready、磁盘或原因正文分配。该作用覆盖已经发布、准备中和仍被旧任务引用的 cell。详细故障与处理义务随后进入现有控制/恢复流程。源端获知到原子推进仍有调度/竞争窗口，本方案不把它改名或省略，也不承诺源端获知瞬间全部处理已完成。

代次使用检查溢出的条件原子更新，最大值保留为永久受限哨兵，任何读者或新绑定均拒绝它；不回绕、不用饱和后的重复最大值继续发新许可。到哨兵后只能通过合法的新运行上下文恢复，不在原 gate 清零。CAS 竞争可能重试，不宣称 wait-free、固定 CPU 时间上界或物理瞬时停发；验证仍记录源端获知到原子失效的实际窗口。

正常健康观察不能回退 failure_epoch，也不能直接清除旧许可 STOP。只有处理完对应故障、取得当前必要证据后，才可发布与该精确 epoch 配套的合格 Reviewed；这允许新的合法接管许可或局部资源能力绑定新 epoch，但旧绑定永远不重新匹配。只有 K/G 自身必要条件中断才要求相应许可换轮，局部资源恢复不自动触发整组接管。

**不能越过未处理事件。** 原子代次已前进而详细原因未送达时，旧 Reviewed.epoch 不匹配，所以新许可保持受限。不能把“读到当前 epoch”和“看到旧健康值”拼成新的 Reviewed。事件丢失、来源状态无法核对、证据覆盖有洞或记录预算不足时，不将该 epoch 标为已审查合格；继续受限并走原故障核对，不能丢事件后凭最后一次健康恢复。

## 审查与新轮次的绑定次序

1. 审查者读取目标 gate/实例/配置和起始 epoch e，在此上下文核对全部来源、未决效果及恢复证据。审查前的健康结果不能重贴当前 e；一次来源健康也不代表整个域合格。
2. 准备 Reviewed(e, 合格, …)，发布时再次检查 epoch 仍为 e，来源集合和配置未变、必要中断处理无空洞。若中间失效，丢弃这份旧审查结果；发布后立刻发生失效也会使 Reviewed 与原子 epoch 失配。
3. 新轮次取得受保护的合格 Reviewed 及 gate 强引用，绑定精确身份/e；再次读取 failure_epoch，匹配才继续 P/W/C 准备。尚无活动许可不影响这个检查，初始化未知也不能作为无故障。
4. 描述不可变地记录所需 gate/epoch 集合。P、C 核验许可本身的依赖，派发读者同时核验许可及该任务资源能力的依赖，不仅在创建时核验一次。失效与发布 CAS 竞争时，即使 token CAS 成功，旧 epoch 也使相应对象不可使用；不得因 CAS 返回成功报告“当前可执行”。局部能力重新绑定也须遵守同样的审查与当前 epoch 检查，但不是另建 G。

跨 gate 的正向审查不是天然原子快照。初始候选采用一致的原子次序，读者在当前时间采样前后复核完整绑定集合及 RoundCell token；只允许同一描述全部依赖均匹配。单调代次与不复用身份用于排除健康 ABA，不以一组互不关联的 true 布尔值替代。具体弱内存和时钟顺序仍须证明。

对某份旧许可/能力而言，其必要 gate 的 epoch 不匹配本身就是该绑定不可逆失效，不等异步把每个旧 cell 都写上 STOP 才限制对应动作。K/G 本身失效后按 TG/CG 新建接管轮次；仅卷/资源能力失效时，按既有恢复政策在仍有效 G 下建立新能力/视图代际，不强制全组换轮、不影响无关卷。两者都不能原地更新旧绑定 epoch。

## 与版本到期和回收分开

到期检查针对原许可/描述/token，不因为读到旧 D 就推进一个共享故障域。否则一次旧到期事件可能误杀合法续期或新 G。共享域代次只用于真实影响该域的前提中断、配置/依赖变化等；普通阶段退出按 AH，局部资源按其实际范围。

ScopeGate 生命周期由运行上下文、已注册来源和任务强引用共同保护。旧来源退出前须交接监测责任，不能只因为 Arc 引用仍在就声称故障监测仍覆盖；也不能释放来源后继续保留合格 Reviewed。原因/未决效果记录按既有控制保留规则，epoch 不是可以丢弃所有历史的水位。

该方案的取舍是故障域内一次中断使依赖它的旧绑定永久失效，健康恢复需新建对应层级的许可/能力；与既有过期/失效不复活及局部降级方向一致。派发多了有界本地 epoch 核验，不增加逐文件 Raft、设备探测或持久诊断日志；依赖集合大小和真实开销按 06 测量，不承诺零成本。

## 验证目标与剩余责任

以下 FS01—FS06 均未实现/执行。

| 场景 | 必须核对 |
| --- | --- |
| FS01：新 cell 准备或发布期间发生故障 | 原子 epoch 变化阻止新旧绑定使用，不依赖找到当前活动指针 |
| FS02：故障已前进 epoch，原因/审查处理延迟 | 不用旧健康值绑定新 epoch；缺事件不假报已处理 |
| FS03：合格→失效→合格，旧回调/描述迟到 | 旧绑定不复活；新合法轮次在完整重新审查后可工作 |
| FS04：多源健康交错及不同故障范围 | 一源恢复不清另一源；纯 K/单卷事件不误杀无关 G/卷，共同风险不漏停 |
| FS05：来源/依赖集合改变与代次耗尽 | 覆盖未明保持未知，旧集合失效；最大哨兵不授权、不回绕 |
| FS06：多 gate 读者暂停、正常负载与新上下文 | 全部依赖和 token/时间一致核验；正常正例能完成，新上下文不继承旧权限或漏查旧外部效果 |

本节形成跨轮绑定候选，不宣称故障探测、事实留存、各源接入或弱内存组合已经实现。仍需将实际来源逐项映射到 gate，明确每项审查证据、监测责任交接和记录预算不足出口；这些是后续集成清单，不能省略后声称完整快速停发已覆盖。18 保持 claimed，EG 重叠、时钟、存储及外部隔离等其他缺口不变。

[故障源接入协议](fault-source-integration.md)现给出来源职责表、先失效后记录、连续已处理前沿 H、完整性失信及来源交接的具体逻辑方向。Reviewed 必须同时满足 H 无洞覆盖和当前 epoch/完整健康证据，不能只比较一个数字；SI01—SI06 未执行，真实适配与源端时效仍需验证。
