# 容量账本与预留生命周期草案

关联：[提交契约](issues/04-durability.md) · [卷提交状态机](commit-state-machine.md) · [性能验收](performance-acceptance.md)

状态：准入粒度、会话保活/竞争约束、容量校准对齐及索引预算两层检查原则已获用户接受；具体记账、计时和并发实现仍未完成，不是已验证的设备容量保证。既有性能、收尾保护、取消安全释放与主备范围不变；本稿不选择容量单位换算、安全余量、滚动额度大小、过期时间或 Rust 同步原语。

## 预算的含义

容量账本绑定卷身份、当前所有权会话及可信容量基线。它记录当前可分配的保守预算和已有写入义务，不是上传回执、节点间复制日志或磁带数据的另一权威；预留成功不代表数据已持久化，也不保证介质以后不会发生异常。

DP 与 IP 分别核算，SSD/内存缓冲另算，任何一项的空闲不能抵偿另一项不足。文件逻辑大小不能未经校验直接当成物理磁带消耗，压缩收益也不能作为必然可用的额外空间；实际计量、格式开销及误差模型仍须验证。

## 已裁定的准入粒度

用户回复“接受，继续推进地图”，确认以下两种准入方式及预算不足时的边界，[裁定记录](issues/04-durability.md#已裁定已知与未知大小的容量预留)限定接受范围，不代表下方记账算法已经验证。

- **大小已知的原生上传：** 在开始写入该文件前，按完整声明大小对应的保守数据成本及可估的元数据/收尾预算增长一次准入。卷内检查与预留须为一个一致的操作，后续在已授予范围内流式写带，不反复申请整文件额度。这里预留的是账本额度，不要求先把整文件缓存到 SSD，也不是提前在磁带上占位写入。
- **大小未知的流式上传：** 先取得一段有界额度，在超出该额度之前申请补充。允许在现有额度耗尽前合并申请，但新数据不能在无有效额度时被确认为已接收，队列和传输缓冲也不能无界增长；不逐个小 write 查询设备。
- **超出声明大小：** 超出的部分必须重新获准，不能静默挪用其他任务或收尾预算。声明大小如何在 API 表达、输入少于声明大小如何判定完整上传，由文件契约继续细化，不把“预留了足够空间”当成文件已经完整。
- **补充额度失败：** 可信预算确定不足时拒绝本次补充；仅容量校准允许既有的有界等待。原先已获额度内的工作是否继续仍受设备状态与收尾保护约束。无法完整上传时沿用保留可靠提交前缀的政策，不自动跨卷续传、不误报整文件成功。

取舍：已知大小预留整文件预算，可以减少并发任务在中途争抢同一份剩余容量，但会使其他任务更早被拒绝；未知大小保留流式能力，但不能承诺一定写完整。正常新增索引、周期维护及预算偏差仍须持续核算，整文件数据预留不是对未来所有维护成本或最终成功的无条件保证。业务接收的具体边界仍需绑定后续接口契约。

## 账本不变量草案

对每个分区 p，在同一计量口径和一致状态下，用下式表达准入约束：

`可分配预算[p] = 基线预算[p] - 基线后已记账消耗[p] - 未消耗预留[p] - 必要索引与收尾保护[p]`

这是记账关系，不是已有的空间估算公式。各项必须不重叠：

| 项目 | 计入范围 | 不允许的做法 |
| --- | --- | --- |
| 基线预算 | 经恢复/校准可用于当前准入模型的保守分区预算，带明确的记账切点 | 直接把一个来源/时刻不明的剩余容量数字覆盖当前账本 |
| 基线后已记账消耗 | 在基线切点之后已发出或已执行的操作所占的保守消耗；尚不能精确确定时保留受约束的占用 | 普通 WRITE 返回后因为尚未提交 index 就把空间视为空闲；校准已包含的同一消耗再扣一次 |
| 未消耗预留 | 已授予但尚未转换为消耗的数据及其他明确任务义务，包括已接收但尚未发出的数据 | 只算设备队列而遗漏 SSD/内存中已接收工作；取消后未检查引用就全额退还 |
| 必要索引与收尾保护 | 当前/必要后续索引和正常收尾的保守预算，包含对应文件/extent/属性增长；DP/IP 各自保护 | 每个任务各扣一份同一共享 Full，或反过来把下一份必要 Full 完全漏算 |

请求引起的数据额度变化与索引/收尾增长一起检查、一起生效；DP 成功而 IP 预算失败不能留下部分准入。共享索引成本的合并与上界估计需要证明，不以一次完整 XML 序列化作为每文件快速路径。

账面不足不能靠整数溢出、负数钳成零后继续准入或忽略误差掩盖。校准发现不足时，先关闭新增额度授予并按既有安全政策处理，不假装可以兑现全部未执行义务。

## 额度转换与释放

| 事件 | 需要保持的记账行为 |
| --- | --- |
| 授予额度 | 同卷内原子检查并增加未消耗预留，关联有效会话；准入退出或取消后不得再次激活 |
| 接收数据、排队 | 在已授予额度内标出待执行范围，不再把相同数据另扣一份整文件预留；缓冲预算独立检查 |
| 发出设备操作 | 对对应范围，将未消耗预留转换为基线后记账消耗，转换不能出现可再次分配的空档；不同时按全额预留和全额消耗重复扣款 |
| 执行结果明确 | 按已验证的结果模型核对保守记账；只有能证明可释放的差额才返回可分配预算，不凭单一返回值猜测物理占用 |
| 执行结果不明 | 保留保守占用并进入恢复门控，不释放并再次分配，不重发可能已执行的操作 |
| 索引写入/提交成功 | 索引本身按实际模型记账；文件持久化成功不退还已写空间。消耗某份保护预算后，继续增长前须确保剩余必要维护/收尾义务仍有预算 |
| 取消或正常结束 | 仅释放确定未消耗且已无在途、固定快照、其他任务或收尾引用的额度；重复完成/取消不重复释放 |
| 缓存清理 | 只释放对应 SSD/内存资源；不得据此增加磁带可分配预算 |

这张表描述一致性要求，不要求每个状态转换同步写节点日志或等待 B。自动会话过期、准入响应丢失后的预留处理见下节草案，不能将网络断连或计时到期直接等同于可安全释放。

[D03 每卷差量发布](commit-publication.md)进一步固定本地更新方向：提交结果、准入、取消及校准在同卷逻辑次序中合并，以发布时当前基线和引用计算；S2 只保留本批转换依据，不保存一份稍后覆盖当前账本的旧镜像。根发布失败保持受限，不能部分退还后继续准入。PC02/PC04 尚未执行，物理消耗模型和会话时间切点不由该本地次序自动证明。

## 上传会话保活与到期回收

用户在澄清“提交是否自动续期”后回复“接受，继续推进地图”，[裁定记录](issues/04-durability.md#已裁定会话活动续期与过期不复活)确认以下原则，具体计时与回收实现仍待细化。

原生上传会话采用有限、可配置且向调用方明确的保活期限。到期是服务端停止接受该会话后续工作的依据，不是证明此前请求未执行或额度尚未消耗的证据。该期限不是设备所有权租约，不参与仲裁，也不能替代 fencing。

**已接受的续期边界：** 未到期会话收到有效客户端写入、保活或合法提交请求时，可以刷新保活期限；已受理提交正在等待落带，不因没有新上传数据而判作客户端空闲过期。周期性 index 提交、其他文件的合批提交或旧在途提交完成都不能单独续期；会话已经过期时，提交完成保留真实结果，但不重新授予写入权限。

**有效活动与计时范围（草案）。** 等待客户端继续提供数据或结束上传的阶段，需要有效的数据活动或明确会话保活；具体保活接口与期限协商仍待文件契约定义。非法请求、无关查询及其他会话活动不延长该会话期限；客户端无需靠创建空文件、补零字节或触发磁带 sync 保活。

服务端主动背压、已收到完整上传后等待提交、设备执行和恢复处理，不应仅因没有新上传字节就被判作客户端放弃。需要保活的等待路径应允许控制请求独立于满数据队列处理；服务端无法可靠接收或评估保活时，应报告控制/资源异常，不猜测会话已安全退出。判定所需的时间源、暂停/续计边界仍须实现验证。

| 情形 | 建议处理 |
| --- | --- |
| 连接短暂中断或单次调用等待超时 | 不立即认定整个会话取消，不立即释放预留；尚存会话是否仍有效以服务端状态为准 |
| 等待客户端继续上传且有效保活期限届满 | 将会话不可继续提交工作的状态与新请求准入检查一致地更新；拒绝迟到的写入、补充额度或保活，不在后台重新激活旧任务 |
| 会话到期，尚有未发出的数据 | 停止该会话尚未进入执行/冻结快照的后续工作；按取消政策检查缓存与预留引用，不能把这些数据计为归档成功 |
| 会话到期，命令在途或快照已冻结 | 保持相应额度占用，不强行中断命令、不改写快照；必要安全处理结束后才重新评估可释放范围 |
| 会话到期与可靠提交完成竞争 | 磁带事实按实际提交结果保留；到期不撤销已提交内容，也不把“过期”解释为上传肯定没有完成 |
| 会话到期，执行结果或引用关系不明 | 保留相关保守占用并进入核验，不因超时自动释放或推算重传偏移 |
| 准入响应丢失，客户端未能继续使用会话 | 建议由同一到期机制处理服务端可能遗留的预留，不要求新增持久化请求回执；客户端仍不能仅凭响应超时断言准入未执行 |

**回收顺序（草案）。** 禁止旧会话继续提交新工作 → 排除新的执行引用 → 核对在途/快照/收尾依赖 → 释放已证明未消耗且不再被引用的额度。回收可分阶段进行：安全的未消耗部分不必等待无关任务完成，证据不足的部分不提前释放；重复到期、取消和完成事件不得重复退还。

有限会话期限不等于所有额度在该时刻必然释放，也不证明磁带已停止移动。已写介质空间、可靠提交的部分文件和卷级必要收尾预算不因到期被删除或回收；共享依赖仍存在时不能释放给其他任务。自动文件删除、介质修复和未知暂存数据清理不由本政策授权。

未到期会话的同主重连方式、身份校验和字节偏移核验留给文件契约；不默认透明断点续传。已到期会话不得由迟到请求复活，应用需核验现有文件状态并按安全重试规则重新申请。A/B 接管不继承旧会话执行权限，不新增会话同步或跨节点自动续接；FUSE 调用中断也不直接套用原生整个上传到期规则。

有效保活可以延长会话，因此该机制只处理失联/空闲遗留，不保证解决持续保活却占用额度的公平性问题。最大持有期限、用户配额、抢占或强制回收活跃上传均未选定，不借本次设计新增这些政策。

**新增候选验证。** 覆盖断连但未到期、准入响应丢失、背压期间有效保活、完整上传等待慢提交、迟到请求与到期竞争、到期与提交成功竞争、共享快照引用以及重复回收。检查迟到请求不能再执行、在途额度不被提前重分配、服务端等待不被当作客户端放弃、已提交状态不被撤销。具体期限与允许检测误差留空，本轮不执行测试或清理任何数据。

## 会话竞争处理草案

本节将已接受的边界展开为实现约束和可控交错用例，不新增公开会话 API、持久回执或设备命令。会话接收权限与已有工作的完成结果分开维护：前者已关闭，后者仍可能正常完成；任何回调都不能仅因操作成功就重新开放接收权限。

用户随后回复“接受，继续推进地图”，接受本节竞争约束及计时分离原则，见[裁定记录](issues/04-durability.md#已裁定会话竞争约束与计时分离)。下表继续作为待实现的验证要求，不表示已选定并发机制或已执行测试。

| 并发事件 | 已接受的一致性约束 | 候选验证 |
| --- | --- | --- |
| 有效活动与旧到期检查相遇 | 续期必须验证会话当时仍有效，并一致更新活动状态/期限；定时检查执行时重查当前状态，不能凭早先读取的截止点让已有效续期的会话过期 | C01：先接受续期，再运行携带旧截止点的检查，不能误关会话 |
| 到期关闭先于迟到活动 | 关闭新工作入口与活动受理必须有唯一、可判定的先后关系；关闭完成后，迟到写入、保活或新提交请求不能续期或进入执行 | C02：先使会话到期，再交付迟到活动，接收权限保持关闭 |
| 新写入与预留回收相遇 | 校验会话/额度、建立执行引用与回收检查保持一致；不能先释放额度，随后仍用旧授权发出该数据写入 | C03：在引用建立和回收之间交错，验证同一额度不会既被重分配又被旧任务消耗 |
| 到期与旧在途提交完成相遇 | 提交完成仅更新确实被其覆盖的结果，并解除真实已结束的引用；不刷新保活、不复活会话、不释放其他快照或任务仍依赖的额度 | C04：会话先到期、旧提交后成功，提交事实保留且新工作仍被拒绝 |
| 多次取消、到期和完成通知相遇 | 对同一份可释放预留只作一次释放；已写消耗不随通知次数减少，结果不明占用不能被猜测释放 | C05：交换事件顺序并重复交付，最终额度和已提交状态不变 |
| 所有权切换后收到旧会话完成通知 | 通知须核对卷及原所有权/会话归属，不能修改新主账本或授予新主执行权限；新主仍凭磁带恢复证据建立状态 | C06：新主账本建立后交付旧通知，不能退款到新会话或唤醒旧任务 |

一致性是逻辑要求，不预设全库锁、具体原子类型或单线程；不同驱动器不因此被强制串行。迟到消息不使用客户端自报的旧时间绕过服务端当前有效性判断；期限边界、计时来源和服务端排队时如何界定有效受理仍须在协议中明确。

**计时器之间不得互相替代。** 会话保活、time-based 索引触发、IP 维护滞后和硬件命令超时分别维护。客户端保活不得重置最早未提交变更时刻，也不能无限推迟 IP 维护；索引成功也不得反向延长失联会话。服务端等待后的暂停/续计公式仍待定义，不在此默认赠送一整段新保活期限。

**已有提交的完成通知。** 会话过期不要求丢弃旧请求的完成结果；在证据和通信条件仍可靠时，可按已受理请求的结果路径通知，但不把通知成功当作会话重新有效。无回执下不保证跨节点找回这次请求的历史结果，也不把“无法通知”转成自动重写。

上述 C01—C06 是待实现的测试要求。下一步仍需定义计时暂停/续计、有效受理边界及对齐容量校准的算法；当前不填参数、不宣称竞争处理已实现或测试通过。

## 校准与接管

建议容量校准与卷内账本更新建立可验证的切点。设备读取结果涉及的操作范围、校准期间已执行消耗及新授予预留必须可对齐：纳入新基线的消耗不能再扣，未纳入的仍需保留，新预留不能被刷新抹掉。来源或覆盖关系不明时不增加可用额度，保持校准/恢复门控；具体对齐算法及设备提示的可靠性仍待验证。

B 完成隔离与磁带恢复后建立新会话账本，不能继承 A 的剩余额度并自动恢复旧上传。旧主重加入同样不得把旧预留当作当前授权。基线中必须处理实际介质占用和未索引尾部的保守影响，不能只按当前 index 中文件逻辑大小的总和推算空闲；安全追加条件未得到验证时仍不开放写入。

### 已裁定：按切点对齐的容量校准

用户回复“接受，继续推进地图”，确认校准对齐方式，见[裁定记录](issues/04-durability.md#已裁定容量校准切点与一致发布)。下方流程表达已接受的校准约束，具体设备能力和实现仍待验证。

设备容量读数与运行时可分配额度不是同一件事。建议校准只更新已验证的容量基线，不用一次设备读数覆盖整个账本；并发新增预留、已有任务尚未执行的义务、收尾预算和查询之后的消耗都须保留。

**候选流程：**

1. **合并同卷校准请求。** 关联卷身份、当前所有权会话及本轮校准标识；多个等待者共享查询工作，但各自准入/退出状态独立。标识只是运行时关联，不是磁带回执或新的权威日志。
2. **在设备安全边界建立切点。** 由有效所有者的驱动器执行流程调度查询，不插入正在执行的索引提交序列，不强行中断命令。记录能与读数对应的已记账消耗范围；不在持有账本更新锁时等待设备完成，也不为校准停止全库无关驱动器。具体是否需要其他同步前提须按目标设备能力核实，本草案不新增隐式 sync 或分区切换命令。
3. **读取并验证候选容量。** 检查卷/分区、单位、状态、信息时效及读数对已发出操作的覆盖关系。命令串行或返回成功本身不能证明容量提示已经反映全部在途/缓冲消耗。DP/IP 各自保留可验证的切点，不假定设备提供两分区原子快照。
4. **使用发布时的现有义务重新计算。** 对每个分区，以候选基线减去它尚未覆盖的保守消耗，再减去发布时仍有效的未消耗预留和必要索引/收尾保护。查询期间新增预留和已按规则完成的安全释放必须反映到当前状态，不使用查询开始时那份旧预留列表替换它。
5. **一致发布新账本。** 发布前重查所有权、卷身份、原基线版本及候选结果是否仍可用；新基线和扣减范围一起更新，避免新旧代际混算。所有权变化或更晚校准已发布时，旧结果不能覆盖它。DP/IP 准入继续联合检查，任一必需分区证据失效时不能凭另一分区的新读数放行。

在步骤 4 中，预算关系是：

`新可分配预算[p] = 候选基线[p] - 候选基线未覆盖的保守消耗[p] - 当前未消耗预留[p] - 当前索引与收尾保护[p]`

这仍是条件式记账关系，只有计量一致、覆盖范围明确且占用分类不重叠时才成立，不是已经验证的设备空间估算公式。已被候选基线反映的消耗不再扣一次；未被反映的不能漏扣。覆盖范围有歧义时，不据此增加可分配额度；没有其他仍可信的基线时，停止新准入并继续受控校准/核验，不能把“未验证”填成零消耗。

**校准期间的准入与性能。** 如果旧基线、所有权和设备状态仍可信，已有额度内可继续有界接收；新准入也只能使用旧账本中仍有效的额度，不能预支候选校准可能释放的空间。当前可信额度确定不足时继续直接拒绝，不为了等待可能变大的读数无限排队；只有确实需要校准才能判断时适用已接受的有界等待。实际设备操作仍按同驱动器串行规则排队，不承诺查询零停顿或零吞吐影响。

建议利用已有安全窗口低频校准，保持正常逐文件路径仅做本地预算操作；这不等于无限推迟必要校准。校准在数据流中的等待/暂停、设备查询次数和准入开销须单独计量，调度周期、低水位及允许开销继续留空。

**失败与差异处理。** 查询失败不自动等于磁带已满；仅在失败没有否定旧证据且旧预算仍可信时继续按旧账本服务。若新证据表明剩余预算不足以覆盖已有义务，停止新增额度，按既有收尾/恢复政策处理；不能静默撤销预留、借用收尾预算或靠负数归零假装一切正常。保留原始错误和差异来源，重建不会自动承诺原上传仍能完整完成。

**候选验证 K01—K06：**

| 场景 | 期望结果 |
| --- | --- |
| K01 查询期间新增预留 | 发布候选基线后新增预留仍在，不超额分配 |
| K02 查询期间安全取消/释放 | 以当前义务为准，不恢复已经安全释放的旧预留，也不重复释放 |
| K03 消耗恰好位于读数覆盖边界前后 | 已覆盖的不重复扣，未覆盖的不遗漏；不能证明边界时不得放大额度 |
| K04 旧校准结果晚于新结果或所有权变化返回 | 旧结果被拒绝发布，不能覆盖新主账本或更晚基线 |
| K05 DP 有新读数但 IP 证据无效 | 不用 DP 富余掩盖 IP 不确定，联合准入不通过 |
| K06 新基线暴露预算缺口或查询失败 | 分别报告不足与无法判定；按证据控制新增额度，不撤销已提交事实 |

上述校准原则已接受：安全边界取数、按覆盖切点对齐、保留当前义务、一致发布；不为普通文件逐个查询设备，也不以旧/歧义读数放大容量。设备提示的真实覆盖语义、保守上界、具体同步前提和切点实现仍须验证，未执行 K01—K06 或硬件测试。

## 已裁定：索引预算的两层检查

用户回复“接受，继续推进地图”，确认本节两层检查及预算不足时的处理原则，见[裁定记录](issues/04-durability.md#已裁定索引预算两层检查)。实现选择与验证用例仍待完成。

本节针对极端小文件归档细化索引预算，不新增索引格式、上传回执或私有打包。建议把日常准入估算与提交前的冻结快照检查分开，不能只按上传数据字节数估算文件系统元数据负担。

**第一层：日常轻量估算。** 随文件/目录、名称与属性编码长度、extent 等相关变化维护可增量更新的保守统计，分别跟踪本次变更的索引成本及后续必要 Full/收尾预算增长。即使文件数据很少或仅有元数据变化，也要核算其索引成本。正常逐文件准入不重新扫描全目录或序列化整份 Full，不用平均每文件大小、上次增量大小或必然压缩收益替代保守估计；具体上界公式待验证。

**第二层：提交前检查。** 在[提交状态机 S2](commit-state-machine.md#正常路径与失败出口)固定实际数据映射和元数据快照后、S3 开始新的索引构造之前：

1. 按既定增量链预算及收尾要求确定本次应写增量还是 Full。不能先按小增量批准预算，随后不复核就改写 Full。
2. 获得同一冻结快照的实际编码长度或经验证的保守上界，结合格式/设备成本模型，核对本次完整索引构造及仍需保留的正常收尾成本。XML 字节数本身不直接等于磁带空间成本；DP/IP 独立核算，不能只保证本次 DP 增量能装下。
3. 若需要增加预留，在一致账本状态下补足差额，不重复扣除已经包含的保护预算。已有其他任务预留和收尾空间不可挪用；补充条件与容量校准门控沿用已接受规则。
4. 只有成本覆盖、所有权、实际位置及其他提交前提都成立，才进入 S3。后续接收或元数据变化不改变本次检查的快照；如快照/布局必须改变，需重新验证对应成本与覆盖范围。

本检查不强制整份 XML 常驻内存、写入本地临时文件或执行两次完整序列化；计数编码、可证明上界或有界编码结果复用的实现选择须结合测量，不能用无界内存换取预检查。这里检查的是索引，不要求整文件数据先暂存。

| 发现的问题 | 建议处理边界 |
| --- | --- |
| 日常估算偏小，但可信可分配预算足够 | 在 S3 前一致补足差额，记录估计偏差，保持被冻结的提交范围 |
| 差额确定无法补足，或无法证明成本上界 | 不开始新的索引构造；暂停扩大受影响卷的新写入义务，报告本次提交未完成/预算无法确认，保留已有可靠提交与当前可验证状态 |
| 既定规则要求 Full，但 Full 放不下 | 不退回增量突破链预算或收尾要求；依照上一行处理，不能以吞吐目标绕过限制 |
| 为缩小索引而遗漏快照声明覆盖的文件/变更 | 不允许据此确认原批次成功；本稿不引入自动拆改冻结快照、删除文件或新事务语义 |
| 预检查通过后发生短写、索引中断或结果不明 | 仍进入既有恢复门控，不以预留充足证明已持久化，也不盲补剩余索引 |

由于数据是流式先写的，S2 预算检查失败时可能已有未提交数据在磁带上；不能将此结果报告为请求完全未执行，也不自动重写数据或截断尾部。已可靠提交的前缀继续保留，尚未被有效索引覆盖的尾部不能被猜测发布。预检查不是正常收尾一定成功或物理 EOM 后还能提交的保证。

**候选验证 I01—I05。** I01：同样数据量、不同文件/extent/属性规模时分别核算元数据负担；I02：估算偏小但可补足时仅补差额；I03：差额不足时 S3 没有开始且不撤销旧提交；I04：必须 Full 时不能退回增量；I05：冻结后并发变更不改变成本对象，预检查通过后的真实写入错误仍走恢复。用例与估计模型需和实际编码结果对照，未运行测试。

轻量日常估算、提交前快照成本检查和预算不足不启动新索引写入的原则已接受。估计公式、误差余量、编码策略及允许性能开销继续留空；既有正常准入性能要求不降低，也不宣称完整索引构建零开销。

## 候选验证与待填项

- 同卷并发请求各自看似能装下、合起来超出预算时，不得全部准入；其中一个因 IP 预算不足失败时，DP 不能泄漏预留。
- 预留转换、设备完成和重复取消交错时，总占用不被重复扣减或重复释放；已写空间不因提交成功退还。
- 校准覆盖旧消耗但未覆盖新的并发预留时，新预留仍保留且旧消耗不重复计算。
- 未知长度续申请失败、声明大小被超出、索引/收尾预算增长时，不超额接收、不挪用保护预算；部分文件结果沿用已接受政策。
- 提交期间的冻结快照仍引用预留时，取消不得提前释放；所有权切换后旧会话不得申请或消耗新额度。
- 正常准入路径无逐文件设备查询、整卷索引序列化或 A/B 同步；这只是待测约束，不宣称性能零开销。
