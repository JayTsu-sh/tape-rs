## Question

将大文件顺序归档恢复优先转成什么可重复测量的验收标准？确定文件大小分布、压缩与数据可压缩性、单驱动和库级指标、冷/热缓存、并发与故障恢复负载；分别计量暂存接收吞吐和真实已提交磁带吞吐，不将暂存接收视为持久化成功，给出基于硬件基线的目标而非猜测绝对速度。

## Context

用户明确要求[准入检查不能牺牲写入性能](04-durability.md#准入检查的性能约束与快速路径草案)。建议本地容量账本与预留作为正常路径、低频安全校准作为慢路径；此设计尚待验证，不提前选定技术或数值。

验收必须分离容量充足的稳定路径与低水位/恢复路径；比较相同可靠性与提交策略下的 CPU、准入 P50/P99 延迟、锁/队列等待、每文件附加设备查询次数、设备空等时间及真实持久化吞吐。包括小文件高并发与多驱动器场景，不用关闭容量保护或提前确认成功来证明性能。性能预算与允许差异仍待裁定，当前不声称测试通过。

[time-size 组合与计时规则](04-durability.md#已裁定time-size-组合与计时规则)已获用户接受：可独立配置、组合时 OR 触发，time 从最早未提交变更计时且不被后续写入重置。后续阈值测量分别记录主动等待、设备排队、数据排出、索引写入与持久化屏障耗时；不能把触发周期直接视为持久化延迟上界。覆盖仅时间、仅完整文件大小和 OR 组合场景，具体默认模式及数值未定。

[收尾预算优先级](04-durability.md#已裁定收尾预算与容量安全优先级)已获用户接受。空间估计与校准测量应覆盖目录/extent/属性增长及在途消耗，分别报告正常容量充足与接近容量边界的表现；不能靠挪用收尾空间来提升容量利用率或吞吐数字。具体预算数值和计算实现仍待验证。

## Comments

### 待确定：代表性工作负载与测量口径

本票据无 Blocked by，按本地 tracker 认领后开始收集性能需求；不宣称提交契约或产品实现已完成。既有方向是大文件连续归档和恢复优先、小写入聚合，但文件大小分布、到达速率和并发度尚无具体输入。

**建议区分测量层次：**

| 层次 | 建议测量 |
| --- | --- |
| 接收与准入 | 接收吞吐、准入延迟分位数、CPU、等待与缓冲占用；不能替代磁带持久化吞吐 |
| 单驱动持久化 | 完整测量窗口内实际可靠提交的逻辑数据量 / 耗时，包含数据写入、周期提交及必要的窗口末尾排空；不把窗口前缓存的突发排出伪装成稳态性能 |
| 索引与维护 | 增量索引、完整检查点、IP 维护耗时与频率；短窗口和包含完整维护周期的长窗口分别报告，不能只选没有检查点的最好片段 |
| 读取与库级 | 冷缓存实际读带与热缓存分别测量；单驱动与多驱动聚合分开，报告公平性和排队，不以理论线性倍数代替实测 |

建议先建立同一硬件、介质、压缩配置及数据集上的可重复基线，再选择吞吐达成比例和允许的软件开销。容量准入增量开销比较必须保持同样可靠性和提交策略，不通过取消容量保护、缩短测试窗口或提前确认成功改善数字。基线建立需另行明确授权的测试环境；本轮不操作设备。

**首轮请求的输入：** 主要文件大小范围（若差异明显，区分按文件数和按字节量的主要分布）、每天或每批次归档量、峰值并发上传数。用户随后明确极端场景为小文件归档、不确定项留空，见下节；不再将补齐这些数值作为当前讨论前提。驱动器数量/型号、介质、压缩可压缩性、SSD 与网络和读取负载也不凭推测填入。

## Answer

用户已明确“小文件归档为极端场景、不确定项留空”，并反复授权范围内推荐自动接受、继续地图。本轮据此接受[性能验收基线](../performance-acceptance.md)，完成本票据的规划裁定：

1. 大文件持续归档/恢复吞吐为基础优化方向，小文件可靠完成文件率、逐文件成本及长期索引规模为独立必测维度；保留延迟、积压、公平性观测，不增加未要求的低延迟 SLA 或私有小文件容器。
2. 接收、可靠提交和应用收到成功分别计数；完整窗口包含尾批和必要维护，稳态不能靠缓存持续增长假装可持续。P01—P06 及最小观测点作为后续绑定依据，不要求逐文件同步诊断或新增回执。
3. 准入快速路径使用可信本地预算，不新增按文件容量查询/共识；实际 CPU、锁/排队和持久化吞吐按同等安全保证比较。不把“不牺牲性能”解释为可以取消保护，也不承诺零软件成本。
4. 未知数值不填造：运行前固定测试配置及目标，允许先报告合成配置基线。没有目标、覆盖不足或行为失败都不能被命名为性能达标；产品默认值不由实验配置暗中决定。
5. 后续交付为数据集/配置记录、绑定 04/05 等最终协议的测试程序、基线与逐项结果。06 resolved 只代表测量/判定规则和明确留空政策已接受，不表示基准已运行，也不替代其他票据尚缺的算法、接口或现场前提。
