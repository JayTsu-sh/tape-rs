## Question

EE 把哪些故障归为组件、硬件、介质、库存和异常终止，各自的检测信号、自动恢复与人工动作是什么？监控守护进程自动恢复的范围和控制节点切换的触发条件是什么？其消息/日志/事件约定有哪些可借鉴？这些如何映射到 04 已裁定的分层健康检查与按影响范围降级、18 的控制存储失信/解除隔离流程，以及 37 的磁带健康维度，而不把 EE 依赖 GPFS/HSM 的恢复步骤当成本项目算法。

## Scope

只核对指南 §6.7、§6.18、§9.1–9.6、§7.22–7.25。[D02 恢复证据](../recovery-evidence.md)已引用 §6.18、§9.3–9.6 为卷发现与安全追加服务，本票据不重复那部分，只做故障分类与运维动作。不核对 EE 源码，不运行实验室命令，不裁定日志框架、SNMP 或告警通道实现。

## Answer

限定研究完成，形成[故障分类与恢复动作候选](../ee-fault-recovery.md)。

### EE 的故障层次与动作

| 层 | 原文事实 | 出处 | 本项目处理 |
| --- | --- | --- | --- |
| 组件监控 | 每节点一个监控守护进程，监视 MMM、LE、远端监控进程、GPFS、HSM 召回进程、rpcbind、rsyslog、SSH；只有前三者有自动恢复（重启）。MMM 无响应时先在原节点重启，失败才切换到冗余控制节点；只有一个控制节点时原地重启。活动控制节点与冗余控制节点互相监视，活动节点还监视普通节点的监控进程 | §6.7.1 印刷页 153 / PDF 177 | 对应 04 的“ltfsd 控制服务失效交由整组恢复流程”；EE 的“先原地重启再切换”是候选顺序，但本项目切换前须满足 18 的隔离与授权门槛，不能仅凭监控判定 |
| 手动切换 | `eeadm cluster failover` 仅在存在冗余控制节点时可用；切换后运行中任务 aborted | §6.7.1 印刷页 154 / PDF 178；§1.2.1 印刷页 8 / PDF 32 | 对应 18 的计划切换排空边界；本项目默认排空而非直接 abort |
| 启动失败 | `cluster start` 返回错误后用 `node list` 查看各节点失败模块；常见原因为 rpcbind 未启动、节点看不到驱动器、没有控制路径驱动器 | §9.1.2 印刷页 294–297 / PDF 318–321 | 借鉴“按模块报告启动失败、监控进程进入恢复序列”；控制路径可见性是 09 的部署核对项 |
| 带库/驱动器硬件 | 带库与驱动器错误由带库 GUI 事件页与驱动器面板报告；收到非预期 sense 时自动生成约 2 MB 的驱动器 dump 到 /tmp，cron 按 14 天/1000 个上限清理；修理驱动器前先 `drive unassign`，驱动器内磁带自动回 homeslot | §9.2 印刷页 297–300 / PDF 321–324 | 借鉴“非预期 sense 自动保存诊断转储并限量保留”；本项目已有原始 status/sense/ASC/ASCQ 保留要求（AGENTS.md），补充转储与配额政策，数值留空 |
| 写失败磁带 | 进入 require_replace；步骤：确认状态→确认同池有足够空间的 appendable 磁带→`tape replace`（内部先 reconcile，再迁移数据到目标带并把坏带脱离池）→移到 I/E 槽处理。多次 replace 失败则 `unassign --safe-remove`，把活动文件召回到有足够空间的 GPFS 后人工重迁 | §9.3 印刷页 301–302 / PDF 325–326 | replace 流程可借鉴；safe-remove 依赖 GPFS 暂存，本项目改为“召回到指定目标池”或交由应用重传，见候选文档 |
| 读失败磁带 | 进入 need_replace；处理步骤同上 | §9.4 印刷页 302–303 / PDF 326–327 | 同上；need_replace 允许继续读取 |
| 软件与日志 | 四个组件各有日志；ltfsee.log 只含警告/错误（人读），ltfsee_trc.log 为机器可读 CSV（local2 facility），可用工具转换；轮转 1M×4 / 10M×9；消息 ID = GLES + 组件字母 + 三位数 + 严重级 E/W/I/D，LTFS 消息为 LTFS[I/D]nnnn[EWID]；建议关闭 rsyslog/journald 限速；`ltfsee_log_collection` 打包日志、配置、系统信息与任务状态文件 | §9.5.1、§9.5.3、§9.5.5 印刷页 303–311 / PDF 327–335；§7.24.1 印刷页 262 / PDF 286 | 借鉴“人读/机读双日志、带组件与严重级的稳定消息 ID、一键收集”；具体框架留实施 |
| 文件 missing | 磁带损坏或未导出即取走导致；索引损坏用 `tape validate`，磁带缺失则放回并 `library rescan` | §9.5.5 印刷页 311 / PDF 335 | 对应 37 的位置维度 missing 与健康维度 require_validate |
| 掉电 | 正在写的磁带很可能不一致；重新挂载后访问各磁带，不一致的卷目录消失，用 `tape list` 确认后 `tape validate` | §9.6.1 印刷页 312 / PDF 336 | 本项目由 04 的 R1—R5 恢复流程处理，不把目录消失翻译为文件不存在；validate 对应 D02 只读核验 + 显式修复 |
| 机械故障 | 修好机械部件后对每盘受影响磁带 validate，再走掉电流程 | §9.6.2 印刷页 312 / PDF 336 | 对应 37 位置维度 inaccessible 与健康维度 check_library |
| 库存故障 | 条码无法识别时出现 UNKN0000 占位；处理：取出、检查标签、经 I/E 槽放回、`tape list` 确认、`tape assign` | §9.6.3 印刷页 312–313 / PDF 336–337 | 本项目库存层把无条码元素标为 unknown，不自动入池 |
| 异常终止 | LTFS 被 kill 或系统挂起后磁带可能留在驱动器并被锁定，需 `ltfs -o release_device` 释放 | §9.6.4 印刷页 313 / PDF 337 | 释放设备是新执行实例恢复的一步，不等于旧主已隔离（recovery-evidence 已强调）；与 18 的 UF 显式解除隔离衔接 |
| 许可证过期 | §7.22 描述节点 LICENSE_EXPIRED 状态与只读重启 | §7.22 印刷页 255–256 / PDF 279–280 | 用户明确：当前不引入任何 license 相关内容和设计；本行仅记录原文存在该章节，不借鉴、不映射 |
| 灾难恢复 | 仅支持 SHARE tier 1 离线保管：迁移时写多副本到独立 DR 池，导出后 `tape move -L ieslot` 取出；恢复时在新环境 rescan→move homeslot→`tape import`，文件保持 migrated 状态无需拷回；未 reconcile 的磁带导入可能出现多代文件或已删除文件 | §7.23 印刷页 256–261 / PDF 280–285 | 站点级 DR 仍在 Out of scope；但“从导出磁带 import 重建目录”是 37 目录重建能力的自然延伸，记为后续扩展 |

### 与既有裁定的对齐

- 04 的“按影响范围降级”和“分层健康检查”给出原则；本票据补充每层的检测信号、EE 动作和本项目的自动/人工边界表。
- 18 的 SG（控制存储失信）、UF（显式解除隔离）、MR（维护参选）覆盖控制面；EE 的监控进程只处理组件重启和控制节点切换，不含设备隔离，因此不能作为本项目切换充分条件。
- 37 的健康维度取值与 EE 的 check_*/need_replace/require_replace/require_validate 一一对应；本票据给出进入和离开各取值的事件与动作。

不采纳：GPFS/HSM 日志与 dsmrecalld 相关恢复、SNMP MIB、safe-remove 到 GPFS。留空：dump 配额、日志轮转尺寸、监控探测周期、原地重启次数上限。
