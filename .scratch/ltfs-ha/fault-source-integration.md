# 故障源接入与无空洞资格审查

关联：[稳定故障域](permit-fault-scopes.md) · [控制故障](control-failure-dispatch.md) · [资格发布](raft-rs-binding.md#资格发布失效代次与同步边界) · [执行授权](issues/18-raft-execution-contract.md)

状态：依自动接受授权采用的逻辑接入协议，未实现/执行。下列来源是后续实现必须承担的职责，不冒充已有 Rust 组件；具体系统/设备适配器及其探测能力仍须验证。普通诊断日志丢失与本节安全事实记录不完整严格分开。

## 来源与影响必须显式映射

记 I 为实例内 K/G 共同执行前提，K 为组协调前提，G 为组设备执行前提，VR/VW 为卷读取/写入能力。它们不是 Raft 投票资格的同义词；一个来源可能另需更新 EG 的 Q/V/B，只有明确影响控制持久历史/协议可信性时才停止健康控制参与。

| 来源职责 | 失效及门控映射 | 恢复合格的最低证据 |
| --- | --- | --- |
| 领导与配置处理 | 当前 Leader/执行实例/必要成员配置关联改变→I；维护已提交历史与合法协议推进另按 Ready 契约 | 当前领导上下文和实际应用配置一致，旧中断已处理，新 CG/TG 轮次完整；不把重新当选直接当执行就绪 |
| 必要控制保存、安装、应用 | 明确失败/失信→I，并按 FD/SG 限制本实例协议输入/输出；单纯在途不当失败 | 原写者收束、可信恢复组合及实际重放/应用完成；确定性失败未修复不能跳过 |
| 运行许可时钟能力 | 读数失败、已知时间域更换/不连续或能力失信→I；不由此自动丢弃健康持久投票历史 | 新时间域能力成立并按新轮次重建；旧期限不得转成新域时间继续使用 |
| 隔离管理通道 | 不能证明指定协调入口/目标/动作关联有效→K；若揭示现有 G 的现实风险，同时更新相应 G/I | 当前限定通道、目标和权限核验，相关旧管理请求仍受约束；K 不自动允许解除隔离 |
| 隔离与旧效果核验 | 旧执行者访问或陈旧管理效果可能破坏排他性→G；共同风险扩大时再按实际范围处理 | 现实隔离持续成立、全部相关未知效果已核验或被可靠约束，不以取消受理代替收束 |
| 设备/路径与资源身份 | 按实际必要路径和资源范围限制 G 或相应资源能力；同时按 EG 更新设备候选条件 | 必要身份和访问条件确立；局部故障可证明独立时不扩大为整组失效，不发无许可探测 |
| 卷身份、索引与视图 | 换卷/当前性或引用信任破坏→VR/VW；仅追加尾部未知→VW | 当前视图及引用、安全读取分别恢复；写入仍需受支持尾部和全部 R5 条件 |
| 容量与本地缓冲 | 可信不足只拒绝新增义务；账本/实际占用无法信任时限制对应 VW/准入 | 按当前预留及可信校准切点重建，不凭文件逻辑大小或清缓存增加磁带额度 |
| 本地许可/状态完整性 | 描述/token 不变量破坏、毒化或不可恢复的发布异常→相应许可/能力；影响不明才扩大 | 依证据重建相关上下文；不 clear_poison 后继续授权，不把正常 try_lock 忙当损坏 |
| 来源监管与配置切换 | 必需来源退出、责任交接失败、来源清单/依赖变化→受其影响的 gate | 新来源覆盖、身份/代际、未决观察及失效记录完成交接，再发布合格审查 |

普通 RQ/会话截止、旧 K 阶段到期及计划排空到期不是一律推进共同 gate 的来源；分别走精确许可/会话/请求的到期规则。只有发现时间依据或必要安全前提本身失信才提升到对应共享域。可安全放弃的本机快照失败、缓存持久化失败也不自动套用必要控制存储故障。

## 来源注册与责任交接

运行上下文先建立 gate 和必需来源清单；全部 gate 从未知开始。每个来源登记实例、配置/资源代际、稳定来源身份、可影响的 gate、事实获取渠道及当前监管责任。登记成功仅表示接入，不表示健康或隔离已经成立。

在允许任何绑定之前，来源须已接通失效发布路径并能被监管；首份合格 Reviewed 须覆盖整份必需清单。不把“尚未收到故障事件”当作初始健康。新来源和资格审查不获得额外设备访问权，所有主动观察遵守原 K/G/安全观察边界。

更换来源或清单时先使旧覆盖失效，再完成责任交接和新审查；旧 gate 在同一上下文内保持身份。来源退出也不能仅靠强引用计数判断：已安排的观察、旧回调、适配器队列和监管责任都须核对。无法无缝证明交接时接受对应范围暂时受限，不隐含复制所有运行状态或重启其他节点。

## 每次失效的发布次序

1. 源端按当前上下文确定影响域；新发现的旧动作危险仍保留原关联并判断当前影响。范围未知时采用既有扩大限制策略，不能因无法精确分类先继续派发。
2. 对相关 gate 推进 failure_epoch，取得本次该 gate 的唯一序号 e。此步骤不等描述/S 锁、诊断格式化、记录空间或持久化；MAX 保持永久受限。对多个 gate 的更新不假装成一次原子事务，观察各自生效点并保守核验全部必要依赖。
3. 保存最小失效关联：来源身份/代际、gate/e、事件类型、原任务或证据引用、已知范围和仍需核验事项。它是资格恢复必需的本地关联，不是磁带上传回执。危险事实仍须按 CG/FG 的持久意图/效果规则处理。
4. 唤醒审查/控制处理路径，补充原因和必要终止记录。不能因唤醒失败重开门，也不能等补录提交才认为 epoch 已失效。若同时影响候选 Q/B 或正常协议参与，分别完成其既有处理，不以 gate 更新冒充全部完成。

先递增后保存意味着可能存在“e 已发布、事件正文未到”的空洞；协议必须保留它，不能从缺日志推断没有事件。重复投递同一 gate/e 不产生另一事件身份；同一真实情况是否可以合并，只有在仍保留必要失效、范围及处理义务时才成立。

## 连续处理前沿与合格发布

每个 gate 维护连续已处理前沿 H，初始为 0。只有序号 H+1 的事件关联完整、必要风险已纳入当前审查且没有缺失义务，才前进；较大序号可暂存但不能跳洞推进 H。这里“处理”不要求所有外部动作成功结束，而是其未知/风险状态已被可靠纳入审查，尚有不安全前提时 qualification 仍不能为合格。

审查在起始 epoch e 上取得必要来源/配置/效果证据，发布合格 Reviewed(e) 必须同时满足：

- H 已连续覆盖到 e，安全关联没有丢失/损坏，所有必需来源仍被覆盖；
- 当前 qualification 的全部前提成立，未决效果不存在未约束冲突；单源健康不能覆盖其他来源限制；
- 发布时原子 epoch 仍为 e，来源/配置/资源代际不变；旧观察绝不重贴到更大 e；
- 该范围的恢复动作已按既有契约完成，合格只允许新许可或新资源能力绑定，不改旧绑定。

当前 epoch 在发布后再次增加时，所有读者的持续匹配立即使该 Reviewed 不可使用。H 只是本地关联的连续处理前沿，不是 Raft applied index、设备完成水位或可删除所有外部事实的回收点。引用和持久拒绝依据仍按原控制保留规则处理。

## 有界记录与失败出口

来源数量、最小事件关联、待处理队列与审查任务均设置预算，数值留空。接入时预备最小安全记录路径；快速失效不因预算不足而拒绝推进 epoch。正文较大时只保留原受保护证据关联，不能无限复制诊断内容。

若不能保存、确认或重建某个已分配序号的必要安全关联，则对该 gate 记录不可忽略的“关联完整性失信”，禁止在当前 gate 上重新发布合格 Reviewed；没有收到事件也已因 H 的空洞无法合格。该标记的设置不依赖已经失败的分配/队列，不能靠下一个健康通知清除。

这是明确接受的保守可用性取舍：安全关联预算耗尽可能要求对应运行/资源上下文重建，不能靠丢掉最旧安全事件继续服务。重建仍须从可信控制历史和现实效果恢复全部必要前提；若丢失事实无法重建，保持受限并显式排查。局部 gate 的失信不自动强制整组 HA 换轮；实例/组级许可失效与局部能力失效仍分层处理。

上述限制不适用于与安全审查无关的普通 debug/性能诊断日志丢失。记录处理后可按已证明引用关系回收本地事件正文，但 H/当前 epoch、未决效果及拒绝依据不能由“队列已清空”替代或清零。

## 验证目标

SI01—SI06 均未实现/执行。

| 场景 | 必须检查 |
| --- | --- |
| SI01：没有活动 cell 时失效、新 cell 正在准备 | 来源先接 gate，旧/新绑定均不能绕过 epoch 变化；初始未知不等于合格 |
| SI02：e 事件延迟，e+1 先处理 | H 不跳洞，不用后来的健康结果发布合格 e+1；补齐且全部前提成立后可继续 |
| SI03：来源退出/更换，旧观察迟到 | 旧清单先失效，旧健康不重贴新代际，新来源未接好不开放 |
| SI04：安全关联预算不足、普通日志分别丢失 | 前者禁止错误恢复，后者不无故升级为安全历史丢失；epoch 不等待分配 |
| SI05：纯 K/单卷事件及真正共同风险 | 局部能力恢复不强制整组接管，旧到期不误杀 G，共同危险仍按真实范围停发 |
| SI06：正常恢复与长期负载 | 连续处理可前进，已安全解除引用的正文可回收，合格新绑定可工作，不靠永久拒绝过验收 |

这份清单收敛职责映射和无空洞审查算法；不等于所有真实来源、监管机制、预备记录容器及故障检测时限已实现。EG 内核调用重叠、源端获知到原子失效窗口、时钟和物理派发仍单独验证，不因此关闭 18。
