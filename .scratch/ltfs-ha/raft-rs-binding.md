# raft-rs 控制推进与设备参选的绑定规格草案

关联：[执行授权](issues/18-raft-execution-contract.md) · [接口事件](control-interface-events.md) · [候选研究](issues/24-rust-raft-binding-evidence.md) · [Ready 推进依据](issues/25-raft-rs-ready-election-evidence.md) · [资格刷新](authority-refresh.md)

状态：依据用户接受的 raft-rs 优先验证方向及自动推进授权，采用以下简化验证基线。固定 v0.7.0 / `10c6e9db6792b85c81784e44fc278f895d5f0ab0`，未最终锁库、未实现/运行。它是事件处理规格，不定义模块 seam、线程数或 Rust 公共 API；不修改库源码、投票/多数派规则或磁带格式。

## 基线与成本边界

首个验证基线采用一个 RawNode 的单一串行变更入口、最多一个尚未确认完成的 Ready；本周期所需可靠保存完成后才 `advance_append`，实际应用完成后才回报 applied。先不采用多个异步持久化 Ready 的流水线，不将应用入队冒充完成。此选择用于减少并发证明范围，不是生产吞吐最优结论或永久禁止后续优化。

可靠保存和应用可以等待外部工作完成，但等待不授予其他线程直接修改 RawNode 的权力，也不能阻止独立安全门控依据当前失效条件停发。串行入口是逻辑排他要求，不要求把存储阻塞、计时、网络和设备命令塞进同一线程。长期保存无结果与资格期限耗尽仍分别按存储/时效规则处理，不假定等待一定有限。

正常数据 write、索引批次和逐 CDB 不进入该控制日志。safe 确认仍按 RQ 周期进行，空闲控制周期不为满足本基线凭空新增 fsync/no-op。选择更保守的控制推进可能增加选举、配置和首次授权延迟，后续测量须区分它与数据写带吞吐；未知数值留空。

## 一个周期的明确顺序

| 切点 | 允许工作及完成依据 | 不允许的捷径 |
| --- | --- | --- |
| P0：可接收下一次内核变更 | 先消费已知资格变化并按角色处理，再选择合法协议输入、定时事件或本地请求；正常协议与本地工作有公平调度 | 先消费已排队的赢票消息，再补处理已知设备失效；任意清空队列 |
| P1：取得 Ready | 保存周期身份及全部输出：HardState、entries、snapshot、committed entries、ReadState、两类消息及其他必要通知 | 只提取 entries，然后丢掉其余字段 |
| P2：保存与快照安装 | 依赖快照/日志/协议状态的可靠保存与 Storage 可读性均满足；有接收快照时本基线还先完成匹配状态机及配置视图的实际安装，再确认本步。可推迟普通消息，受持久化约束的消息必须等待 | 超时伪报成功；只保存快照正文就当安装完成；在 Ready 未处理完时并发 step/tick/campaign/退位/修改计数 |
| P3：确认保存 | `advance_append(ready)` 仅在 P2 真正完成后调用；完整取得 LightReady 的新增 commit、消息和待应用条目 | 使用隐含应用完成的快捷路径，却实际上只安排了应用任务 |
| P4：完成条目应用 | 以当前已实际安装的状态机视图为基线，按位置处理 Ready 及 LightReady 的条目；按顺序处理配置项、空条目、业务结果 | LightReady 条目先于前面的 Ready 条目；把配置条目当业务拒绝 |
| P5：确认实际应用 | 连续完成至 A 才 `advance_apply_to(A)`；保存具体结果，核验返回 ReadState 与实际 A；处理该调用可能产生的后续 Ready | 把 applied 设到队列末尾；丢掉配置自动退出等产生的新工作；回调直接启用 K/G |
| P6：返回安全调度点 | 下次变更前再次核对资格；新 Ready、正常输入与必要完成事件按可验证次序继续 | 无限 drain 本地输出而饿死投票/复制；因候选不合格永久停止处理全部消息 |

P1 的 ReadState 可以先登记，但最早到满足 P5 实际应用及 RQ 全部条件时才可成为 usable；回调先到、后到或丢失均不重写真实完成顺序。P2 的普通消息晚发是本基线的保守策略，不把它描述为库对所有消息的强制持久化要求。消息交付仍按下文区分旧竞选请求和正常投票/复制响应，不在保存完成后无条件发送已失效的竞选输出。

任何可能改变内核状态的调用都经同一入口；直接访问公开字段也不例外。外部完成通知携带周期/实例关联，重复、旧实例或已失效关联不得错误确认另一周期。字段名称及方法语义以 [25 的固定源码依据](issues/25-raft-rs-ready-election-evidence.md#answer)为准，升级必须重核。

## LightReady、快照与恢复一致性

[SQLite 控制事务](control-store-transactions.md#四类权威事务)现分别绑定 P2 与 LightReady 新 commit；提交可靠后安装匹配的 RAM Storage 视图，真实 apply 仍走 P4/P5。同步 Storage 读取不在 S 中等待数据库；完整日志/快照 RAM 预算和持有旧对象的成本按该支持范围验收。精确编码留实施，不能再将引擎/原子批次机制视为未选择。
维护三个不同位置：协议已提交位置 C、本机实际应用位置 A、可靠快照切点 S；另有日志/协议状态的可靠保存依据。它们不是一个 `last_index`，也不直接等于 tape generation。A 只随连续实际应用前进，S 只随完整快照可靠发布前进。

LightReady 返回的新 commit 必须进入本地恢复账目，不能假定下轮 Ready 会重报相同 HardState 差异。依自动推进授权，[控制存储基线](control-storage-recovery.md)现采用业务状态仅持久完整快照、快照后日志重放，并保守要求新增 commit 的依据可靠后再应用对应条目；无变化的周期不新增空批次。若将来改为状态机/applied 单独持久化，须重新证明对应 commit 与日志/快照的配套关系，不能混拼两种恢复方式。原子批次现映射到 SQLite，精确存储编码与绑定留后续实施规格。

接收快照包含三个不同完成点：可靠保存、实际安装状态机/配置、确认实际应用。实际安装前不以该快照服务控制查询或授予权限；安装后也不恢复旧运行 K/G。快照元数据、Storage 和状态机配置视图须一致，不重复执行快照已经涵盖的配置转换。覆盖历史的回收继续受 CS 的唯一恢复依据、拒绝旧授权、未决动作及证据依赖约束。无条件取 `max(applied, commit)` 不能修复缺失的历史。

保存失败不 advance 成功；状态机安装/应用失败不假报 A。业务条件拒绝是正常确定性结果，不与存储失败混同。必要历史失信时按 SG 受限，不通过清空控制目录、自动缩群或读磁带 index 重建 Raft 状态。

## 设备资格变化与竞选入口

参选资格 EG、隔离协调 K、设备执行 G 分别判断。设备执行条件不足不自动禁止 HK 允许的限定协调；已有有效 Leader 也不因一个 Follower 不合格就退位。下表的退回策略仅用于已不合格的 PreCandidate/Candidate，不扩大为所有角色每次健康变化都强退。

| 入口或角色 | 本基线采用的验证候选 | 必须保留/证明 |
| --- | --- | --- |
| 启动 | 先建立本实例的资格状态和受控入口；未知资格不自动 campaign，旧 ready/K/G 不恢复 | 正常可信恢复仍可投票/复制；MR 仅按既有维护例外衔接 |
| 显式 campaign／本地 MsgHup | 只在消费时仍合格才交给内核；不把排队时的健康值当永久许可 | 所有应用调用均经封装，无其他直接入口 |
| 竞选中失效 | 在合法内核变更切点，按真实当前 term 退回 Follower，再处理可能赢票的响应；未知 Leader 用 INVALID_ID | 不清除同 term 已投 vote；核对 pending snapshot、读请求重置、迟到响应和旧输出 |
| 禁选 Follower 的定时事件 | 保留必要 elapsed 年龄推进，抑制本节点 Hup；正常消息仍按原路径重置计时 | 不停 tick 导致旧 lease 永久不老化；溢出/饱和、重新合格及随机超时行为须验证 |
| 不合格节点接收 TimeoutNow | 只在来源/消息已通过验证的限定分支，保留固定版必要 term 前缀并抑制 Hup；高 term 用公开退回路径处理 | 不直接赋 term/vote、不伪造 heartbeat；产生的 HardState 走正常保存；低/同 term 及异常输入分别核对 |
| Vote/PreVote、复制、心跳及快照 | 继续经原协议入口处理；先完成已知失效 Candidate 的退回，防止旧获票继续当选 | 不过滤全部选举消息、不对所有消息套 max(term)，保留 PreVote/lease 等特例与正常复制 |

禁选计时与 TimeoutNow 适配依赖公开字段/方法，但复制了部分固定版推进语义。依自动推进授权，将其列为受控适配验证候选，接受需要固定源码审计和升级回归的成本；这不是现成稳定禁选 API，也不是无需核心扩展的证明。未通过完整入口验证前不得宣布 EG 集成完成；若最终需要改库源码或放宽既有规则，仍另行报告，不由此文批准。

已生成但未交付的本节点旧竞选请求、给其他节点的投票响应、普通复制响应分别处理。禁止新竞选不等于任意丢弃所有 Ready 消息；即使不再交付旧竞选请求，也须保留正确 term/vote 保存与已发消息的迟到处理。来源鉴别、消息分类和网络重试的具体实现仍待核验。

## 保存等待期间的失效轨迹

1. 当前 Candidate 取得 Ready，保存尚未完成；模型安排获胜响应进入外部输入队列，但尚未交给 RawNode。
2. 监测路径获知资格失效，按其适用范围关闭外部新派发并发布失效关联；不在等待中的 RawNode 上并发退位。EG 失效不凭空表示每种 K 的前提都失败。
3. 保存真实完成，按 P3—P5 收束该周期；必要提交和历史应用照常处理，但任何旧授权/确认不得复活已失效的运行资格。
4. 在下一次会改变竞选结果的输入前消费失效；Candidate 合法退回后才交给原协议处理旧获票响应。保持正常其他节点的投票/复制，不能永远挂在 Ready 等待中假称正例通过。
5. 若保存失败或必要协议状态失信，则进入对应受限路径，不伪造 Ready 已完成来执行退回；新节点接管仍须外部 fencing，不能依赖旧节点及时完成此序列。

物理失效、监测获知、门控生效和串行推进者消费失效分别观察。共享资格变化与内核推进的候选同步边界见下节；具体并发实现仍未验证。软件不能预知尚未观测的故障，也不能凭本段消除最后检查后暂停的物理交付窗口。

## 资格发布、失效代次与同步边界

依自动推进授权，采用“当前资格与失效历史分别保存、短控制临界区串行化发布与推进、外部停发不等待 Ready”的验证基线。这是项目设计，不声称 raft-rs 已提供相同接口；不增加持久化上传历史或按文件共识。

### 最小本地状态

| 状态 | 用途与约束 |
| --- | --- |
| 本机实例与配置关联 | 所有资格观察、竞选关联和完成通知限定在当前实例/配置，不凭节点名跨重启复用 |
| 当前资格 Q 与修订 V | Q 区分合格、不合格、无法确定；V 标识会改变准入判断的有效更新，不能只比较相同布尔值。无实质变化的重复健康观察不反复制造新资格 |
| 失效代次 B | 接受一次使原竞选资格中断的更新时前进；Q 后来恢复合格不回退或清除 B。未知若不足以继续证明资格，按同样中断处理 |
| 本轮竞选绑定 Bc | 本节点进入 PreCandidate/Candidate 时关联当时 B；若 Bc 不再匹配，旧竞选必须在合法切点退出，即使 Q 此时已恢复合格 |
| 已处理失效位置 Bh | 只有实际完成所需本地处理后才推进；收到通知、请求退回或安排任务不算已处理。不把一个权限的完成误记为所有权限都处理完 |
| 运行许可终止信息 | K/G 按各自精确身份、范围及原因单向终止；资格恢复不清除此信息，不为旧许可重建截止点 |

这些是本机运行协调状态，不替代复制控制记录、Raft term/vote 或磁带权威。实例重启后资格从未知开始，不从快照恢复本地 Bc、截止点或活动门控；按正常新轮次或 MR/MH 路径重建。计数器不能回绕后复用身份，表示能力耗尽须保持受限并走受控恢复，具体位宽不预填。

**合并通知不能抹去失效。** 可以合并重复的当前状态展示，但“合格→失效→合格”至少保留 B 的前进及其处理义务；不能只剩最后的 Q=合格。仍影响安全的原因、作用范围和外部动作关联不能被这一个数字替代或回收；不保证所有证据都能压成固定大小。

### 资格更新的受理规则

1. 核验观察的实例、配置、来源、覆盖范围及适用性。恢复合格须基于当前前态/修订和完整必要证据；检查开始后前态改变的迟到“健康”结果不能直接覆盖新限制。
2. 同一来源的重复/过时状态更新不按到达顺序最后覆盖。旧动作带来的新危险事实仍保留原关联并另行核验，不能因关联旧就忽略；“旧健康结果不能解禁”不等于“旧危险事实一律丢弃”。
3. 确认失效时推进对应 B，记录作用范围并触发受影响门控停发。仅 G 条件不足不自动结束仍符合 HK 的 K；仅一个 Follower 不合格不撤销其他节点的合法执行权。
4. 恢复 Q=合格不恢复旧 Bc 或 K/G。若存在尚未处理的竞选中断，先完成旧竞选退出，再允许新的正常参选机会；不因一个健康通知直接调用 campaign 或忽略 FG/UF/MR 的限制。

### 短控制临界区的职责

候选使用同步门 S 串行化资格的正式发布与单次会改变竞选结果的 RawNode 推进。门内完成当前 Q/V/B 读取、未处理失效判断、允许的角色处理以及该次内核调用，不能检查后释放 S，再无条件用旧判断调用内核。只有 RawNode 的串行持有者执行内核变更；其他发布者只更新资格状态和待处理关联。

S 不跨存储读写、快照构建/安装、状态机大批量应用、网络发送或任何 await。取得 Ready 后记录等待阶段并释放 S；等待期间资格仍能发布，但不能借 S 已空闲就违反 Ready 契约修改 RawNode。保存及安装真正完成后，按 P3—P5 继续必要历史处理；下一次可推进竞选的输入前先检查并处理 B 的变化。配置应用等会调用内核的步骤仍单独走合法入口，不把整批应用锁在 S 内。

用于现实风险的外部停发入口不等待取得 S、Ready 保存完成或撤权提交，只能针对适用的运行许可单向关闭，不能开门。RawNode 的后续正式处理不得丢掉该停发事实。该入口与新许可启用、刷新及实际派发的同步仍须分别证明；不声称几个原子字段已构成正确设备门控。

正常每条设备命令不获取 S，不等待本轮 Raft 保存；它使用当前运行许可的本地门控。S 的竞争成本在控制面测量，不将新锁放到逐文件写入路径。禁止在持有 S 时等待设备执行锁、远端响应或无限循环，防止安全发布被慢操作拖住；锁公平性、调度饥饿及可允许的临界区成本须后续验证，数值留空。

### 重叠事件的可观察边界

资格发布和一次不可中断内核调用必须能给出真实的先后关系：发布已完成且随后开始的调用不得用旧资格；调用已经跨过约定同步点时，不能靠事后日志把它改写成从未发生。尚在争用发布入口、源端已经发现危险、门控实际关闭和 RawNode 消费更新，是不同可观察事件。

不能通过重新命名“获知”来隐藏风险：测试必须记录源端获知至发布及处理的延迟，并检查已有失效信号是否被随后输入绕过。早期草案未裁定调用内部角色变化的语义；现依 [35 后明确采用的细化](election-overlap.md)，允许重叠调用有真实内部中间态，但不能发布/服务不合格的新领导资格。调用产物先隔离，返回后复核，按是否已有未完成 Ready 选择合法退回切点；必要历史不回滚，合法响应不整批删除，不能只关 G。源端至失效发布、资格接受至实际网络交付仍分别需要同步与观察证明，不能由 S 名称赋予。

### 同步验证场景

| 场景 | 安全断言与进展正例 |
| --- | --- |
| QS01：Ready 中出现合格→失效→合格，旧赢票响应已排队 | B 的变化不被最后 Q 覆盖；合法切点先退出旧竞选，旧响应不能完成它；新的合格参选仍能按正常路径推进 |
| QS02：迟到健康结果与新限制交错 | 旧前态结果不解禁，新危险事实仍可核验；重新取得当前完整证据后可恢复资格 |
| QS03：保存长等待期间失效 | 外部门控可先关闭，资格发布不等磁盘；不非法修改 Ready，不伪报保存完成；真实保存完成后正确处理更新及正常复制 |
| QS04：资格发布与一次内核调用争用/重叠 | 保存源端发现、发布开始/完成、内核检查/完成的真实顺序；已发布失效不被新输入绕过，未证明的重叠窗口不记通过 |
| QS05：旧 K/G 回调与新资格更新并存 | 终止精确关联、不恢复旧许可；有效新许可不被无关旧通知撤销，真正影响当前安全的风险仍停发 |
| QS06：持续资格观察、配置变化及重启 | 重复观察不引起无限退回，重要失效不因合并丢失；健康投票/复制与恢复正例可推进，重启不继承本地旧资格 |

## 禁选计时与恢复合格的限定算法

依据 [26 的固定源码研究](issues/26-raft-rs-election-timer-evidence.md)，依自动推进授权采用下列验证候选，不改库源码或投票规则。记逻辑年龄 e、基本选举阈值 E、当前随机阈值 R、有效最大阈值 U；有效且无计算溢出的配置满足 `0 < E <= R < U`。

1. 仅在合法串行变更切点、当前仍为设备不合格 Follower 时使用本适配；其他角色和合格节点按原有路径，未完成 Ready 期间不直接写计时字段。
2. 读取该时刻的 e/R；若 e<R，安全加一；否则停在 R，已有 e>R 也只归一至 R。不先做可能溢出的普通加法再取 min，不触发该 tick 内部的本节点 Hup。
3. 这保留 `e<E` 和 `e>=R` 两个判断，避免禁选无限延长旧 Leader lease。正常 Append/Heartbeat/Snapshot、批准实际 Vote、term/角色转换等合法重置仍交给原协议；后续读取新 e/R，不用额外保存的旧最大年龄覆盖。
4. 恢复合格这一事件本身不清 e、不重新抽取 R，也不立即调用 campaign；下一正常 tick 仍先检查当前资格和角色，再按原协议决定。被未应用配置阻止的 hup 等路径仍可重置年龄，不承诺资格恢复后立刻参选或所有路径永不再次出现短期 lease 条件。
5. 构造/校验配置前，先检查默认 `2 * election_tick` 的可表示性，再验证真实区间；显式最大值不能假定等于 2E。规范化 `e<=R<U` 使正常 tick 的下一次加一可表示，但不证明其他计数器永不溢出。
6. Ready 等待期间的 tick、协议消息重置及资格变化保留因果次序；不把整段墙钟差机械累加到刚被心跳重置的 e。该年龄不用于 RQ 续期，暂停/时钟失信和真实期限仍按 RQ 处理。

ET01—ET06 均未实现/执行。此处收敛了计数及资格恢复候选，未解决资格发布的同步实现、调度公平性、所有竞选入口或物理隔离；源码版本变更仍须重新核验。

## 可检查的完成条件与剩余工作
