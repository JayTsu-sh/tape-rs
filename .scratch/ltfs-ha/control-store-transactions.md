## 一个节点一套控制库

每个 Raft 成员独立保存自己的控制库，不跨节点挂载同一个数据库，不复用可删除重建的文件 catalog。控制日志通过 Raft 复制；本地库只实现该成员必须履行的可靠保存。磁带不能补出丢失的 term/vote，控制库也不能替代可恢复 LTFS index。

首版将日志、HardState、完整控制快照及恢复必需的证据正文放在同一数据库；不使用 ATTACH、多库提交或外置权威快照文件。快照仍是控制状态同一实际 apply 切点的完整闭包，平时业务控制状态仍在 RAM 应用，不新增逐条持久化的业务 applied 表。

本轮选择的代价是完整快照需要编码、事务和内存预算；不声称其吞吐最优。外置大对象可后续另行设计，不能为绕过预算把必要正文临时移成不可核验的外链。

## 最小记录集合与编码边界

以下为内部持久化逻辑字段，不是对用户公开的 API 或最终 SQL DDL。

| 记录 | 必要内容 | 约束 |
| --- | --- | --- |
| 单一控制根 | 格式版本、集群/成员/存储身份、发布修订、最新 term/vote/Cd、当前快照引用 S/term/ConfState、日志首尾与压缩边界任期 | 同一事务发布；引用和实际条目一致，不能只更新位置 |
| 日志条目 | 完整 index/term、条目类型及原协议内容、受支持编码标识 | index 唯一；保存命令原内容，不在存储层重解释条件拒绝或丢空条目 |
| 完整快照 | 精确对象身份、格式版本、同一切点 S/term/ConfState、正文长度/内容摘要、完整业务控制状态与安全闭包 | 发布后不可修改；不含可直接复用的运行 K/G、截止或设备 ready |

Raft 的无符号位置/任期按固定 8 字节大端 BLOB 表示并检查类型/长度，不能通过有符号 INTEGER 强转截断，也不能用 SQL 浮点计算位置。应用侧使用检查算术，编码顺序和范围查询须有 u64 边界测试。格式魔数、版本及有界长度分别校验；摘要用于发现内容不匹配，不代替事务、认证或防回滚。摘要算法、精确二进制字段号及实现依赖在实现规格固定，不默认为兼容任意未知版本。

初始化必须是显式新集群或合法成员引入流程；正常打开路径发现库不存在、身份不符或编码未知，不自动建一个同身份的空 voter。三节点初始化与 SG 成员恢复的外部流程仍由 18/09 负责。升级不在线自动改写权威格式；支持版本不匹配时先限制该节点，不静默丢字段运行。

## 一条写入口与一次发布

首版采用每库一个串行数据库工作入口；后台快照发布、日志回收也经过它，没有独立数据库维护写者。Rust 运行时的任务超时只结束观察，不取消已交付的数据库操作。关闭入口、等待正在执行的数据库调用返回、结束事务和释放全部连接分别观察；不能凭工作线程回调丢失启动第二个实例。

每项修改均携带 SCM 的原实例、操作身份及不可变内容。处理必要协议批次时检查预期发布修订；不符合即报告条件失配，不在内部换 expected 重试。准备内存视图、编码及空间预算先于事务提交；不能在可靠提交后才发现根本无法表示必需的 Storage 后态而假装 P2 成功。

权威变化采用一次事务：读取当前根并核对前置条件 → 配套条目/快照变更 → 写完整新根/递增发布修订 → 提交 → 更新匹配的 RAM Storage 视图 → 通知准确阶段。任一步失败均保留原操作关联，按 FD 处理。事务成功不表示多数派提交、实际 apply 或所有旧写者已退出。

快照正文与引用可在同一事务内一起写入，因而没有“已公布引用但正文属于另一次未完成文件同步”的窗口。这里将 SCM 的正文可靠保存与引用发布合并为一个原子提交，不伪造先前独立的正文可靠成功；大对象构建在事务外进行。

## 四类权威事务

| 事务 | 本次原子变更 | 不能顺手做的事 |
| --- | --- | --- |
| DB1：Ready 必要保存 | 本周期必要条目、合法冲突后缀替换、HardState 与配套根；无变化则不写空事务 | 不能删除/改写已提交冲突历史；不把 last_index 当 commit |
| DB2：LightReady commit | 在同一最新根上更新新的可靠 Cd；核对日志/快照覆盖，保留当前 term/vote | 不等待下次 Ready 猜测重报，也不拿旧整份 HardState 覆盖最新值 |
| DB3：发布本机快照 | 插入完整新快照、切换 S 引用、保留发布时最新 HardState/必要后缀；可配套压缩已覆盖前缀及更新边界任期 | 不回退 RAM apply，不把本机快照当接收 MsgSnapshot，不自动结束未知动作 |
| DB4：安装所接受快照的持久组合 | 仅真正出现在 Ready 的快照与本周期内核认可条目/HardState，原子替换恢复基线及日志范围 | 拒绝旧快照/仅快进 commit 的分支不安装正文；不能保留内核已丢弃的旧后缀或用快照任期替换当前投票任期 |

DB4 提交后还须更新 Storage 并实际安装同切点业务状态/配置，才满足 P2。DB2 可靠且视图匹配后才能 apply 超过旧 Cd 的条目。完整消费 Ready/LightReady 和真实 apply 的顺序保持 P0—P6，SQLite 完成不直接调用设备派发。

DB3 的慢构建只携带捕获切点和完整正文，不携带可覆盖当前根的旧 HardState。轮到写入口时读取最新根，核验 Snew 仍可合法发布、当前日志/配置关联及捕获的实际 apply 证据；过时优化可无修改放弃。不能因为构建期间普通协议保存前进，就机械退回协议历史；也不能无条件覆盖已更新的 S。所需压缩边界必须由当前 Raft/Storage 契约允许且不超过发布的 S。

## 读取、引用与回收

RawNode 同步 Storage 读取使用已匹配的 RAM 只读视图，不在 S 或未完成 Ready 期间偷偷等待数据库工作线程。视图包含协议必要日志范围、边界任期、最新可靠 HardState 和完整可发送快照；副本 apply 仍使用自己的连续位置与正确 ConfState。

准备新视图在控制临界区之外进行；候选从当前可靠前态加不可变变更构造，数据库事务内能查询到的修改不提前进入可见 Storage。数据库提交后，受保护地安装完整后态，在安装成功前不确认 P2/DB2 完成。旧读者持有安全不可变引用，不能拿裸指针跨替换；引用保护失信是 FD 视图失败，不回滚已经可靠的数据库事务。现有已交付旧消息仍按自己的历史关联处理，旧视图不成为新操作的许可。

首版不允许网络发送任务持有 SQLite 读事务/游标等待远端。需要发送的条目/快照先取受保护的 RAM 引用，数据库短读取结束后才能排队；引用及出站资源有明确预算。完整日志窗口、快照及旧读者的内存成本必须列入支持范围；不能口头写“RAM 视图”却只缓存一部分，并在缺页时绕回 S 内磁盘 I/O。

旧快照/日志只有在完整新恢复组合已经可靠发布、协议不再要求且安全闭包仍完整时才能回收。回收亦走同一写入口，在事务内复核当前引用；旧网络/读者持有的是独立安全内存引用，不延长 SQL 事务。RAM 对象实际回收等待其引用释放，不能用删除数据库行代替对象生命周期证明。压缩日志不删除新快照内的未决动作。

## 资源与失败预算

控制日志积压、完整快照、编码副本、SQLite 事务日志以及旧 RAM 引用分别预算；具体额度保持待配置/测量。新控制工作可在受理前因空间不足被拒绝，但不能拒绝保存已经进入必要协议阶段的事实后仍参与投票。预留不等于保证磁盘永不满；必要保存真的失败时按 FD 立即停止该实例，而不是清旧历史腾位置继续。

快照应在日志/内存硬上限前提前触发，构建预算不足而旧恢复组合和必要写入仍可靠时只放弃本机优化，不自动全组撤权。完整控制闭包超出支持上限时报告明确容量限制，不能截掉未决动作、压成摘要或把未知结果标成完成。该能力边界必须进入后续配置验收；尚未测量的工作负载不宣称支持。

写入成功但通知丢失、数据库调用仍在途、事务明确失败、提交后 RAM 视图失败分别记录。首版不靠自动重试 COMMIT/重做旧批次消除未知结果；停止并收束旧写者后，读取完整恢复组合核对实际结果。可信恢复可以自动重建控制上下文，不恢复旧运行许可；历史失信继续 SG，不自动清库。

## 验证目标与剩余边界

DB01—DB08 均未实现/执行。

| 场景 | 判据 |
| --- | --- |
| DB01：日志后缀/HardState 提交中断 | 恢复为完整旧/新事务，不混分支；已提交历史不被覆盖 |
| DB02：LightReady commit 与实际 apply | Cd 可靠先于超出旧 Cd 的 apply，term/vote 不回退 |
| DB03：慢本机快照遇新 term/vote/新快照 | 最新协议状态保留，过时快照不逆向发布，合法新快照可以推进 |
| DB04：三类收到快照结果 | 拒绝/快进不误安装；真安装的 DB/Storage/apply 各自完成，崩溃恢复新组合 |
| DB05：提交成功丢回调、视图切换失败 | 不假 advance、不重做旧操作，收束后按实际库恢复 |
| DB06：短读、发送引用与回收 | 不跨网络持 SQL 事务；删除旧行不破坏活跃内存引用，引用释放后可以回收 |
| DB07：额度/编码边界及源格式不兼容 | u64 不截断，完整闭包不裁剪，不假初始化空身份；正常资源下有进展 |
| DB08：停写/旧调用迟到、进程崩溃与机器掉电 | 新写者不与旧修改并发，分别核对事务原子性和真实可靠性，不以进程测试代替掉电 |
