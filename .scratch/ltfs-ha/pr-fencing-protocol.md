# 设备层隔离协议候选：持久预留 + 软件纪律

来源票据：[09](issues/09-fencing-deployment.md)。前提由用户在 2026-09-17 给出：生产环境没有可由软件调用的断电/复位手段，没有可用的外部隔离；没有本系统之外的软件访问同一逻辑库。证据见[设备层隔离的实验室证据](fencing-lab-evidence.md)。本文是 09 选项 B 的具体化，与 [18](issues/18-raft-execution-contract.md) 的阶段（H1 隔离协调许可 K → G 首次确认 → H2 恢复 → H3 服务）对接，不改变 18 已裁定的任何条件，只回答"K 许可下的指定隔离动作是什么、怎样算完成"。

## 对 03 的修订

03 原文："外部 fencing 是自动接管的前置条件，使用经验证的电源/PDU、虚拟化管理面关停或覆盖全部设备路径的 fabric 隔离。"三类手段在本部署前提下都不可用。修订为：

> 自动接管的前置条件是**经设备回读确认的隔离**。合格手段在原有三类之外增加第四类：对受管逻辑库内每一个支持持久预留的设备完成抢占，并逐设备回读确认旧键已不在注册表、持有者为本轮的键。任何设备无法确认时不自动接管，转人工确认（选项 C）。

03 的其余内容不变：受管设备组独占、旧节点不自动抢回、本地锁或租约过期不算隔离证明、SSH 停服务不算隔离证明。

**已接受的缺口**（用户已知）：PR 挡不住在旧节点上主动重新注册并抢占的软件。由运维前提覆盖：受管节点上不运行 IBM LTFS、ITDT 等会操作预留的工具；本逻辑库不对外部主机开放。本系统自身绝不自动恢复预留。

## 键

8 字节，大端：

| 字节 | 内容 |
| --- | --- |
| 0 | 固定前缀 0x4C（'L'），区别于 IBM LE 的 0x10/0x40/0x60，便于现场识别是谁的键 |
| 1 | 节点号（三节点内的稳定编号，来自 Raft 成员配置） |
| 2–7 | 本轮执行资格的代数，取 18 的接管轮次；48 位 |

性质：同一节点重新当选也得到新键，所以"旧实例、旧轮次"的键天然是陈旧的（18 的 TG05）。键不含秘密，任何人可读；安全性来自设备按注册表拒绝命令，而不是键不可猜。

## 接管：K 许可下的隔离动作

对逻辑库内每个驱动器 D（换带器见后）：

1. `PR IN READ KEYS` 与 `READ RESERVATION`，记录现状（旧键、持有者、generation）。读不到或命令失败 → 该设备"无法确认"。
2. `PR OUT REGISTER AND IGNORE EXISTING KEY`，注册本轮键。
3. 按现状分支：
   - 有持有者且不是本轮键 → `PREEMPT AND ABORT`（类型 Exclusive Access，service action key = 持有者的键）。若注册表里还有其他陈旧键，逐个 PREEMPT 移除。
   - 无持有者 → `RESERVE`（Exclusive Access）。
4. **回读确认**：`READ KEYS` 只含本轮键；`READ RESERVATION` 的持有者是本轮键、类型 Exclusive Access；generation 相对第 1 步已变化。三者都满足才算该设备已隔离。
5. 全部驱动器确认后，向 18 报告"隔离动作完成且已回读"，这是建立 G 的必要条件之一，不是充分条件（18 的其余门控照旧）。

任何一步结果未知（超时、传输错误）：不重试抢占链的后续步骤，先重新执行第 1 步读现状，再从合适的分支继续；连续无法确认则该设备判"无法确认"，整体不自动接管。

**类型为什么用 Exclusive Access**：Write Exclusive 仍允许旧节点读和定位，会移动磁带位置；本系统要求旧节点的任何介质命令都被拒绝。

## 持有期间的纪律

当前执行者在每条设备命令的结果上检查以下信号，任一出现即按 18 的 HX 处理（停止未发出的命令、冻结卷、不再发任何 PR OUT）：

| 信号 | 含义 |
| --- | --- |
| UNIT ATTENTION 2A/03 Registrations preempted、2A/04 Reservations released、2A/05 Reservations preempted | 别人动了我的注册或预留 |
| 状态 RESERVATION CONFLICT | 我已不是持有者 |
| UNIT ATTENTION 29/xx（上电、复位） | 预留可能已丢失，且磁带位置不可信 |

收到 29/xx 后若仍是合法执行者，恢复路径是重新走一遍"接管"的 1–4 步（读现状、注册、预留、回读），再按 D02 恢复卷；不允许跳过回读直接继续写。

**写入前与提交前自检**：追加文件写第一个字节之前、提交动带之前、提交的屏障之前，各对该驱动器做一次 `READ RESERVATION`，持有者不是本轮键则停止并冻结卷。前两处失败时介质未被触碰；屏障前失败时索引已写，按 04 的"结果未定"处理。只在屏障前检查是不够的：实机实验里同节点旧轮次的实例（设备不会拒绝它，因为是同一个发起方）在屏障前才被拦下时，数据和两份索引已经落带。这把"预留在不知情时丢失"的窗口限制在一次追加之内。代价是每次追加与提交各多一到两条命令，数值影响留给 06 的测量。

## 换带器

IBM LE 不预留换带器；TS4300 换带器是否支持 PR 未知。协议：接管时对换带器尝试同样的 1–4 步；设备以 ILLEGAL REQUEST 拒绝 PR 命令时，记为"换带器不支持预留"，不算"无法确认"。此时旧节点仍可能移动磁带。缓解：它无法把磁带从已被新 Leader 预留的驱动器里取出（卸带需要驱动器命令）；新 Leader 在每次移动前后核对库存（现有 `MediumChanger` 已做移动结果核对），发现不一致按 37 的库存异常处理。

## 正常移交与释放

- 计划切换（18 的排空）：旧 Leader 排空后 `RELEASE` 并注销自己的键，新 Leader 仍执行完整的 1–4 步，不因"对方说已释放"而省略回读。
- 节点退出受管（维护）：注销键；不使用 `CLEAR`，以免清掉当前执行者的注册。
- 异常遗留：所有节点都停了之后留下的预留，由下一个合法执行者按接管流程抢占，不需要人工清理。

## 人工出口（选项 C）

以下情形不自动接管，报告不可用并给出原因：任一驱动器无法确认；回读发现注册表里反复出现非本轮键（说明有东西在抢回）；PR 命令在驱动器上不被支持。运维确认旧节点已停后显式授权，新 Leader 仍先执行 1–4 步。

## 候选验证 PF01—PF10

- PF01（实验室已观察）：抢占后旧路径的介质命令先得 2A/03 后得 RESERVATION CONFLICT，写入不落带。
- PF02（实验室已观察）：旧路径重新注册并抢占可以抢回。对应"回读发现反复出现非本轮键 → 人工出口"。
- PF03（模拟器已通过，实机 LIO 已通过正例）：接管 1–4 步的正例；抢占命令传输失败时 `fence` 返回错误而不是接管，重新从读现状开始可以完成。
- PF04（部分通过）：`reservation::ownership_lost` 把 2A/03—05、RESERVATION CONFLICT、29/xx、自检失败统一判为失去资格；`retry_unit_attention` 不再吞掉 2A/03—05。实机 LIO 上被抢占的旧持有者先得 2A/05、后得 RESERVATION CONFLICT。29/00 目前仍会被定位类命令的重试越过，由写入前自检兜底；上层（ltfsd）收到信号后的整组冻结尚未实现。
- PF05（模拟器已通过）：驱动器复位清掉预留后，追加在写第一个字节之前以 `OwnershipLost` 失败；提交中途预留消失时提交失败、卷冻结、已发布视图不变；自检失败后不重新预留。
- PF06（模拟器与实机 LIO 已通过）：同一节点新轮次得到新键，注册新键后预留跟随新键；旧轮次实例的自检失败，什么也不落带。设备本身不会拒绝同一发起方的旧实例，这一条完全靠自检。
- PF07（部分通过）：不支持 PR 的设备 `fence` 返回 `Unsupported`（模拟器）。实验室 LIO 的换带器支持 PR 并可被隔离，不代表 TS4300。库存核对部分未做。
- PF08（需真机）：LTO-8 驱动器对 Exclusive Access、PREEMPT AND ABORT、REGISTER AND IGNORE 的支持与回读内容；TS4300 换带器是否支持 PR。
- PF09（需真机）：驱动器断电/复位后预留是否保持；APTPL 是否可用。
- PF10（需真机或可注入延迟的环境）：PREEMPT AND ABORT 时旧节点有在途 WRITE，缓冲数据是否落带；接管后 D02 的结论。

## 实现状态（2026-09-17）

`src/scsi/reservation.rs`：`ReservationKey`、`read_status`、`fence`（读现状 → 注册 → 再读 → 抢占/预留 → 清陈旧注册 → 回读确认）、`verify_holder`、`release_and_unregister`、`ownership_lost`。`LtfsVolume::set_reservation_guard` 启用三处自检。CLI：`pr-status`、`pr-fence --node --round`、`pr-release`、`ltfs-write --guard NODE:ROUND`。模拟器支持多发起方（`SimLibrary::drive_as`）、Exclusive Access 语义、按发起方投递 2A/03、`reset_drive`。`tests/sim_fencing.rs` 9 项。

实机（TAPERS，内核 LIO，两条路径）用 tape-rs 自己的实现走完：空闲设备取得预留 → 同节点换新轮次 → 另一节点抢占接管 → 旧持有者被拒 → 新持有者读写 → 计划移交释放 → 原节点新轮次重新确认。实现中发现并修正的一处：注册新键之后必须重新读现状再决定分支，否则同节点换键时会试图抢占自己。
