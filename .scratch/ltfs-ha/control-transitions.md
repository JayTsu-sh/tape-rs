# 控制状态转换、提交与外部交付契约草案

关联：[执行授权票据](issues/18-raft-execution-contract.md) · [控制提交依据](issues/20-control-authorization-evidence.md#answer) · [资格刷新](authority-refresh.md) · [维护交接](maintenance-handoff.md)

状态：将 CG/TG/FG/HK/PS/MR/MH 已接受约束整理为转换契约，未实现/执行；不新增产品策略，不选择 Raft 库、持久化格式、字段编码或线程模型。表中的转换是逻辑边界，允许满足同样前置条件的原子合并，不要求每行各写一条日志。

## 三层分别负责什么

| 层次 | 检查和结果 | 禁止混入 |
| --- | --- | --- |
| 提案受理与证据核验 | 当前合法协调身份、请求范围、实际外部事实及预期控制前态；形成带关联及条件的控制命令 | 受理成功不等于提交，不提前授予外部派发权 |
| 已提交命令的状态机应用 | 只依据同一已复制前态、命令及协议规定的有序元数据作确定性转换，输出应用结果及位置 | 不读取本机墙钟、当前本地 Leader 布尔值、实时设备或远端证据链接来决定不同副本是否应用；不执行隔离、原始 CDB 或外部重试 |
| 当前执行实例的派发门控 | 确认所需转换已在本机实际应用，复核当前轮次/实例、资格时效、现实隔离和资源条件，才允许相应动作交付 | 不凭历史授权、提案返回、日志重放通知或过期回调开放 K/G；不把逻辑授权当物理屏障 |

本机时效是运行门控的一部分，不是各副本自行按本地时间修改已复制状态的规则。确需记录到期或终止时，由具备相应资格的路径提交明确关联的转换；失效实例先本地停发，不能等这条记录成功。Follower 的正常 apply 与其禁止设备执行并不矛盾。

所有外部证据在提案受理或派发前核验；状态机只处理随命令明确表达的事实声明、关联和可确定性检查的内容。若采用摘要或引用，实际取证及来源验证不得在 apply 时依赖每个节点各自的网络结果。声明被提交不证明现实条件永久成立。

## 控制请求的条件与关联

逻辑请求须能表达：集群与受管配置关联、目标控制对象及其代际、所属接管/维护过程和实例、操作类型、预期前态、请求关联及必要事实引用。逻辑版本及前态须可识别“状态曾改变后又看似相同”的情况，不能只比较一个 ready 值。具体版本粒度与编码仍待实现设计。

依赖前态在排队期间改变时，应用层返回明确的条件不成立结果，不把旧请求自动改绑到最新轮次后执行；处理结果是状态机应用结果，不是让 Raft 撤销或跳过已提交日志。协调方须重新读取并核验，必要时形成新的、有当前授权的请求。

请求关联约束低频控制转换，不是上传回执。相同关联携带不同目标或内容应作为冲突拒绝，不能默认为重试。已能证明处理过的相同请求只返回原结果或可核验的当前结论，不创建第二轮授权；无法证明历史结果时报告未知/需要核对，不能因去重缓存缺失就自动重做。此处不承诺永久请求历史查询或外部 exactly-once，安全防重用及快照保留要求见后文。

## 转换与外部动作对应表

“复制前置条件”列只指应用时能从已复制前态及命令检查的条件；现实有效性另由受理/派发门控检查，不能让表中的记录替代硬件证据。

| 逻辑转换 | 复制前置条件及状态结果 | 提交并在本机应用之后 |
| --- | --- | --- |
| 建立新接管轮次 | 配置及预期当前轮次匹配，新轮次/实例关联不复用；更新当前轮次，旧授权记录显式结束或标为被取代，保留旧执行者及未决动作 | 只允许继续本轮控制处理，不直接授予 K/G；旧节点不一定知晓变化，仍需外部隔离 |
| 登记隔离动作意图 | 轮次、目标、动作类型及范围匹配，相关限制可表达；保存待核验动作关联，不默认“未派发”或“已成功” | 按 HK 取得有效 K 及覆盖该意图位置的首次 safe 确认后，当前协调路径才可派发指定动作；apply 不派发 |
| 记录动作观察/核验结论 | 匹配原动作身份、目标和事实版本；区分观察、结果未知、动作收束及隔离事实，不以单个成功码清除其他未决项 | 当前流程继续核验或准备后继转换；旧动作的迟到事实可保留，但不能直接成为新轮次授权 |
| 建立设备执行授权 G | 当前轮次/实例/配置及所需隔离核验关联匹配，授权未被终止或取代，记录范围与依据一致 | 仍须 RQ 的首次确认、当前安全前提及 HK 的 K→G 交接检查才进入 H2；各卷按 R1—R5 开放服务 |
| 结束指定轮次/授权 | 必须指定原轮次/授权身份；已结束可返回一致结论，不把迟到结束转换套到新 G | 不产生设备命令，不证明旧执行者物理停稳；本地失效时早已停发，不等待本转换 |
| 在线恢复候选限制 | 当前限制及相关动作集合/事实版本匹配，目标与配置一致；按 FG/UF 记录可解除的指定限制，其余限制保留 | 仅恢复该项候选资格的控制前提，仍需现实条件；不自动参选、回切、扩大设备权限或解除未授权的物理隔离 |
| 记录维护事实并完成在线收束 | 关联 MR 的维护过程、当前实例及实际已应用控制历史；明确处理原限制与全部相关未决项，不离线覆盖旧记录 | MR 在首次选举前的外部维护准入不依赖本条先提交；当选后本条及必要控制转换完成、外部维护派发封闭并交接核验后，才可进入新 K/G |
| 登记计划切换及终止旧执行权 | 请求、受管范围、当前轮次与预期维护状态匹配；控制记录不承载逐上传排空进度 | 仍按 PS 核验本地排空及目标，先关闭旧 G 再触发转移；请求已知/未知结果均不自动重开旧许可。具体转移 API 与持久化顺序仍待集成 |

纯粹读取控制状态、处理已有观察或提交本地停发事实，不以已经具备 G 为前提，否则无法从无设备授权推进恢复。新外部动作则必须走各自资格路径；MR 的带外停服维护例外不能被扩展为任何 Follower 都可发外部命令。

## 三个重点交错

**旧轮次授权晚到。** A 的建立 G 请求先提交，之后 A 已本地失效但该命令此时才 apply：状态机仍按有序历史处理，本地门控不因此复活。如果新轮次转换已在该副本更早应用，则旧请求的预期前态不匹配，不能覆盖新轮次。两种顺序都不允许依据回调直接打开 I/O。

**旧隔离结果在新轮次返回。** 先匹配原动作并保存可核验事实；新的协调方若需要写入当前结论，重新读取状态并构造符合当前前态的记录，不改变外部事实的原始归属。相互矛盾的观察保留来源和关联并标为待核验，不能用“最后到达者覆盖”抹掉风险。冲突或迟到危险不能静默丢弃：若现实表明当前隔离失效，当前实例按安全门控立即停发，再处理控制记录；不是让任意旧回调直接修改新 G，也不是等记录提交才处理危险。

**意图已应用、派发或响应未知。** 已有意图不等于外部动作已经执行，缺少完成记录也不等于没有执行。恢复方核对关联及实际效果，不在日志恢复时自动“补发”。即使某适配器将来提供幂等接口，也须核对其真实语义，不能由控制请求去重推导设备端只执行一次。

## 快照、结果保留与未决效果

快照须保留当前配置/轮次关系、必要授权终止或防复用依据、仍影响安全的旧执行者和全部未决外部动作、尚未收束的维护交接。不能因为进程重启、日志压缩或任意保留期限，就把未知动作变为不存在或让旧请求重新成为合法新请求。

无需永久保存所有已终结控制请求的完整正文，但回收方案必须证明旧请求不可能被误当成新权限请求，并保留当前安全判定所需的事实。具体去重窗口、单调代际/前态校验、终止信息保留和证据回收算法尚未选定，不能先删除再假设可从磁带重建。安全语义与存储优化分别验证，不引入上传历史回执。

### 同一切点的快照内容

快照的逻辑内容须来自同一已应用位置 S，不能把 S 时刻的当前授权、S 之后的终止边界与 S 之前的未决动作拼成一份不存在的状态。实现可以采用冻结视图等机制，但选择及成本尚未确定。与之配套的 Raft 快照位置、任期和成员配置元数据由所选库协议确定；业务快照不取代节点仍须可靠保存的当前投票、任期及其他协议状态。

| 信息类别 | 最小保留语义 | 何时可减少明细 |
| --- | --- | --- |
| 当前控制对象 | 受管配置及代际、当前接管/维护关联、授权和候选限制；对象间关联一致 | 转为历史后也须先判断是否被以下安全信息引用 |
| 拒绝旧权限请求的依据 | 能拒绝已结束、被取代或跨实例复用的请求；包含所需代际、预期前态、终止信息或请求内容关联 | 有语义等价且可靠持久的拒绝依据替代，恢复及请求重试仍不会创建第二份权限时 |
| 未决外部动作 | 原动作/物理目标/所属实例、可能影响范围、未知或冲突状态及必要证据关联 | 实际影响已收束且不再被任何安全判定依赖；仅轮次结束、超时或日志已压缩均不够 |
| 当前安全判定所依赖的证据 | 支持当前隔离、候选限制或维护交接的事实及可核验来源；保留必要关联链 | 替代证据已核验并完成所需控制转换，且删除旧证据不会令剩余引用无法核验时 |
| 已终结且无安全引用的请求结果正文 | 可用于精确返回历史结果，但不是永久保存承诺 | 拒绝旧请求的持久依据和必要动作关联已经保留；正文回收后只返回可证明的结果，不能猜测历史成功/失败 |

“证据关联链”包括理解被引用事实所需的目标身份、配置映射、动作归属及适用范围。若使用外部链接或摘要，摘要本身不保证正文仍可取得，更不证明隔离仍有效；不能把仅有失效链接的快照当作完整安全证据。必要证据不可核验时按既有受限策略处理，不通过本机缓存或人工批准补出事实。证据载体和保存位置仍待实现/部署设计。

### 防复用与结果回收判据

回收前对每一类能建立或扩大权限的旧请求，必须能回答：**仅凭回收后保留的状态，重试、迟到、跨节点恢复或进程重启时，为什么它仍不能被当成新请求执行？** 不能回答则保留必要终止信息、请求内容关联或前态依据，不以保留天数代替这份证明。

允许以逻辑代际和已关闭区间压缩明细，但这只是待实现的表达候选：

1. 边界必须属于明确的集群/受管范围及已证明有序、不可复用的对象序列，不能用磁带 generation、单独的 Raft term、任意请求编号最大值或墙钟充当全局关闭边界。K 阶段退出不等于同一接管轮次的 G 已终止，不同权限种类不能共用未经证明等价的关闭含义。
2. 若表达“该边界以前均不可再授予权限”，须证明覆盖区间内没有仍允许使用或状态未知的空洞；不能看到更高编号已结束，就推断较低编号全已结束。暂不能连续覆盖时保留分段或必要单项信息，不预设一种具体编码。
3. 关闭权限的边界与外部动作的收束边界分别维护。一个授权可已结束，但它关联的外部动作仍在未决集合；压缩授权历史不得删掉该动作及事实补录所需的归属。
4. 使用旧上下文申请权限应被拒绝，不代表该上下文的迟到事实也应被拒绝保存。仍有安全关联的动作观察按原身份核验；相互冲突的事实不能因关闭边界而消失。
5. 相同请求关联与不同内容的冲突识别，只有在旧请求已被更上层的持久拒绝条件完整覆盖后，才可不再保留原内容关联；否则必须保留相应依据。请求结果缓存被逐出不是未知请求重新获准的依据。
6. 边界前进或安全记录回收须能从相同复制状态确定地重建。各副本不能依据不同本地时钟或缓存压力，单独改变权限判定。纯结果展示缓存可以有不同驻留内容，但不能造成授权接受结果不同。

**示例。** 旧轮次 A 的 G 已结束，新轮次 B 已建立，而 A 发出的隔离动作 X 仍不知道是否会迟到影响 B。快照可以保留对 A 的紧凑拒绝依据，但必须继续保留 X、目标及所需证据；A 的旧授权请求不能复活，X 的迟到结果仍可进入核验。如果 X 后来被证明收束，但当前安全判断仍引用其隔离证据，也不能立即删除全部证据正文或关联。

### 发布、回收与恢复顺序

[控制存储恢复草案](control-storage-recovery.md)将以下原则细化为首版完整控制快照加日志重放、可靠 commit 先于实际应用、本机/接收快照分别发布及启动恢复屏障；[SQLite 事务映射](control-store-transactions.md)现将完整闭包与发布元数据置于同库事务，不改变确定性 apply 或未决效果保留。实际 SQL/编码与存储环境仍需验证，不将抽象顺序当成已有实现。

1. 从同一已应用切点取得一致状态及其必要安全信息，按所选实现验证编码完整性、身份、位置和引用关系；不能只用文件校验和代替语义一致性检查。
2. 新快照及恢复所需元数据达到所选存储/库要求的可靠保存和可恢复发布条件后，才回收其已经可靠覆盖、且协议允许回收的旧日志或旧快照。若快照仍依赖某些外部证据正文，回收也不能同时破坏这些依赖。具体落盘屏障和发布算法待实现验证，不声称一次 rename 已足够。
3. 构建、保存或发布中断时，只使用能证明完整且配套的恢复组合；不混合新快照内容与旧元数据，也不因空间压力自动删除唯一可信恢复依据。
4. 可信的较旧快照与完整必要日志可以按支持的协议重放到所需位置；这不同于将整个控制目录回滚后继续使用旧身份。恢复须保留正确的 Raft 协议状态，无法信任历史连续性时按 SG 受限处理。
5. 重放只重建控制历史。当前实例的 K/G 时效、维护派发许可和设备 ready 不由快照自动恢复；按正常启动/新轮次或 MR/MH 路径重建运行资格，不能因为快照中存在 active 授权便开始执行。

**容量边界。** 未决动作和必要证据的数量不保证固定上限。压缩重复观察或回收无安全引用的结果可以减少成本，但不能保证解决任意积压；空间压力下仍不能删除未知效果、伪造成功或回滚拒绝边界。资源预留、告警和新增控制工作准入的具体策略另待细化，不在本节隐式规定自动全组撤权或新增每文件持久化开销；已发生必要控制持久化失败时仍按既有 SG/资格失效规则处理。

### 快照与回收候选验证

**CS01—CS08，均未实现/执行。** CS01：并发 apply 与快照构建只得到同一切点状态，不漏未决动作；CS02：低代际仍可用/未知、高代际已结束时不错误推进连续关闭边界；CS03：旧授权已压缩但动作未决时，旧权限请求拒绝、迟到事实仍可核验；CS04：正文/结果缓存回收后，同请求重试或不同内容冒用不产生新权限，未知历史结果不猜成功；CS05：仍被当前安全判断引用的证据不可被孤立回收，失效外链不被当有效证据；CS06：快照保存/发布各阶段中断，不先丢掉唯一可信恢复组合；CS07：可信旧快照加日志可重建控制状态但不恢复运行许可，失信目录回滚不当正常重启；CS08：必要状态积压及容量压力不靠删除未知效果解决，完整安全条件成立的恢复正例能推进而非永久拒绝。
