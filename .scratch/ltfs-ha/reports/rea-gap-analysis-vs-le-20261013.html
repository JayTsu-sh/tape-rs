REA 与真实设备及 tape-rs 实运行 GAP 报告

日期：2026-10-13　分支：ltfs-recovery-ibm-interop　真实设备：10.131.7.209、10.131.7.220

证据规则：本版只有在真实设备上实际运行并获得响应的项目功能，才标为已验证。REA 和源码静态差异只标为候选 GAP；未运行的 tape drive 功能不推断结论。

1. 最终摘要

当前项目已经在真实 `.209` TS4300 的空闲 changer `/dev/sg5` 上成功运行 tape-rs inventory --device /dev/sg5 --no-drive-scan，返回码为 0。项目实际发出的 MODE SENSE 和 READ ELEMENT STATUS 均成功，解析出的地址 map、库存、barcode 和 drive serial 与原始 SCSI 响应及 `.220` 管理面结果一致。

因此，changer inventory/map 不是当前环境中已证实的 GAP。项目的 tape drive 状态、READ POSITION、LOG SENSE、MAM、READ(6)、大文件拷贝性能和 LE/tape-rs 命令序列仍未完成真实项目运行验证；这些项保留为未验证，不能称为已确认 GAP。

项目结果
大文件只读拷贝尚未完成。当前 LTFS 挂载没有可见的大文件，且访问路径曾阻塞；不能写带造数据，也不能中断活动 LE 会话。
LE 与项目实际 CDB 对比尚未完成。需要 drive 空闲窗口，在同一介质上分别运行 LE 和 tape-rs，并记录 SG_IO 的 opcode、CDB、transfer length、resid、sense、耗时。
已完成的项目层命令对照changer 的 MODE SENSE/READ ELEMENT STATUS 已由项目真实发出并成功解析；这不等价于 tape drive 性能验证。

性能实测必须记录文件大小、冷/热缓存、起止时间、吞吐量、READ(6) 次数、READ POSITION/LOCATE/SPACE、LOG SENSE、filemark/EOM 以及每条 SG_IO 的状态。只有相同介质和相同条件下完成 LE 与 tape-rs 两组运行，才能确认底层命令 GAP。

6. 下一步真实验证顺序

  1. 确认 `.209` LE 正常退出、FUSE 卸载，并再次核对所有 `/dev/sg*` holder。
  2. 对空闲 drive 运行项目 status、position、Inquiry/VPD、LOG SENSE、READ ATTRIBUTE；保存 raw CDB/响应/sense。
  3. 选择已有真实大文件和明确的只读介质，运行项目 READ；再运行 LE 读取，记录吞吐和命令序列。
  4. 用同一批证据逐项更新本报告。没有对应设备响应的项继续保持“未验证”。
  5. LOAD/UNLOAD/MOVE、写带、MAM write 另行确认后执行，不纳入默认只读验证。

7. 结论

本轮已完成“当前项目 changer inventory 在真实 TS4300 上运行并与 LE/管理面交叉核对”，该功能目前没有已证实 GAP。尚不能把这个结果扩展为整个项目通过；tape drive 功能和大文件性能必须在设备空闲窗口中由当前项目实际运行后再判断。
