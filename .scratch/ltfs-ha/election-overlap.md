# 竞选内核中间态与可发布领导资格

关联：[研究 35](issues/35-election-invalidation-overlap.md) · [原 EG](issues/18-raft-execution-contract.md#已裁定接管条件前置与执行就绪复核) · [控制推进](raft-rs-binding.md) · [网络边界](raft-network-boundary.md)

状态：依本轮自动接受授权采用的受控适配方向，未修改 raft-rs、运行模型或操作设备。本文**明确细化**“不产生不合格 Leader”的可观察边界：禁止对外发布/服务不合格的新领导资格，不承诺与故障重叠的库调用连内部角色赋值都不会发生。这是本次记录的选择，不能倒写成原用户已明确规定内部瞬时语义。

## 选择及代价

固定版 raft-rs 的一次获票处理可以在内部完成预选转正式竞选，或正式获胜、Leader 赋值、追加空条目及生成 Append。已有外层检查不能在这些内部步骤间抢占；事后发现失效也不能把发生过的 term/vote/日志变化回滚。

首版采用：所有入口前检、调用产物暂留、返回后复核、失配后合法退回，且必要历史照常保存。不选未经授权的库 fork，不依赖 panic/unsafe 打断调用。新增取舍是失效重叠时可能有内部角色/日志变化和额外控制处理，但它不能成为临时可服务的控制 Leader，也不能只靠关 G 就继续使用其领导输出。

若未来要求连内部角色也绝不变化，则需要另一份库内同步设计和授权；一次 bool hook 同样不能自动证明源端获知瞬时的保证。本文不把这种更强要求说成不可实现，只是不宣称当前外围方案满足它。

## 事件与状态展示

区分 F（来源获知）、X（竞选失效代次发布）、I/O（一次内核调用开始/返回）、M（库内角色变化）、A（适配层接受合格新领导资格）、N（消息越过实际网络交付边界）。

- X 在 I 前已发生：先处理已知 B/Bc 失配，不能先交付赢票响应再补处理。
- I 与 F/X 重叠：M 可能发生，必须保留真实观察；调用返回后的检查不能声称 M 从未发生。
- M 不等于 A：原始 role、SoftState 或库日志不能被路由、控制业务、RQ、计划转移和 K/G 建立直接用作领导资格。
- A 仍不等于设备执行就绪：后续 CG/HK/RQ、隔离及卷恢复不省略。
- F→X、最后核验→N 的窗口分别验证；不能将来源获知重新定义成拿到 S 锁之后，也不能把软件输出入队当网络已交付。

运维诊断允许展示“库内部角色”及其尚未接受/已失效状态，但正常服务发现和业务入口只展示被适配层接受、仍符合相应服务前提的领导资格。不隐藏诊断事实，不以两个名字包装一个实际仍在服务的不合格 Leader。

## 一次竞选相关调用的完整处理

1. **进入前。** 唯一 RawNode 推进者在无未完成 Ready 的合法切点核对 Q/V/B、Bc、必要证据和未处理失效。未知/不合格不发起新竞选；自动、显式和 TimeoutNow 保留已定适配及 term 特例。对其他节点的合法投票/复制仍处理。
2. **调用中。** 不并发修改 RawNode，不抢夺其可变访问权。消息、角色通知及业务可用状态不被另一个任务直接取走发布；库内日志只作诊断，不触发 K/G 或设备操作。
3. **返回后。** 先按原竞选身份与 Bc 再核验；预选赢票引起的正式竞选也属于同一检查责任。失配的新 Candidate/Leader 产物不得以较新的健康 B 重新绑定。
4. **无旧 Ready 未完成且尚未领取新 Ready 时。** 对已失效的 PreCandidate/Candidate 或本次新产生但未经 A 接受的 Leader，按真实当前 term 通过合法公开退回路径成为 Follower，再取得 Ready。保留同 term vote 和日志，不自行删除自动空条目或回写旧任期。
5. **失效发现时已有 Ready 未完成。** 先隔离相关竞选/新领导产物，继续必要保存、快照安装、实际应用和 advance；到合法切点处理退回。存储/应用失败按 FD 出口，不伪造 Ready 完成来退位。
6. **合格分支。** 只有原竞选关联、当前必要资格和正常 Raft 结果都成立，才可接受 A；A 的发布及后续业务/输出还须绑定精确实例/竞选代次，不能仅返回一个 raw role 布尔值。其具体原子发布与网络交付组合仍是实现验证责任。

有证据已经被接受的现存 Leader 与本次未经接受的新 Leader 分开。前者遇局部故障继续按原分层规则处理，不因任意卷满/FUSE 异常就退位或清空正常复制输出；后者不能借此例外留在后台提供控制服务。丢失领导权、必要控制状态失信及当前 K/G 失效仍执行各自原政策。

## 输出分类与持久化

| 产物 | 失效竞选的处理 |
| --- | --- |
| 本节点原竞选未交付 Vote/PreVote 请求 | 按原竞选身份阻止发送和后续重试；不能重贴新 Bc |
| 未经 A 接受的新领导 Append/Heartbeat/领导服务产物 | 保持隔离，不因位于 Ready 可提前发送组就旁路；两类 Ready 消息、LightReady 及已排队任务都纳入 |
| 给其他候选者的合法投票响应、Follower 复制/快照响应 | 继续按真实协议状态、持久化与网络规则处理，不与本节点失效竞选输出一起全删 |
| HardState、entries、committed/apply 义务 | 独立保留；输出被丢弃不取消必要保存及应用，也不允许回滚 term/vote/commit |
| 已交付的请求及对端可能产生的投票/任期变化 | 不声称撤回；迟到响应按当前 term/role 合法处理 |

“产物暂留”只增加内存/队列的受控阶段，不增加一次磁带提交或逐文件共识。输出分类须记录来源调用与竞选身份，不能只根据发送时 raw role、单个消息类型或数组位置猜测。对未知归属的自我领导产物保持隔离并核对，但不能把未知变成任意删除合法协议响应的理由。

## 验证目标及完成边界

以下 EA01—EA06 对应主文，研究报告 EO01—EO06 另保留；均未实现/执行。

| 场景 | 必须检查 |
| --- | --- |
| EA01：已发布失效后各入口到达 | 自动/显式/转移/赢票不能继续旧竞选，健康投票复制仍可工作 |
| EA02：预选/正式赢票内部与失效重叠 | 如实记录 M；不发布不合格 A/N，合法退回，不回滚必要历史 |
| EA03：领取 Ready 前后及保存/advance 期间失效 | 区分可立即退回与须先收束周期，两类 Ready/LightReady 不漏隔离 |
| EA04：旧输出、健康 ABA、异步取日志完成 | 原身份不换绑；正常协议响应不被全丢，已发事实保留 |
| EA05：无候选与正常新选举 | 无候选不提供临时控制 Leader；合格候选满足 quorum/log 条件时可被接受并进入正常接管 |
| EA06：A/N 与现存 Leader 的故障范围 | 旧有效 Leader 的局部故障不误套失败竞选；当前服务前提及真实交付窗口分别验证 |

该候选收敛 EG 的产品可观察边界及固定版外围处理路径，不代表 A/N 原子发布、完整输出来源标注或所有回调入口已经实现。仅有调用后检查仍不足以证明网络交付竞争，故保留相应缺口；18 claimed、09 阻塞，未启动总 spec。
