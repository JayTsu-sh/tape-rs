# 续期逻辑接受与证明可见的细化候选

关联：[原始 QG/RQ 裁定](issues/18-raft-execution-contract.md#已裁定持续资格的本地时效与过期不复活) · [细化审计](issues/31-renewal-contract-refinement.md) · [前轮分析](renewal-time-evidence.md) · [整体许可状态](permit-publication.md)

状态：依自动推进授权采用的稳态续期逻辑候选，具体依据与条件证明见 31。未实现、未运行模型，不代表时钟/原子容器/快速撤销或完整 18 已完成。本文明确修正前轮助手对接受点的过强固定，不改变期限内证据要求、原 t0、终止不可逆或外部 fencing。

## 修正的是接受点，不是过期后开门

18 原裁定要求在期限内接受有当前上下文和新鲜性依据的多数派证据，并明确原子更新待设计；并未要求所有实现都以最后一次证明发布 C 作为接受点。29/30 对未证明候选的否决是必要的，但将“P 必然只是无意义登记，C 才能是接受”提升为唯一产品语义，会排除本应接受独立细化审查的方案。

本候选以**经后续证据证明合格的 P**作为成功续期的逻辑接受点，C 仅使该证明对读者可用。并非任意 P 都接受：若实际 P 已跨旧截止、后采样无法证明及时性、证据不全、前态失配或终止获胜，都不允许发布可用续期。证明未可用时不提前放行新期限；成功终止永不被迟到证明覆盖。

如果某条轨迹中没有及时的合格 P，仅仅无人写 Terminal，也不能延长许可。因此新候选不是“只要到期处理没运行就可以续期”，也不是“截止前开始请求就足够”。网络请求/实际 apply 尚在等待不具备发布 P 的前提。

## 顺序对象与读者返回值

[组合顺序的来源上界细化](permit-call-sequence.md#有期限的来源证据也必须纳入检查)补充本文 D/N 的使用：原 RQ 期限公式不变，但各层实际可用截止 U 还受自身必要证据上界限制。同轮成功续期须 newU>=oldU，P/W 证明早于原可用截止，Pending 仅使用旧证据绑定；否则不能保证下文读者的保守性。这不要求 C 早于旧截止，真实故障仍立即按适用范围停权，局部资源上界不并入共同 G。
抽象状态仍是同一实例/轮次的有效许可与截止点，以及不可逆终止。定义两个不同操作：续期在原期限内接受合格新证据；终止结束精确许可。查询/派发检查只返回**当前动作是否有足够依据**及其保守可用截止，不承诺显示精确最新抽象 deadline。

这个查询约定十分重要：证明尚不可见时，按 oldD 提供较保守的可用区间，不能向外断言“绝无更早发生的逻辑续期”；证据不足时可以不派发。若流程要报告“本轮已终止”，则须确立对当前许可的终止，而不是先返回终止再发现条件更新输了。

对 Pending 超过 oldD、尚无可用证明的情况，允许保守终止本轮。即使模型后来能证明 P 原本及时，终止一旦成功也必须保留：后续确认失败，该失败续期可排在终止之后解释，不强行把失败分支的 P 映射为成功接受。正常没有风险且证明及时可用的路径应能继续，不把永久拒绝作为实现。

## 最小具体状态

| 状态 | 必要关联与读者解释 |
| --- | --- |
| A：当前已证实许可 | 原许可身份、修订 r、截止 D、当前资格/范围；读者核验当前时间及其他门控 |
| P：待证明的条件续期 | 精确原 r/许可、oldD、证据期限 E=t0+T、候选 N=max(D,E)、完整非时间证据及不可复用 P 身份；未有可用证明时不能使用 N |
| C：有证书的续期描述 | 精确 P 及其发布后时间样本、上下文/证据关联、N；证书证明历史接受条件，不保证读取时 N 尚未过去 |
| X：精确许可已终止 | 不可逆结束及必要原因/修订；不能被 P/C、健康或旧回调覆盖 |

这些是逻辑状态，不能据表声称任意 Rust 结构都可一次 CAS。引用保护、各故障域的一致读取及资格已知到发布的同步仍依赖整体门控候选。

## 单刷新者的处理次序

1. 完成 safe 返回、真实 apply 和全部非时间前提核验，绑定当前 A/r、原 ctx/t0、成员/轮次/实例和相关资格。E 不重置。以下重点讨论 E>D 的真实延长；E<=D 不需要发布延长，也不能作为忽略已过期证据的理由。
2. 准备不可变 P，通过前态条件转换 A/r→P。准备前时间检查仅用于尽早拒绝，不作为 P 及时的最终证明；任一适用失效变化使旧前态不能被使用。
3. **成功发布后**读取同一可信时间域的样本 W，证明实际 P 先于取样，并要求 W<oldD 且 W<E。采样晚了、时钟失信或关联失败，则保守结束精确许可；不借模型知道 P 曾及时来挽救。
4. 构造绑定精确 P 的不可变证明，条件转换 P→C。若期间已有终止/资格失效，不替换 expected 重试旧证明。若只有有效并发观察，仍须按当前状态判定；不在不匹配的新许可上重放。
5. C 的逻辑含义是“本次合格续期已在 P 接受”。C 可见晚于 oldD 不单独构成复活，前提是 P 确实满足第 3 步且中间没有已成立的终止。该解释只适用于本候选的完整历史，不用于给前轮简单 CAS 补一个旧时间戳。
6. C 若迟至 N 之后才可见，它最多携带历史接受证明，不提供当前执行权。读者及下一次续期都检查当前时间和 N；不能仅凭 Confirmed 标签恢复 active，也不能把历史续期结果报成“目前仍可执行”。下一次真实延长仍需新的 P/W 满足原 N，故不能跨 N 再接受新证据。

后采样无法得到足够证据时，宁可保守终止；接受这个可能缩短可用性的代价。该候选不需要假设刷新线程总在某个固定时限内运行，但仍需要真实可信的时钟顺序与内存协议，不能据此宣称无需暂停/虚拟化验证。

## 读者、到期与撤销竞争

读者从生命周期受保护的当前完整描述取数，执行前重核关联/范围及时间。读取旧描述时，不能直接将它当作当前终止依据。

- 读到 A 或 C：仅在其当前已证实截止尚未过且全部门控成立时允许当前动作；当前期限已过则对精确版本请求终止。条件失配后重读，不用旧截止误杀已经合法更新的状态。
- 读到 P 且 now<oldD：只能依据旧已证实许可处理，不能使用 N。重试不制造新证据，也不扩大动作范围。
- 读到 P 且 now>=oldD：没有可使用的新证据，尝试精确 P→X 的保守终止。若成功，此后任何 C 均不得复活；若输给了 C，先核验当前 C 的真实证书与 N，不能先向外宣告本轮已终止再改口。
- 若因竞争/资源不足暂不能完成核对，本次动作不派发，可报告受限/待重核；不假报终止已经完成。但后续也不能跳过原截止检查，只因未写出 X 就放行。
- 明确适用的领导/控制存储/隔离故障按真实影响关闭当前许可，不能因刷新改变版本而消失。旧 K 阶段事件不改绑新 G；本节不重新定义 K→G。

最后一次允许检查之后的物理交付暂停窗口仍由 LG/HK 与外部隔离处理。把对象查询线性化不等于将 CDB 受理与时钟原子化。

## 历史映射与覆盖要求

对于最终证明完整、没有终止获胜的成功续期，P 有后取样提供的 oldD/E 上界证明，可作为期限内接受事件。P 期间读者使用 oldD 是保守结果，与已抽象续期不矛盾。若读者保守终止获胜，则之后不能存在有效 C；可映射为终止，不要求给失败续期选成功生效点。

这仍是条件证明草案，不是穷尽所有具体交错。必须为所有外部可见结果给出一致顺序解释，不能只证明无人观察的成功分支；不能给“精确最新截止查询”沿用这里的保守查询含义。

以下 RA01—RA06 均未实现/执行。每项同时记录实际时间采样、P/C/X、读者结果、许可身份及派发，不将模型真值交给运行程序。

| 场景 | 必须检查的结果 |
| --- | --- |
| RA01：P 后取样越期 | 不使用发布前样本补证，拒绝延长并保守终止 |
| RA02：及时 P/W，C 跨 oldD，无终止 | 完整证书才允许映射为 P 时接受；读者仍核验当前 N |
| RA03：Pending 关闭与 C 竞争 | 关闭获胜则 C 失败；C 获胜则重读，不能先报告已终止 |
| RA04：C 或读者使用、下一续期跨 N | 历史成功不赋予当前执行权；不能跨 N 构造下一次续活 |
| RA05：多源失效与修订竞争 | 适用故障不被健康或版本重试擦除，旧许可回调不改绑新许可 |
| RA06：证明可见、生命周期及正常进展 | 未见证书不能用 N，无释放后使用；无故障正常刷新和连续刷新可完成 |

## 与旧分析及完成条件的关系

30 的 RT01、RT03、RT05 继续作为安全要求。RT02 在“P=未接受登记”的旧具体解释下仍必须拒绝；本候选为成功分支改变的是具体状态的抽象映射，须通过 RA02/RA03 的完整证明，不能同时保留“P在抽象上必定没有接受效果”又宣称 C 可以迟到。30 的研究报告和历史裁定保留，当前候选以本节明确说明的细化为准。

首次 G 启用没有可供保守使用的旧期限；K→G 还涉及权限种类和外部动作封闭，不能直接套用稳态续期。[32 后的独立候选](activation-handoff.md)已给出首次零副作用、交接双侧封闭和失败保留 K 退出的条件映射。时钟能力、实际表示/生命周期、无分配快速撤销、EG 重叠窗口及设备交付证据仍需收敛。18 保持 claimed，09 不解除依赖；不以研究审计替代实现/运行证据，不启动总 spec。

[33 后的表示候选](permit-representation.md)进一步将 P/C 映射到受保护描述与整数 token 的条件发布；到期关闭必须用 exact token，不能因读到 oldD 就无条件置整轮 STOP。[稳定故障域](permit-fault-scopes.md)使已中断的资格绑定不会因后来健康重新匹配。此为实现方向，RP/FS 及 RA 的组合验证仍未运行。
