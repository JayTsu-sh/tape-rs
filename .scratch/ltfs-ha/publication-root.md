## 根的组成

每卷一个不可变根 `VolumeRoot`，由以下部分组成，各部分本身不可变，更新通过构造新根替换：

| 部分 | 内容 | 变化来源 |
| --- | --- | --- |
| `epoch` | 运行实例 ID、恢复上下文 ID、本卷根序号（单调） | 每次发布 +1 |
| `committed` | 已提交视图：路径→（版本、长度、extent 引用、xattr、状态 committed/partial）；目录树 | 仅 CP4/CP5，或恢复 R4 |
| `pending` | 未提交集合：路径→（in_progress/ready 记录、已落带但未索引的范围、最早登记时刻、所属会话） | 准入、接收、完成、取消、发布差量 |
| `ledger` | 容量账本快照：基线、预留、滚动额度、收尾预算、校准切点 | 准入、释放、校准、发布差量 |
| `sessions` | 会话表：会话→（期限、引用计数、状态 active/closing/expired） | 续期、到期、取消、发布 |
| `commit_slot` | 本卷唯一进行中的批次描述（S2 冻结描述）或空 | S2 建立、CP5 清空 |
| `capability` | 服务能力：视图可信、可读、可写、恢复受限原因、IP 维护债务 | 恢复、健康事件、发布失败 |

`committed` 与 `pending` 使用结构共享的持久化映射（新根只复制被修改路径的分支），使一次发布的分配量与本批变更数成正比而不是与目录规模成正比。这是成本上界的来源，不是对某个库的选择。

## 读者与生命周期

- 读者通过 `load(root)` 取得整根的引用，并持有到操作结束；不得分别读取 `committed` 与 `capability` 后拼接。
- 根替换是单一原子指针交换，发生在该卷的状态更新顺序器内；顺序器外不允许写。
- 旧根在最后一个读者释放后延后回收；回收在顺序器之外的低优先级任务执行，不进入 HA 停发路径或设备派发路径。
- 读者持根期间该根内容永不变化；读者观察到的 `epoch` 与其后请求携带的 `epoch` 不一致时，服务端按 CP3 重新读取当前根，不用旧根继续。

## 发布差量的计算（CP4 的具体规则）

输入：当前根 `R`、冻结描述 `D`（含精确覆盖集合 `cover`：路径→已冻结长度与版本）、S4 证据。输出：新根 `R'`。

1. `committed'`：对 `cover` 中每条路径，写入冻结的版本与 extent；不触及 `cover` 之外的路径。
2. `pending'`：对每条路径，若其未提交范围完全被 `cover` 覆盖则移除；若只覆盖前缀，保留剩余范围并保留原最早登记时刻（PC01）。
3. `ledger'`：按 `D` 中记录的额度身份把“预留”转为“已消耗”；若校准已在 `R.ledger` 中把该消耗纳入基线（校准切点晚于 `D`），则只解除引用不再扣（PC02）。
4. `sessions'`：解除本批引用；已到期会话不复活；仍 active 的会话期限不变。
5. `commit_slot'` 置空；`capability'` 不因发布改变，除非 S5 失败（见下）。
6. `epoch'` = `R.epoch + 1`。

差量计算只读 `R` 与 `D`，不访问设备、不做 I/O；失败即丢弃 `R'` 草稿并进入失效标记路径。

## 预备失效路径

发布失败（CP3—CP5 任一步无法形成可信 `R'`）时必须能在不分配新内存的前提下把卷置为“视图不可信”：

- 每卷在恢复完成时预先构造一个 `poisoned` 根：`committed`/`pending` 指向当前根的同一份共享结构（只增加引用，不复制），`capability` 固定为“不可信，需重建”，`commit_slot` 保留失败批次的描述引用以便诊断。
- 失效时用同一原子交换把 `poisoned` 根换入；此后所有读者得到不可信能力标志，文件契约据此返回 RecoveryInProgress。
- `poisoned` 根本身在每次成功发布后重新预构造（成本仍是 O(1) 引用增加）。
- 已提交事实不受影响：S4 证据独立于根；证据完整的等待者仍可被通知持久化成功（PC04）。

## 会话时效的切点

- 会话期限使用 34 号票据采用的 BOOTTIME 时钟；期限值存放在 `sessions`，续期是顺序器内的一次根替换，不是原地修改。
- 到期判定只在顺序器处理某个事件（接收、续期、发布、定时检查）读取当前根时进行：`now ≥ deadline` 且会话无在途引用 → 转 expired 并释放可释放额度；有在途引用 → 转 closing，引用归零时再释放（C01—C06）。
- 定时检查事件携带其发起时读取的 `epoch`；处理时若当前根 `epoch` 更新且该会话已续期，检查作废（旧到期检查不覆盖新期限）。
- 时钟暂停恢复后的处理沿用 34：暂停跨期限的许可不复活；会话同理。

## 成本上界

| 操作 | 上界 | 依据 |
| --- | --- | --- |
| 一次发布的分配 | O(本批变更路径数 × 路径深度) | 结构共享映射 |
| 一次发布在顺序器内的时间 | O(本批变更数)，不含 I/O | 差量只读 `R`/`D` |
| 失效标记 | O(1)，无分配 | 预构造 `poisoned` 根 |
| 读者取根 | O(1) | 单指针 |
| 旧根回收 | 与被替换分支大小成正比，延后执行 | 引用计数 |
| S2 冻结描述内存 | O(本批文件数 + 本批 extent 数) | 只记录本批 |

本批大小由 04 的准入与有界接收限制，因此上述上界最终受准入参数约束；数值留空。
