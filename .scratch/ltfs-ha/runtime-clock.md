# 运行许可时钟与暂停恢复契约

关联：[研究 34](issues/34-runtime-clock-contract.md) · [RQ](authority-refresh.md) · [P/W/C](renewal-acceptance.md) · [首次与交接](activation-handoff.md) · [故障源接入](fault-source-integration.md)

状态：依自动接受授权采用、经 [34 限定研究](issues/34-runtime-clock-contract.md#answer)核对的 Linux 运行许可计时基线；未实现、未测时钟或访问设备。本节只规定 K/G 的时效与时间证据，不替代外部 fencing，不把会话空闲、索引触发、Raft tick 和硬件命令超时合并成同一个计时器。

## 选择与计量

首版采用 Linux `clock_gettime(CLOCK_BOOTTIME)` 作为 K/G 原 t0、发布后 W、deadline 及派发当前时间的统一来源；不用墙钟日期/UTC 或 Raft tick 判断本地证据是否过期。选择理由是显式包含 Linux 系统挂起时间，不以抽象 `Instant` 的跨平台行为隐含同样保证。部署必须支持该 clock id；不支持时拒绝建立运行许可，不静默回退到另一只时钟。

时间值绑定当前运行上下文及已核验的时间域。校验返回成功、timespec 字段及整数转换，期限构造采用检查溢出的算术；读取错误、非法值、溢出或域不匹配均拒绝该许可的使用/发布，并进入适用故障流程。相等的连续读数可以合法存在，不以“没有变大”单独判定时钟失信。

原 t0 在进入资格请求队列之前读取；E=t0+T 不因排队、网络、apply、锁竞争或回调处理而重置。T/周期/容许开销保持待配置/测量，不提供占位默认值。比较采用严格 now<deadline；达到截止即不满足当前可用条件，是否终止按 exact token 规则处理。

时间域标签只是防止程序混用不同上下文的证据，不是防 VM 内存回滚的安全锚点。旧许可和本地期限不从 Raft 快照、进程缓存或磁带恢复后继续使用；新运行上下文重新取得资格证据。即使启动标识或 namespace 标识相同，也不能单靠它证明没有虚拟机快照恢复。

## P/W/C 与普通派发的绑定

以下 D/E 检查还须满足[组合顺序中的来源时间上界](permit-call-sequence.md#有期限的来源证据也必须纳入检查)：原 RQ 期限公式保持，实际可用截止分层取最小值，同轮续期可用截止不倒退。K→G 核验原 K 上界，但 G 不继承纯 K 截止；这不额外要求 C 及时公开。
1. 准备所有非时间证据，在原时间域内捕获 t0/E 和必要原 deadline，按既有条件发布 P。
2. 成功 P 后才发起同一时间适配的新 W 采样，适配须证明样本取自该次调用区间，保持实际发布先于采样的关系；不能预读时间后缓存返回，也不能以编译器/CPU 原子次序名称代替时钟取样顺序的证明。
3. 首次要求 W<E；稳态要求 W<oldD 且 W<E；K→G 要求 W<Dk 且 W<Eg。证据不足则按原关闭/失败规则，不移动接受点补救，不从现在重新起算。
4. C 只公开绑定 exact-P 的证据，迟于新期限时最多保留历史成功；每次使用仍读取当前时间，验证 token 和全部必要 gate/epoch 在采样前后的关联。最终软件检查后的物理交付仍有暂停窗口，不能因此提前标记命令已发送。

到期定时任务只负责唤醒/推进检查，不拥有最终过期裁定。即使 timer 未调度，派发/续期仍读取当前时间；timer 携带旧 D 到达时须重查精确当前版本，不能无条件停止已合法续期或新 G。BOOTTIME 的计时选择不保证机器会被唤醒，也不承诺调度延迟上界。

## 暂停及虚拟化支持边界

| 情形 | 首版处理及必须成立的前提 |
| --- | --- |
| 线程/进程调度停顿 | 使用恢复后的当前读数检查原截止，时间正常推进时停顿消耗窗口；不从暂停点继续倒计时 |
| Linux 系统挂起/恢复 | BOOTTIME 的含挂起语义作为基线，恢复后仍先核验原期限与现实前提；无休眠期间服务或自动唤醒承诺 |
| 受控 daemon 重启 | 不继承内存许可；按可信控制历史、旧任务/效果收束及新轮次恢复，不重新解释旧 t0 |
| VM 暂停、迁移、整机快照保存/恢复等生命周期变化 | 首版未资格化“活动许可跨操作继续使用”；应在受控流程先停权并约束旧副作用，恢复后新运行上下文、新资格及新许可 |
| 未通知的 VM 恢复/回滚、时间域被共同冻结 | 不承诺来宾能发现；部署不满足首版许可连续性前提，不能仅凭本机双钟比较或一个 instance id 宣称安全 |
| time namespace/时间域或实现前提改变 | 活动上下文不支持热切换；已知变化进入时间能力失信，新域重新核验，不用偏移换算延续旧许可 |

这是本项目支持条件，不是禁止用户管理虚拟机，也不是本轮执行停机/迁移的授权。将来要支持活动许可跨 VM 操作，须证明实际 clocksource、hypervisor 补偿/恢复、通知与强制停权的组合，并单独覆盖内存回滚、旧队列/管理效果及控制存储历史；不能只做一次 guest 时间读取便解锁支持。

整机快照可能一起恢复本地失效标记、epoch、身份和未发送队列；“恢复后启动新进程”的约定须有实际执行保证，不能依赖被回滚的内存自行发现全部问题。外部隔离仍负责防止旧执行者侵害新执行者，但不能据此把未证明的本地时效称为已经满足。

PVE/EE3 是已知可用实验室入口，不是上述时钟及生命周期能力已经验证的证据。本轮不更改其配置、clocksource、暂停策略或快照策略，不把它们自动认定为生产 Raft 部署。

## 失信与有限检测能力

可观测的读失败、同一有因果次序的采样明显倒退、时间域更换或适配完整性失败，进入实例 K/G 共同时间能力故障，先失效 gate，再记录及核对。时间恢复看似正常不能重开旧许可。该执行门控不自动清空 Raft 历史或剥夺健康成员的合法投票，控制可信性按独立故障依据处理。

不同线程读数的报告到达顺序不等于实际采样顺序，不能把一个较早采样的迟到通知误判为时钟倒退。检测须关联真实采样顺序/上下文；无法建立比较关系时不能伪造倒退结论，也不能将比较通过当完整连续性证明。

“单调”不保证与真实时间完全等速，日志墙钟也不提供稳定的误差界。没有经过资格化的运行环境和计量依据时，不将 T 宣称为真实物理时间上的硬上限或 HA RTO 保证；初始目标是执行明确的同域年龄检查，性能/误差和暂停行为另行验收。

## 验证目标与环境证据

TC01—TC06 均未实现/执行。

| 场景 | 必须检查 |
| --- | --- |
| TC01：队列、apply、线程暂停消耗原窗口 | t0 不重置，恢复后读当前值；超期不能因 timer 未运行继续 |
| TC02：P/W/C 各点暂停与迟到确认 | 后采样确在 P 后；各类期限条件分别满足，C 跨新期限只记历史 |
| TC03：读取失败、算术边界、相等与乱序样本 | 错误/溢出拒绝；相等不误报失信，报告乱序不等于真实时间倒退 |
| TC04：Linux 挂起与到期回调延迟 | 时间语义符合所选平台，原截止仍有效；不把唤醒或回调时间当新的起点 |
| TC05：VM 生命周期/namespace 与回滚 | 未资格化环境不宣称通过；分别证明停权、新上下文及旧效果约束，不靠双钟或内存标签判定全部安全 |
| TC06：正常空闲与多驱动负载 | 合格环境下首次/续期/交接有进展，记录读取成本及抖动，不增加逐文件共识或设备时钟探测 |

环境记录至少包含被测内核/架构、时钟接口与 clocksource、虚拟化及 namespace 条件、允许的生命周期操作、暂停/恢复路径、原始观测和未覆盖项。配置声明、模型测试、现场结果分开保存；本轮仅形成契约，不填“通过”。具体 Rust FFI/适配实现、时间与内存序组合及真实环境资格化仍需落实，18/09 状态不变。
