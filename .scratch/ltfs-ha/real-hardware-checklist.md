# 待真机验证清单与 Holo 作为唯一设备的含义

用户在 2026-09-17 说明：目前没有真实的 IBM 带库，只有 Holo-VTL 作为模拟。仓库 CLAUDE.md 里写的 TS4300（10.128.54.118，FC 直连）当前不可用。本文把散在各处的"需真机"项收拢到一处，并说明在没有真机期间什么算证据、什么不算。

## 1. 证据分级

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| S 规范 | T10/SNIA 文本规定的行为 | Index Construct 的结构、PR 的类型语义 |
| L 参考实现 | IBM LTFS 2.4.8.3（tsclient 上 `/opt/ltfs-ref`，与 EE 的 LE 同版本号）的源码和它的实际运行结果 | 它对 VCI 长度、时间戳格式、预留键的要求 |
| E EE 集群 | 实验室里运行中的 IBM Spectrum Archive EE 写出的磁带和它持有的预留 | EE 克隆带的布局、驱动器上的预留键 |
| H Holo | Holo-VTL 上观察到的行为 | hw01—hw06、双向互通、抢占实验 |
| M 模拟器 | tape-rs 自带的 `SimTransport` | 74+ 项测试 |

没有真机期间的规则：**L 和 E 是"对真机行为的可执行规格"**，因为它们是针对真实 IBM 驱动器写的、并在真机上运行过的软件。某个行为若 S、L/E、H 三者一致，可以当作高置信；只有 H 和 M 一致、而 L/E 没有覆盖到的，只能算"在模拟设备上成立"。笔记和代码里此前写的"实机"一律指 Holo，不是真实驱动器。

Holo 自身分三层，可信度不同：

| 层 | 负责什么 | 可信度 |
| --- | --- | --- |
| Linux 内核 LIO 目标 | iSCSI、ACL、持久预留（`emulate_pr=1`）、任务管理 | 成熟的通用实现，语义按 SPC；但它不是磁带驱动器固件 |
| tcmu-runner + libtcmu | 内核与用户态之间的命令与数据搬运、残留长度 | 有一个已知问题：读到文件标记/短读时的残留长度，补丁已写未部署 |
| Holo 数据面（Rust） | SSC 磁带语义、MAM、分区、SMC 换带器 | 已发现并修复 6 处偏差，见下；应假定还有未发现的 |

## 2. 已修复的 Holo 偏差（说明模拟设备会错在哪类地方）

1. 读到文件标记时 sense 缺 VALID 与 INFORMATION。
2. 反向 SPACE 到 BOP 返回 ILLEGAL REQUEST 而不是 EOM + 00/04。
3. 正向 SPACE 越过 EOD 的返回码与位置不对。
4. VCR（MAM 0009h）不随写入变化。
5. VCR 在装载时 +1。
6. 080Ch 被当成 256 字节定长属性，IBM 用 79 字节读不到。

共同特点：都在"规范有明确规定、但 Holo 作者接入的备份软件（Veeam、Dbackup）没有用到"的角落。LTFS 用到的命令面比备份软件宽，所以 tape-rs 和 IBM LE 是目前检验 Holo 的最好手段。

## 3. 待真机验证清单

真机到位时按此逐项重跑。每项写明现在的依据和风险。

### 设备层隔离（09）

| 项 | 现在的依据 | 风险 |
| --- | --- | --- |
| PF08 LTO 驱动器对 Exclusive Access、REGISTER AND IGNORE、PREEMPT AND ABORT 的支持与回读内容 | L：IBM LE 在真机上用同一套命令；H：LIO 上全流程通过 | 低。驱动器支持 PR 是 LE 能工作的前提 |
| PF08 换带器是否支持 PR | H：LIO 的换带器支持；L：LE 不预留换带器 | 高。真实换带器很可能不支持或行为不同；协议已按"不支持"设计了降级 |
| PF09 断电/复位后预留是否保持，APTPL 是否可用 | 无 | 中。协议已假定不保持，靠写入前自检兜底 |
| PF10 抢占时在途 WRITE 的缓冲数据是否落带 | 无 | 中。协议已假定可能落带，接管后必走 D02 |
| 多路径（同一节点多条 FC 路径）下的注册语义 | 无 | 取决于将来的物理拓扑 |

### 提交与恢复（04）

| 项 | 现在的依据 | 风险 |
| --- | --- | --- |
| D01 最终屏障：WRITE FILEMARKS(0) 返回 GOOD 是否保证缓冲已落带 | S：SSC 规定 immed=0 时同步；H：Holo 是软件实现，不构成证据 | 中。这是 S4 的物理依据 |
| EOD、SPACE、READ POSITION 在分区边界与 EOM 预警区的真实语义 | S + H（偏差 2、3 修复后） | 中 |
| 掉电后驱动器对未刷缓冲的处理、EOD 是否可靠 | M：`power_cut`；H：未做（Holo 无法断电单个驱动器） | 中。D02 的尾部分类就是为此设计的，但 T1—T4 的真实形态没见过 |
| VCR 在真机上随哪些操作变化 | S/L：LTFS §10.3 与 LE 的用法；H：偏差 4、5 修复后符合 | 低 |
| 机械操作超时（MOVE MEDIUM 300s、LOAD 300s、FORMAT 数小时） | 仓库原有数值，来源是此前的真机 | 低，但 Holo 上毫秒级完成，超时路径从未真实触发 |

### 性能（06）

Holo 的吞吐、定位时间、装载时间都不代表磁带。06 的全部数值目标在没有真机前无法验证，继续留空。Holo 上能验证的只有"软件自身不是瓶颈"这一侧，例如哈希吞吐（已测）、索引序列化与发布的开销。

### 格式互通（40）

| 项 | 现在的依据 | 风险 |
| --- | --- | --- |
| tape-rs 写的卷被 IBM LTFS 读写 | L：参考实现 2.4.8.3 实跑通过 | 低。格式是介质无关的，这一项不依赖真机 |
| VL06 2.5 增量索引样本带 | 无样本来源 | 与真机无关 |
| 压缩标志、块大小上限（`Maximum device block size`） | H：Holo 报 1 MiB | 低 |

### 拓扑

原先问的"FC 还是 SAS、有没有交换机"在没有真机时不需要回答。17 的"三个节点都能到达全部驱动器"在 Holo 上由 iSCSI ACL 实现，没有物理端口数的限制。将来选购真机时，这一条要重新提出：LTO 驱动器端口数有限，三节点全可达基本要求 FC 交换机。

## 4. 对后续工作的含义

- 三节点 Raft + 设备层隔离的开发和故障演练**可以完全在 Holo 上进行**：给 TAPERS 的目标再加两个发起方的 ACL，就有三条独立路径。节点可以是三台 VM，开发早期也可以是同一台机器上的三个 open-iscsi iface（抢占实验已证明可行）。PVE 能对单台 VM 执行停止/重置，可以用来制造"节点卡死后恢复""节点掉电"的场景，这是验证"旧 Leader 不知道自己已下台"的合适环境。
- 每发现一处 Holo 偏差就修 Holo（用户指示），并在本文第 2 节登记。
- 不把 Holo 上的通过写成"硬件验收通过"。08 的验收框架里，凡依赖驱动器固件的用例标注"Holo 通过 / 真机待验"两栏。
