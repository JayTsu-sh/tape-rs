# 卷提交状态机草案

关联：[提交契约](issues/04-durability.md) · [决策地图](map.md)

状态：逻辑状态机整体仍待评审；其中已提交后的本地视图/缓存失败、索引预算两层检查、正常卸载排空、恢复时分开开放读写及本地发布资源前置准备政策已获用户接受，见对应小节。本文不是现有代码行为或已验证的设备协议。沿用已接受的磁带权威、无回执、流式写入、快照合批、部分文件保留和分层降级原则；数值参数继续留空。本稿不决定线程模型、Rust 类型、接口错误码或具体 CDB 顺序。

## 状态必须分开记录

- 提交进展：当前有限变更集合处于准备、写入、已可靠持久化还是需要核验的阶段。
- 服务能力：所有权及设备状态是否可信，本地文件系统视图是否可用，是否允许新业务写入。
- 请求观察结果：当前等待者是否已被该提交覆盖，应用是否实际收到成功响应。

三者不能压成一个 success/failed 标志。以下阶段描述提交进展；所有阶段都受服务能力门控，响应发送也不改变磁带事实。已持久化的事实来自经过验证的数据、可恢复索引链和介质屏障，不来自内存状态名称。

## 正常路径与失败出口

| 阶段 | 进入或完成所需证据 | 状态变化与失败出口 |
| --- | --- | --- |
| S0 累积变更 | 有效所有权、资源准入与写入门控成立 | 流式写带，保留未提交变化；普通 write 接收不算持久化成功。结果不明则进入恢复门控 |
| S1 选取有限提交范围 | time/size/显式请求或容量安全条件触发；标出当前等待者要求覆盖的变更 | 截取有依赖一致性的有限集合，不等待未来上传无限扩张；排出该集合所需的数据。父目录、文件映射等必要依赖不能随意裁断，具体文件操作依赖由文件契约细化 |
| S2 固定可索引快照 | 选定范围的数据实际写入结果、位置和长度已确定，在安全边界暂停后续数据写带 | 固定映射和元数据，选择增量或所需 Full，复核预算。候选 generation 不得提前发布为已提交；位置/结果不明则恢复，不按请求长度猜 extent |
| S3 写入索引构造 | 快照、必要基线/增量依赖和预算可验证 | 在同驱动器不可插入的提交序列中写索引；后续接收仍可进入有界缓冲，不能改动本快照。索引部分写入、执行结果不明则停止追加，不盲重写该索引 |
| S4 核验介质持久化 | 数据及相关可恢复索引达到最终设备协议规定的屏障和完整结果检查要求 | 条件满足才确立该快照已可靠提交；尚有未解释错误或缺少证据时不能越过。普通 WRITE 成功或某个通用同步调用成功不能单独替代本条件 |
| S5 发布本地已提交视图 | 同一有效服务实例仍持有 S4 的完整证据，且发布范围对应冻结快照 | 正常路径推进本地已提交视图，仅清理已覆盖的 dirty/计数；后续变更仍保留。若本地更新失败，转入下节的缓存/视图异常分支，不把已写磁带回滚 |
| S6 通知已覆盖等待者 | 该请求要求的完整文件状态或 fsync 范围确实被 S4 覆盖，且结果关联仍可靠 | 正常路径发送成功；未覆盖者等待后续提交。响应失败不撤销持久化事实，也不重复写带；服务端发送成功不等于能证明客户端已收到 |

S4 是持久化确认条件成立的边界，不是新上传回执格式。S5/S6 之间的本地异常处理政策已接受，具体实现仍待细化。IP/MAM 维护按既定调度另行进行，不作为每次归档成功的必经阶段；其失败仍可能限制后续服务，清洁卸载要求不变。

**已裁定的授权中断边界。** 用户已接受 [18 的单命令停发政策](issues/18-raft-execution-contract.md#已裁定失去执行资格后的命令边界)：执行资格失效后，S3/S4 尚未发出的后续命令也停发，不因本批已开始而继续补写索引、结束标记或最终同步；已发出的单条命令不默认强制中止，其迟到完成不恢复授权。S3 排他性不等于失效后允许完整收尾。已接受由此可能限制原卷自动追加的代价；资格失效判据和交付门控仍待细化，LG01—LG06 未运行，既有异常尾部恢复与已提交事实保护规则不变。

**提交覆盖规则。** 原生完整上传按完整文件就绪状态判断覆盖；FUSE 对打开文件的 fsync 按所要求的已有变更判断，不等待 close。已提交前缀不等于整文件完成。同卷合批共享屏障，不新增任意多文件事务或跨卷原子性承诺；请求关联只需支撑当前有效会话，不因此新增磁带 upload_id、回执或跨节点历史查询。

**发布规则。** 从快照发布已提交范围与保留后续未提交范围必须在逻辑上完整一致；不得清空整卷 dirty 后遗漏新变更。具体原子发布机制和分配策略待实现设计，不声称当前代码可做到无失败发布。候选 generation 在 S4 前不能充当成功证据；发生故障后，从磁带恢复有效状态再确定后继索引关系，不靠复用/跳过某个内存计数器裁定安全性。

**已裁定的 S2 预算细化。** [索引预算两层检查](capacity-reservations.md#已裁定索引预算的两层检查)要求在日常轻量估算之外，对冻结快照的实际编码成本或可证明上界作提交前检查；需要的差额与收尾保护无法满足时，不进入 S3。必须 Full 时不退回增量突破既有规则。本项原则已接受，不指定编码缓存或遍历次数，也不保证通过预算检查后设备一定写入成功。

### 待验证：S3→S4 最终屏障候选

[最终屏障研究](issues/13-final-barrier-evidence.md)核对索引结束标记与同步的关系。本节把已接受的“可靠落带后确认”落实为保守候选路径，不改变归档确认点，也不代表现有代码或设备已经通过验证。

1. 在受保护的同驱动器提交序列中，按已验证的 LTFS 布局完成冻结快照的索引构造及结束标记；每步都保留并核对完整执行结果。具体文件标记参数和布局仍须纳入整体命令协议，不借本节擅自改成立即返回模式。
2. 在尚无充分证据证明结束标记覆盖全部所需持久化义务时，候选基线保留一条显式 `WRITE FILEMARKS(IMMED=0, count=0)` 最终同步；它不另写文件标记，不用于修补残缺索引。此前任一步结果不明时，先走恢复门控，不能用这条命令洗掉错误后继续确认成功。
3. 最终同步及相关命令的 SCSI/host/driver 状态、sense、实际传输结果与延迟错误全部得到解释，所有权、卷身份、执行上下文及请求覆盖关系仍可信，且格式可恢复条件成立后，才允许进入 S4 确认边界。`ioctl` 返回成功或某次 GOOD 状态不能单独替代这组条件。

**有条件的减少命令。** “索引结束标记本身兼任最终屏障”保留为待验证优化：必须证明目标命令参数及设备模式下，它同时持久化全部相关先前数据、索引和标记，并完成完整错误检查，才能讨论省略额外 count=0。不能因 IMMED=0 的一般完成措辞、相同 opcode 或某次正常测试成功就宣称等价；也不把显式 count=0 当作弥补未知设备语义的万能保证。

该同步按卷提交批次执行，可由同批多个文件共享，不要求逐 write/逐文件强制同步，也不把 IP 更新塞回每次归档确认路径。屏障返回不明时不盲重发；B 的新设备连接即使同步成功，也不证明 A 的历史请求成功，仍从磁带恢复证据判断。候选是否冗余及实际性能收益都须测量，不承诺少一条命令就一定更快。

**验证重点。** 覆盖结束标记前后与显式屏障前后失效、屏障响应丢失、先前写入的延迟错误、短写/异常残差，以及新主连接后的恢复；比较两种路径时须使用相同工作负载、提交覆盖及掉电恢复判据。仅正常写读测试不能证明掉电持久化。缓冲模式、固件、HBA/nexus 条件和完整 CDB 协议仍待核实；本轮未运行任何模型、性能或硬件测试。

## D03 已裁定：发布准备与同批一致转换

用户回复“确认”，接受本地发布资源前置准备策略及其时间/有界内存取舍，见[裁定记录](issues/04-durability.md#已裁定发布准备与同批一致转换)。本节细化既有冻结快照与发布规则：**在 S2、首次发出本批索引写入前，准备好本批本地发布所需的可预见资源；准备不足则不进入 S3。** 目的是减少可靠落带后才发现无法构造本地视图的风险，不承诺发布绝不会失败。此处的资源是本地状态构建/保留资源，与已接受的介质索引容量预算分别检查。

### 准备的范围与性能边界

准备内容绑定同一有效所有权上下文、卷身份和冻结快照，包括本批已提交视图的待发布变化、请求覆盖关系，以及 dirty/触发计数和容量记账的转换依据。它们仅供当前运行实例使用，不是新的上传回执、磁带扩展属性、持久化日志或 A/B 同步记录，也不成为磁带权威的第二个提交参与者。

日常写入沿用轻量累计；提交时处理本批必要变化及依赖，不要求每批复制全目录、把整份 XML 放入内存、逐文件查询设备或缓存完整文件数据。实现应复用既有快照和预算检查结果，但仍须测量 CPU、内存及提交延迟；准备可能增加 S2 耗时和有界内存占用，不能无证据保证性能不变。必须 Full 时的必要工作不因这项增量准备策略被省略。额度、数据结构、锁和线程模型留待实现设计。

准备失败沿用索引写入前的本地失败分支：只有能证明本批索引尚未发出、此前数据执行结果和位置可信，才可保留状态重新准备。已写数据不当作未执行、不重新写一遍；无法证明则恢复门控。有界接收和背压仍有效，不能无限积累待发布快照。

### S4 之后只转换本批覆盖的状态

| 状态 | 发布本批时必须成立的约束 |
| --- | --- |
| 已提交视图 | 精确对应 S4 已证明持久化的快照；不能带入后来接收的变化。对依赖该视图的服务，不暴露更新一半的混合状态 |
| dirty 与 time/size 触发 | 只移除本批覆盖的变化；后续变化、最早未提交时间和未覆盖的完整文件计数保留。不能因同一文件已有前缀提交就减掉整文件的待提交计数 |
| 容量账本 | 将已执行写入及相应预留按既定覆盖规则转换，不重复扣账或退还；提交成功不等于物理占用消失，不擅自更新设备剩余量。后续授权、未知占用和 DP/IP 收尾保护保留 |
| 请求等待者 | 只有要求的范围确实被该快照覆盖且证据仍可靠才成功；重复完成通知不重复清理，迟到完成不续期、不复活会话或改动新 owner 状态 |

这些转换需要可验证的一致边界，不要求所有状态存于一个数据库或由一把全局锁保护。发布不能覆盖准备后产生的新变化、取消/到期结果或已完成的容量校准；若当前状态不再符合转换前提，禁止盲套旧准备结果。后续设备工作与新准入必须使用一致、可信的视图和账本，否则暂停受影响服务。

**交错示例。** 文件已有变更 X，被一次 fsync 和本批冻结快照覆盖；写索引期间同一文件又接收变更 Y。S4 成立后，本批只能确立 X 持久化并确认要求 X 的等待者；Y 仍未提交，保留其 dirty、时间与资源占用，等待后继批次。不能用“清除这个文件的 dirty”顺带清掉 Y，也不能因此确认要求 Y 的后一个 fsync。本例不新增可见性或任意覆盖写承诺，具体文件契约仍待后续票据。

准备成功后若 S4/S5 之间仍出现本地故障，继续适用[已接受的本地视图或缓存失败政策](#已裁定已提交后的本地视图或缓存失败)：可靠落带事实不回滚；有完整请求证据可单独确认并报告降级；失效活动视图停止服务并重建。准备记录丢失不能推断磁带未提交，B 仍从磁带恢复，不重放 A 的发布队列。

**候选验证 PV01—PV05。** PV01：S2 本地准备不足，不发本批索引命令且不重复已写数据；PV02：上述 X/Y 交错，仅清理并确认 X，Y 及其计时/额度保留；PV03：准备之后发生取消、到期或容量校准，发布不覆盖新状态、不双重扣账/退还，物理占用不因提交而释放；PV04：S4 后注入缓存失败、活动视图失败和重复完成，分别按证据降级且不重复转换；PV05：准备后换卷/换 owner，或 A 在 S4 后、S5 前掉电，旧发布不能更新 B，B 按磁带证据恢复且不猜历史请求。均为待实现用例，未执行。

资源前置准备策略已获用户确认；其余约束重述或细化既有不变量，不将本节视作已验证的并发算法。PV01—PV05 和性能测量尚未执行，04 保持 claimed，D02 恢复算法仍待验证，不提前开展 07 的模块/API 设计。

### D03 进展：每卷有序差量发布

依自动接受授权，采用[本地状态发布协议](commit-publication.md)：同卷状态更新具有唯一逻辑次序，慢工作返回结果而不直接改部分字段；S2 保留冻结提交描述，S4 后按身份将本批覆盖应用于当前状态，最后发布完整根。取消、后续变更及较新容量校准不被 S2 旧镜像覆盖。首版同卷仅一份索引提交等待收束，下一批仅有界接收；不同驱动器并行及 HA 独立快速停发不变。

采用每卷有序更新的局部协调成本，以及根构建失败时停止受影响视图服务的保守策略；不增加磁带或本地持久事务、逐文件 Raft、回执或全目录复制要求。PC01—PC06 未实现/执行；实际表示、生命周期、失效标记和成本上界仍待落实，不以逻辑发布方案替代 D01/D02 或 18。

## 异常分支

### 索引写入前的本地失败

索引构建或预算准备失败，不自动等于设备状态不明。如果能证明没有发出本次索引写入、此前数据命令已结束且结果/位置可信，可保留快照与未提交状态，等待解决本地问题后重新准备；不能把此前已落带但未提交的数据说成“从未执行”，也不能重复排出相同数据来补偿本地失败。无法证明这些条件时按恢复门控处理。

本分支不指定自动重试次数或等待时长，不允许在资源不足时无限增长接收队列。任何重试仍须复核所有权、快照范围、实际位置和容量预算。

### 索引或屏障结果不明

冻结受影响资源的正常追加和自动重放，保留可用的错误与快照证据，按[恢复写入必要检查](issues/04-durability.md#待裁定错误分类与恢复写入门控)核验。未达到确认条件的请求不报成功；此前已可靠提交范围不一并改成未提交。

恢复得到较新的有效文件系统状态后，依然不能在无回执模式下猜测每次历史请求结果。旧 dirty、旧写头和旧会话不能直接恢复为可执行队列。已接受的不自动修复尾部、不自动跨卷续传原则继续有效；受限读取的具体接口仍待裁定。

### 已裁定：已提交后的本地视图或缓存失败

用户针对磁带已可靠提交后 catalog 更新失败的确认与降级建议回复“接受”，[裁定记录](issues/04-durability.md#已裁定提交后本地视图或缓存失败)限定本次接受范围，不代表整份状态机获批。本地 catalog/缓存不是磁带权威的第二个提交参与者，按以下边界区分两类失败：

1. **仅可重建缓存的持久化更新失败。** 当前进程内的已提交视图、请求覆盖关系及 S4 证据仍完整可信时，允许确认当前已覆盖请求成功，同时报告服务降级；把故障缓存标为无效，不再以它回答最新状态。后续服务只有在替代的可信视图、容量账本和调度状态均可用时才继续，不能为绕过数据库错误而绕过一致性检查。
2. **本地活动视图发布失败或一致性不明。** 磁带的已提交事实不撤销；暂停受影响卷依赖该视图的正常查询和新写入，重建/核验后再开放。若当前请求的 S4 证据与覆盖关系仍能可靠读取，可单独返回该次持久化成功并报告服务降级；若连该关联也不能证明，则不猜成功，允许结果未定。控制状态报告在安全可用时继续提供。

缓存是否失效、本地状态是否可继续信任也需要可验证的处理路径；遇到进程状态可能损坏、控制不可响应或影响范围不明时，按已接受的扩大降级/整组恢复政策处理，不能坚持将故障限制为单卷。

这项已接受政策的取舍是：不让可重建缓存成为额外的持久化权威，同时允许应用遇到“归档已持久化，但文件服务暂时不可用”。后者应明确报告，不用旧目录返回成功或文件不存在掩盖降级。证据不足时不自动重传；具体附带状态和 POSIX 映射仍由文件契约决定，不新增上传结果的持久历史查询。

### 响应丢失与节点接管

S4 后响应丢失不触发数据重写。A 崩溃后，B 仍先完成隔离/所有权和磁带恢复；A 的内存阶段、本地缓存或日志不是 B 确认历史请求成功的充分证据。有效文件状态可恢复与旧请求是否能精确关联分别报告，应用保留源数据并按后续安全重试契约处理，不自动重放。

## 已裁定：正常卸载的排空边界

用户回复“接受，继续推进地图”，确认本节正常卸载边界，见[裁定记录](issues/04-durability.md#已裁定正常卸载的排空边界)。流程约束已接受，具体实现与 U01—U05 验证尚未完成。

本节仅讨论主动请求的正常卷卸载，不定义节点故障接管、强制卸载、库级停机或应用文件 close 的完整语义。沿用已接受的清洁卸载一致卷要求，将“归档已提交”“卷已完成收尾”“介质已卸载”分别报告；前一项成功不代表后一项成功。

采用以下已接受的有限排空原则，具体时限留空：

1. **关闭该卷新任务入口。** 卸载请求与新任务准入建立明确先后关系；排空开始后不再接纳新上传或独立的新修改任务。已有任务身份与允许收尾范围必须可核验，不能不断把新上传挂到旧会话上延长排空。其他安全、独立的卷不因本请求停止服务。
2. **已有工作安全收尾。** 排空开始前已受理任务可以继续其必要数据与提交工作；确需补充额度时仍按可信容量及收尾保护检查，不因“正在卸载”免检，也不保证一定补足。未结束上传不被假定完整，不自动取消、删除或跨卷续传。既有会话到期政策不变，卸载本身不续期。已就绪的小文件尾批和纯元数据变化不等待 time/size 门槛。
3. **建立最终收尾切点。** 只有未完成上传及其他可能继续改变该卷的工作已完成，或经既有取消/到期规则安全结束，才能固定最终快照。所有会影响位置或仍引用设备的操作须安全结束；随后到物理卸载完成前不再放入新的冲突操作。不能只看数据队列为空就认为排空完成。打开句柄的具体处理留给文件契约，本节不规定“所有只读句柄必须 close”。
4. **核验收尾，再卸载。** 按既定规则完成必要 DP Full、IP 更新及一致卷/持久化检查，沿用索引预算两层检查，不挪用保护预算。已有最终状态如足以证明要求已满足，不要求无条件重复写相同索引。只有收尾成立且所有权及设备门控仍有效，才允许发出正常物理卸载；机械操作的真实结果另行核验。

**到期与错误出口。** 若排空期限到达且卸载命令尚未发出，终止本次自动卸载推进，报告未完成阶段及可确认的阻塞原因；不默认取消上传、不发出物理卸载，也不因等待任务随后完成就继续这次已结束的卸载请求。该卷保持停止新任务准入，已有工作仍按安全条件处理。调用方可明确重试卸载，或请求恢复准入；恢复须重新验证所有权、视图、位置及容量，不以一次超时自动放行。具体管理接口留给后续设计。

如果物理卸载命令已经发出，则响应超时不证明介质仍装载或命令未执行，须核验实际位置和结果，不能盲重发或移带。任何结果不明的索引、屏障或设备操作仍走恢复门控；最终 Full/IP 收尾失败不撤销此前可靠提交，但不能报告清洁卸载成功。排空期限只约束流程等待，不缩短硬件命令超时或授权强行中断在途命令。

**候选验证 U01—U05：** U01：排空入口与新准入竞争，只有明确在切点前受理的任务进入收尾；U02：完整小文件不足 size 门槛及纯元数据尾批仍被提交；U03：上传持续未完成导致期限到达，不取消、不卸带，随后完成也不重启旧卸载请求；U04：最终索引预算不足、IP 更新失败或所有权失效，不越过卸载门控，旧提交事实保留；U05：卸载命令已发出但响应丢失，报告未定并核验，不断言仍装载或盲目重试。

“停止新任务、允许已有任务安全收尾、排空到期不强制卸载”的边界已接受。截止点实现、错误/管理接口、读句柄语义、时限及设备协议均未定，U01—U05 未实现或执行；不因此关闭提交票据或解除文件契约/恢复验收依赖。

## 已裁定：恢复时分开开放读写

用户回复“接受，继续推进地图”，确认可信当前视图可先读、写入另行核验，见[裁定记录](issues/04-durability.md#已裁定恢复时分开开放读写)。本节开放原则已接受，恢复算法与 RV01—RV05 验证仍未完成。

本节收敛既有恢复草案中的服务开放政策，不设计索引扫描算法、具体 POSIX 错误码或新的历史快照接口。恢复后的目录/读取资格与追加写入资格分开；恢复不是一个同时开放所有操作的布尔开关。

| 当前可证明的状态 | 已接受的开放边界 |
| --- | --- |
| 所有权、隔离或设备操作安全条件不成立 | 不执行正常读写设备任务；不能以“只读”绕过旧主隔离或与未知在途操作争用驱动器。安全可用的控制状态报告与正常文件服务分开 |
| 仅得到旧 Full、缺失依赖的增量链或无法确定最新性的视图 | 保留恢复证据并报告恢复未完成/受限，不作为普通接口的当前目录开放；缺失路径不转成正常的文件不存在，旧内容不冒充当前内容 |
| 已验证当前已提交视图，相关数据引用及安全读取条件成立，但安全追加位置或容量条件尚未证明 | 可先开放该可信视图的目录查询和安全读取，继续拒绝新修改；不等待写入资格才能提供所有读取，也不把读就绪报告为完整恢复读写服务 |
| 当前视图与全部恢复写入前提均成立 | 可按既有准入规则恢复新工作；不复活旧会话、恢复旧预留或自动重放故障前上传 |

这里的“当前”必须由恢复协议证明有效完整基线与必要增量链及其覆盖范围，不是“目前扫描到的最大 generation”，也不是某份 XML 可以解析。发现更晚索引残片时，不能仅凭残片存在就断言旧视图一定过时，也不能直接忽略残片：需由恢复算法区分未完成尾部与可能遗漏的有效提交；无法区分时保持恢复受限。扫描范围、判定证据和停止条件仍待协议验证，本政策不授权全带无限扫描或自动修复。

**不能把回退伪装成恢复成功。** 例如 IP 中存在旧快照，而 DP 上是否还有已提交变更尚未查明时，不用旧目录的“查不到”指导应用重传或覆盖。若最终证明旧快照及其有效后继已覆盖全部可恢复提交，则可按该验证结果开放，不因索引年代较旧就永久禁读。无回执下，当前文件状态仍不能保证对应到某次丢失响应的请求。

**先读不等于放宽安全。** 读取、定位仍经过同驱动器调度，不与正在核验的冲突操作并行。正常查询使用完整一致的已验证视图，不混合已恢复目录和未验证条目；若后续证据否定当前视图或访问安全，撤回受影响服务资格并报告恢复状态。索引/引用检查不是全卷数据读回校验，每次数据读取仍检查实际结果，读错误不以补零或静默返回旧版本掩盖。

本轮不新增专门的旧快照浏览、抢救导出或部分目录发布接口。此前提出的受限读取仅在能够明确表达范围且安全条件成立时才有讨论基础，不能默认通过普通 Native/FUSE 接口实现；是否增加专用功能留待明确需求。普通接口的错误映射、目录枚举与句柄语义仍归文件契约，接管计时终点仍归恢复验收；本节不提前认领这些依赖票据。

**候选验证 RV01—RV05。** RV01：仅旧 IP 可读而 DP 覆盖未明，不开放普通最新目录或返回误导性的不存在；RV02：视图和安全读取已验证而追加位置未明，只开放读取；RV03：读就绪后收到改变视图可信性的证据，暂停相关服务，不继续使用失效缓存；RV04：所有权/隔离失效，即使索引已验证也不发新读取命令；RV05：随后写入门控满足，只受理新授权工作，不恢复旧上传权限。验证须覆盖合法未完成尾部与缺失有效提交两种候选情况，不能把二者统一为静默回退。

“可信当前视图可先读，写入另行核验；最新性不明不冒充正常目录”的原则已接受。RV01—RV05 未实现或运行，恢复算法、时间目标和接口仍未完成，不承诺只读服务无条件快速恢复。
