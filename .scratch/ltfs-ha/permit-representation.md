# 运行许可的标准库状态表示候选

关联：[整体发布](permit-publication.md) · [续期接受点](renewal-acceptance.md) · [首次与交接](activation-handoff.md) · [限定研究 33](issues/33-permit-state-representation.md)

状态：依自动接受授权采用、经 [33 研究](issues/33-permit-state-representation.md#answer)核对的表示与失效分类候选；未实现代码或运行模型。目标是给 P/W/C 和精确关闭提供具体内存载体，分开引用安全、当前权限及快速失效，不能仅凭锁或原子类型名称宣布完整 HA 协议完成。

## 首版候选组成

[组合调用顺序](permit-call-sequence.md)规定原请求至 P/W/C、当前读者及派发的整体衔接。描述还须分别保留必要来源的旧/新时间绑定；同轮成功续期可用截止不倒退，Pending 只用旧绑定。局部能力与共同 K/G 分层，不把所有卷的截止塞入共同许可。
每个接管轮次使用独立、稳定的 `Arc<RoundCell>`；调度任务和对应失效源在正常准备时取得强引用，不能在故障热路径从裸指针临时补引用。旧任务持有旧 cell，不根据相同节点名、指针地址或磁带 generation 找到新 cell。对象身份不复用，重启不恢复这些内存对象为有效许可。

| 对象 | 职责 | 不承担的保证 |
| --- | --- | --- |
| `Mutex<Arc<Descriptor>>` | 同一时刻保护完整不可变描述的替换和引用克隆，描述含精确身份、修订、阶段、原/新期限及已核验的证据关联 | 不用于等待 Raft、I/O 或网络；互斥不证明时间没有过去 |
| `AtomicU64` 控制字 | 编码修订、阶段及不可逆整轮 STOP，提供与精确前态竞争的发布/关闭点 | 不是原子指针，不容纳证据正文，也不是设备受理记录 |
| 独立共同故障门控 | 表达超出单轮的实例/资格失效，阻止未发布的新轮次漏停 | 单个旧 RoundCell 的 STOP 无法覆盖未来对象；跨轮绑定仍须专门协议 |

首版以具备所需 64 位原子操作的目标为前提，位域划分和不回绕的修订规则须在实现中固定；不允许在不支持的目标悄悄用可能等待的锁模拟快速撤销。控制字中的阶段和描述中的阶段须一致，不能只比较修订低位或把 STOP 位屏蔽后继续派发。

此处采用最强原子次序作为初始验证基线，不主张其自动解决多字段、时钟或外部效果。后续若降低次序须重新给出可见性依据。证据正文仍归不可变对象/控制历史管理，不在每次检查中重新验证整份隔离记录。

## 唯一发布者的转换

1. 锁外构造新不可变描述，绑定精确原描述/控制字；所有可能分配、等待 safe/apply、解析与慢证据核验在锁外完成。准备成功不等于批准发布。
2. 短时取得描述锁，读取并核对当前描述、控制字及必要共同资格。前态不符则放弃旧准备；不能改 expected 后将同一旧结果提交到新轮次。
3. 保留旧 `Arc`，将新描述装入锁保护位置，再用原控制字执行条件 CAS 发布对应新修订/阶段；读者在此期间不能取得描述锁。发布不清除 STOP。
4. CAS 成功形成该次内存发布点，释放描述锁；CAS 失败则在解锁前恢复旧描述，**绝不恢复旧控制字或清 STOP**。随后根据失败原因重核，不执行重复外部动作。
5. 旧/失败描述的引用释放、回收及可能析构在锁外处理。每次发布独立收束，P 后取样及 C 的构造不被合并成未经证明的 `now` 检查加 deadline 替换。

P 是上述条件发布之一；W 在成功 P 之后取样，C 是绑定 exact-P 和真实 W 证书的另一发布。P 与 C 之间释放锁，让读者/终止者按 RA/AH 的原规则观察。W 不合格则关闭，不用原描述仍匹配替代时间证据；C 即使成功也不保证当前期限未过。

[BOOTTIME 契约](runtime-clock.md)要求 P 后才调用新采样、样本来自该调用区间；原子次序不自动赋予这份时钟保证。[故障源接入](fault-source-integration.md)要求安全关联连续处理后才恢复合格，描述与 gate 核验不能只看一次最后健康值。TC/SI 与 RP 的组合未执行。

发布者不是快速撤销者。若它暂停持锁，普通读者只能暂拒，适用整轮/实例故障仍必须能通过独立原子门控停发。不得持锁做 CDB、存储、网络、等待外部结果、复杂析构或无界重试。

## 每次派发检查

1. 使用任务已持有的精确 cell，先查适用共同故障及 STOP；已无权则拒绝，不取描述锁。
2. 对描述使用 `try_lock`，竞争失败只返回“本次暂不能核验”，不等待锁，也不报告许可已经终止。不得让调用者把这个结果当已成功或永久取消整项任务。
3. 成功取得锁时，克隆受保护的 `Arc<Descriptor>`，同时读取控制字并核对完整身份/修订/阶段；任何失配不拼接，解除锁后重核或拒绝。不把取得描述副本当作持久 capability。
4. 解锁后按[稳定故障域绑定](permit-fault-scopes.md)复核全部必要 gate/epoch，在可信当前时间采样前后检查完整绑定集合及控制字；按当前具体状态判断：稳态 Pending 仅用旧截止；首次/交接 Pending 零副作用；Confirmed 仍用当前实际截止。任何共同/卷级必要门控变化都不沿用原允许结果。
5. 仅全部成立才允许该次软件派发尝试；之后的暂停及物理交付窗口仍由 LG/HK 外部隔离处理。锁和描述引用均不应跨设备慢调用；后续命令重新检查，不能沿用这次允许。

描述在读者暂停期间因强引用仍可读取，但它可能已不再是当前版本；内存可读不等于权限有效。控制字修订不回绕，防止旧描述在地址复用或多次更新后误匹配。不得通过无限自旋等待描述锁或一直重做 Raft 请求获得所谓进展。

## 不同失效不能共用无条件 STOP

| 已识别事件 | 候选处理 | 禁止混用 |
| --- | --- | --- |
| 明确适用于该整轮的现实/控制故障 | 对稳定 cell 的控制字 `fetch_or(STOP)`，不取描述锁、不分配、不等待原因持久化；来源与详细证据稍后补录 | 新描述发布不能覆盖该位；发生故障时无已发布许可也不能丢失跨轮限制 |
| 精确旧截止的到期检查 | 携带受保护描述与 exact 控制字，当前取样已到期才 CAS 到 STOP；失败须重读当前状态 | 不对旧 D 使用无条件 STOP，否则可能误杀已合法续期状态 |
| 旧 K 的普通阶段结束/到期 | 只作用于精确 K 阶段或仍受其截止约束的交接 Pending，竞争失败按 AH 分类重读 | 不以整轮 `fetch_or` 误杀已合法生效的 G；CAS 重试不称为单步无等待撤销 |
| 旧 K 事件揭示当前共同危险 | 按风险对当前许可的真实影响进行整轮/共同故障关闭 | 不以“旧回调”丢弃仍适用于 G 的隔离风险 |
| 单卷只读/局部资源故障 | 关闭对应卷能力，健康控制投票及其他独立卷保持原规则 | 不借一个全局 STOP 把局部故障扩大为全部控制失败 |

到期 CAS 成功代表真实终止；CAS 失败不是终止已完成。C 赢后应核验新证书/当前期限，不能先报告已关闭再改口。因一次竞争无法完成检查时先拒绝本次派发，再安排受控重核；不得借重核任务排队延长截止。

`fetch_or` 的意义是该单次原子关闭不经过描述互斥锁或应用层分配，并非保证进程调度、CPU 指令或物理停发有固定实时上界。针对已知整轮故障的快路径与按旧版本核验的到期路径，分别测量，不把后者的重试隐藏在前者指标中。

## 生命周期、毒化与资源上界

只用持有中的强引用读取 cell/描述，不自写 `AtomicPtr` 加引用计数协议。运行期仅保留当前描述、在途候选及实际读者仍引用的旧描述，不永久积累每次续期历史。每个执行上下文限制在途检查/候选数量；管理接口及任务队列的额度须覆盖保留对象，不能允许无限读者钉住旧版本。

源端快速撤销的稳定句柄不在撤销调用中替换或释放最后一个引用。`Arc` 最后一次释放可能触发析构，控制路径与读者释放均须审查析构内容；不可把大清理、设备操作或锁等待藏在 `Drop` 中。具体回收预算和延后清理机制仍待实现，不以“用了 Arc”宣称无延迟成本。

描述锁发生毒化时保持受限，先关闭对应许可；不能自动 `clear_poison` 并继续使用状态。毒化是提示，不是完整损坏检测或内存安全证明；发布失败/异常后的状态信任按既有故障规则重建。正常锁竞争不是毒化，也不是控制存储失败。

短锁竞争导致额外暂拒和重新调度，属于本候选接受的可用性/性能代价。选择依据是可检查的生命周期与较小实现复杂度，不是假设其一定快于其他容器；必须在相同可靠性下测量多驱动派发、刷新竞争与保留内存。

## 验证与完成边界

以下 RP01—RP06 均未实现/执行；与研究报告的 PR01—PR06 及 PU/RA/AH 区分编号。

| 场景 | 必须核对 |
| --- | --- |
| RP01：装入新描述后整轮 STOP、发布 CAS 失败 | 解锁前恢复旧描述，不清 STOP，不出现新描述/旧可用 token 配对放行 |
| RP02：读者克隆后暂停、替换及旧对象回收 | 无悬空访问，恢复后按 token/期限拒绝旧权限；资源解除后旧对象可回收 |
| RP03：发布者持锁暂停、故障与普通读者到达 | 整轮原子关闭不等待锁；try_lock 失败暂拒而非伪报终止；不声称物理瞬时停发 |
| RP04：合法续期/交接与旧到期事件竞争 | exact 失败须重核；旧 K 事件不误杀 G，共同危险仍关闭当前许可 |
| RP05：新轮次准备遇故障再健康 | 必须有跨轮/资格绑定证据，不能只给旧 cell 置 STOP 后开放新 cell；结合 FS 场景核验 |
| RP06：毒化、修订耗尽、持续负载及正常正例 | 不清毒化/回绕继续；有界保留，无故障且资源/调度条件满足时发布和派发可完成 |

本候选具体化了**已正确绑定轮次**内部的描述读取、条件发布和整轮原子关闭。[稳定故障域代次](permit-fault-scopes.md)另给跨轮绑定与健康恢复的协议候选；源端接入、K 专属关闭进展、多源资格的一致组合、时钟及实际派发仍需验证，不把这些责任藏在“再检查健康”一句话里。18 继续 claimed，09 依赖不解除；条件设计不是实现验证结果。
