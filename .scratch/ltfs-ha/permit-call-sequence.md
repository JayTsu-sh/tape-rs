# 许可从证据接收到单动作检查的组合顺序

关联：[控制推进](raft-rs-binding.md) · [表示](permit-representation.md) · [故障域](permit-fault-scopes.md) · [来源审查](fault-source-integration.md) · [时钟](runtime-clock.md)

状态：依自动接受授权采用的组合调用设计，未实现/执行。这里串联已定机制，明确每一步输入与失败出口；不是总项目 spec，不声称有完整形式化或弱内存证明。设备命令已交付与软件允许仍严格区分。

## 证据与调用结果分层

| 结果 | 准确含义 | 不能据此进行的动作 |
| --- | --- | --- |
| 已收到 safe 结果 | 协议返回了匹配请求的 ReadState 候选 | 未实际 apply、身份失配或时效未满足时不能发布许可 |
| P 的条件发布成功 | 原描述/token 条件转换完成，仍待后采样证明 | 首次/交接不能派发；稳态不能使用新期限 |
| 证书已具备/确认 C 已发布 | 存在对应 P 的可核验证据，可能仅证明历史及时接受 | 不能省掉当前时间、gate、阶段和资源条件核验 |
| 本次软件检查允许 | 本次动作在检查切点有充分当前依据 | 不是长期 capability、设备已经受理或下一条命令也获准 |
| 已交付或交付未知 | 达到实际适配器定义的底层边界或无法判定 | 不因后续停权当作未执行，不盲重放/退款 |

内部通知不能只返回一个 `success=true` 同时表示上述不同结果。具体 Rust 公共 API 仍由后续模块/接口票据确定；这里不新增上传回执或持久化请求状态。

## C0 到 C4：取得可用的非时间证据

1. **C0 初始化与来源覆盖。** 当前运行上下文、时间域和稳定 gate 已建立，必需来源注册并有合格 Reviewed；来源记录 H 无洞覆盖对应 epoch。权限未知时只允许既有安全观察与合法控制推进，不提前探测设备来填补执行前提。
2. **C1 原请求发起。** 单发布入口取得精确许可/轮次及原 token，记录进入协议队列前的 BOOTTIME t0，检查构造 E=t0+T；每上下文最多一条资格请求在途。首次 K/G 需自己的控制位置，K 不能替代 G 的首次确认。
3. **C2 原 RawNode 周期。** 按 P0—P6 保存并实际应用 Ready/LightReady。ReadState 可以先登记，但只在实际 A 达到返回位置及该授权所需位置后才交给后续证据核验。存储失败走 FD，不伪造 advance，也不因等待冻结许可期限。
4. **C3 关联及资格快照。** 以原 ctx/t0、集群/配置、当前 Leader 上下文、运行实例和许可身份核验结果。取得受保护的原描述及全部必要 Reviewed/gate 关联；期间失效或合格审查未覆盖当前 epoch 时拒绝。迟到危险事实另行处理，不能按“旧响应”丢弃。
5. **C4 阶段前置。** 首次满足各自的 K 或 G 条件；稳态要求原许可未终止；K→G 还须保持准备入口封闭、固定原 Dk、相关外部效果安全及 G 的全部首次前提。非时间证据尚未具备时不先占一个 P 等待补齐。

C3 的快照是受保护的证据关联，不是冻结外部世界；后续发布及读者继续核验同一必要绑定。涉及变更的重试必须重新核对前态，不把原 ctx 重新绑定到另一个实例或 t0。

## C5 到 C8：条件发布与时间证明

1. **C5 准备并发布 P。** 锁外准备不可变描述；锁内核对原 token/描述、阶段及绑定，换描述后 CAS 发布 P。CAS 失败恢复旧描述而不恢复 token/清 STOP，锁外释放。返回的 P 身份固定，不能拿另一份 Pending 的成功补证。
2. **C6 P 后新采样。** P 成功并释放描述锁后，才发起 BOOTTIME 的新 W 调用；实际取样须在调用区间内。按首次、稳态、交接分别检查 E、oldD/E、Dk/Eg，并复核原必要 gate/epoch 未变化；没有足够时间/资格证据就进入对应失败/关闭，不进入 C。
3. **C7 确认发布。** 构造 exact-P 的不可变证书，再按同一表示协议尝试 P→C。P 与 C 之间允许终止者竞争。STOP 或绑定变化不可覆盖，失败不改变 expected 强行提交；交接失败保留 K 退出，稳态失败不回写旧候选期限。
4. **C8 结果交付。** C 发布成功只说明描述/token 转换及证书可用；随后已过新期限或 gate 已变化时，不报告当前仍可执行。需要动作资格时调用独立当前检查，不能将发布完成回调直接接到设备发送。

失效发生在 P/W/C 任意间隙时，区分已发生的历史接受与当前不可用状态。某个 gate 在最后核对后变化，即使 token CAS 仍成功，所有绑定旧 epoch 的读者也不得使用该对象；不把 CAS 成功当作跨所有 gate 的原子授权。

## 有期限的来源证据也必须纳入检查

若某项必要资格证据有自己的有限有效截止，不能只检查 RQ 的 E、却默认该证据永不过期。该截止须来自已定义的本地时间域/资格策略；未经核验的远端墙钟时间不能直接与 BOOTTIME 比较，没有有效性契约的必需来源保持未知。

分层定义可用截止 U：K/G 各取自身已证实期限与实例/组必要时间上界的最小值；单动作再与相关资源能力的截止取最小值。局部卷证据到期不因此终止共同 G。U 不重写原 t0，也不把外部隔离转换成租约。稳态更新须证明 P/W 仍早于**原可用截止**，同时新证据满足自己的时间上界；首次与交接同样加入各自必要上界。不能在原证据已过期后，只换一份新健康证据让旧许可继续。

原 RQ 期限仍按 N=max(D,E) 计算；来源上界形成独立限制，不改成新的 t0。首版同轮成功续期另要求 newU>=oldU，维持 Pending 使用旧证据时的保守下界。否则拒绝该续期，不把更短新期限追溯生效到 P；旧证据只有在仍真实有效时才可继续使用，真实失效立即走原 gate/epoch 规则，需收束时按对应范围处理。不能为保持单调而忽略已知风险。

例如 oldU=100、P=10/W=11、新来源上界=20、C=40，若允许该续期成功，Pending 读者在 30 使用旧截止就不再保守；newU>=oldU 正是排除此历史，不是要求 C 必须早于旧截止。Pending 分别保存旧/新证据绑定及上界，仅使用旧已证实范围。K→G 前态证明包含 K 的可用截止，确认后的 G 仅纳入 G 自己的必要上界，不继承纯 K 的截止。RA/AH 原有成功接受点、失败不复活和交接不回退均保持。

来源存在期限时，其身份、版本及时间上界作为不可变绑定的一部分随本次发布核验。证据换新不能只改一个共享 health 指针绕过许可更新；原绑定过期后按新轮次/新资源能力恢复，范围仍分层。读者和精确到期处理使用实际可用截止，不仅看较晚的 RQ deadline。具体来源期限与更新适配仍需落实，不为开始 spec 把未知期限填成无限。

## D0 到 D4：检查与派发

1. **D0 精确任务。** 任务持有原 RoundCell、动作类型/目标和对应资源能力的安全引用；已知交付或未知任务不得重新进入普通新派发路径。
2. **D1 取得描述。** 先查 STOP/适用故障，随后 try_lock 取得一致描述/token，克隆受保护引用后解锁。忙只拒绝本次核验；毒化/不变量破坏按其真实故障范围关闭，不伪报已成功或已取消。
3. **D2 当前有效性。** 对同一描述的全部许可及资源 gate/epoch，在当前时间采样前后复核；核对阶段、范围、实际可用截止及恢复能力。稳态 Pending 只能用旧已证实范围，首次/交接 Pending 不派发。
4. **D3 实际入口。** 仅 D2 允许才进入一次受控派发尝试；不跨慢调用持描述锁，不提前把入队或允许标记称为已交付。最后检查后的暂停窗口继续交由 LG/HK 的外部约束，具体驱动/管理适配必须提供可观察边界。
5. **D4 完成处理。** 结果仍归原动作；设备事实、提交证据、用户响应分别判断。下一条命令重新从 D0 检查，不因为本批已经开始或上条成功而继续。

纯内存检查重试不得重新产生 CDB/管理副作用。锁忙、证据不足或关联变化时可以重新调度尚未交付的工作，但不能改绑一个新许可去继续已失效轮次的队列，也不能把当前受限说成确定未提交。

## 两条并行安全路径

来源路径在获知适用危险后先推进 gate epoch，再记录事件/处理 H 和必要控制状态；不等待 C0—C8、描述锁或当前 Ready。精确截止/K 阶段关闭按 token 与当前状态处理，不无条件推进共享域。两者的处理结果、重试和源端至生效窗口分别观察。

控制路径只能发布合格新对象，不能清旧 STOP、重用旧绑定或补造实际 apply。关闭可以先于持久化终止记录，但新接管仍须真实隔离与效果核验。时钟能力失信、必要控制存储失败和局部卷异常按各自职责处理，不能合并成“全部停 Raft”或“只丢一个回调”。
